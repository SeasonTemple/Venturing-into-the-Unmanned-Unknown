# AI-Native SDLC 总检查清单

研发顺序：意图 → 设计 → 实现 → 验证 → 测试 → 交付 → 演进 → 工具生态。

## 意图与需求
- [ ] 核心目标具备可观察的外部结果，且完成定义优先由端到端用户路径刻画
- [ ] 范围边界与明确“非目标”已写清，可约束 Agent 不擅自扩权
- [ ] 当前迭代基线内的验收标准可客观判定
- [ ] 关键规则已配有状态表格、正反例或属性描述
- [ ] 尚未确定的关键边界已明确登记为“已知未知”，并写明后续查证方式
- [ ] **关键性能、体验目标或显式“不作承诺”说明已写明**（若适用）
- [ ] 涉及并发、权限、恢复或关键性能的高风险线索已标出

## 设计与架构
- [ ] 模块职责清晰，依赖方向单向且具备结构性边界约束
- [ ] 核心接口均具备无歧义、可判定的输入/输出/错误契约
- [ ] 关键非法状态已通过类型系统或统一边界校验予以排除
- [ ] 已识别的高风险路径均已明确标注下游验证、测试或仿真去向
- [ ] 外部失败、超时恢复与过载背压策略已明确定义
- [ ] **关键路径已设定可核对的性能与资源预算，或已获批准标为“未承诺”**
- [ ] **过载或资源耗尽时的背压拒绝与 Fail-Closed 安全失败行为已定义**
- [ ] 时钟、网络与外部存储等非确定性依赖具备可插拔测试边界
- [ ] 关键架构取舍已形成 ADR 决策记录
- [ ] 已知的 Agent 高频误用场景已通过目录结构、类型或静态检查阻断，或已登记待收紧计划

## 实现
- [ ] 全部代码改动严格落在设计划定的模块边界内，接口行为满足契约
- [ ] 异常、超时、背压与安全失败路径均已显式实现，无静默吞错
- [ ] 高风险逻辑具备可观测断言、诊断状态与测试注入钩子
- [ ] **未在未审批的情况下突破已承诺的性能或资源预算**（偏差已记录并回流设计）
- [ ] **关键预算路径具备可供测试层直接测量的稳定接口或度量探针**（或已说明不可测风险）
- [ ] 无未经设计批准的架构级跨界引用或结构漂移
- [ ] 代码结构与命名对后续人类评审（HITL）保持清晰可读
- [ ] 审阅与自检中重复出现超过一次的错误模式已转化为自动化检查或测试，而非新增规劝注释

## 验证（正确性层）
- [ ] 关键功能性质均具备唯一 ID 与无歧义陈述（可执行优先）
- [ ] **关键用户路径具备真实的端到端运行时证据**（或持有显式签核跳过说明）
- [ ] 每一项声明通过的检查都已如实填写“已查性质”与“未覆盖边界”
- [ ] 跨进程并发或高风险协议路径已完成设计级检查，或已记录经批准的跳过理由
- [ ] 已结合目标语言生态成熟度完成了必要的实现层静态分析、契约或 BMC 检查
- [ ] 所有通过与反例证据均可由他人通过记录的命令、脚本或种子一键重放
- [ ] 暴露出的反例已全部关闭，或已正式回流为意图/设计修正项
- [ ] （若工程中引入形式化工具）D1–D6 评估记录完整且维护负责人明确

## 测试与质量保障
- [ ] 主成功路径与核心验收场景均已建立自动化测试并与性质 ID 映射
- [ ] 关键异常输入、权限拒绝与恢复失败路径均具备有效覆盖
- [ ] 关键通用不变式已通过属性测试（PBT）或等价机制检验
- [ ] **已承诺的性能与资源预算均已完成核对测试（或持有书面批准的延期记录）**
- [ ] 性能测试报告包含完整硬件环境、构建选项与基线对比版本指针
- [ ] 合并相关绿灯均能汇总形成“已查性质与未覆盖边界”清单
- [ ] 高风险外部输入解析面已接入模糊测试（Fuzz），关键协作轨迹已建立 Expect 或仿真覆盖
- [ ] 分布式状态恢复或复杂异步场景已评估确定性仿真（DST）或书面接受残余风险
- [ ] 本地测试运行路径与 CI 约定流水线保持一致可执行
- [ ] **功能完成标准由真实用户路径的端到端证据界定**，单元测试不单独充当“已完成”依据
- [ ] **若运行变异测试**：严格限定于本次改动范围并设定时间或数量预算，未跑完部分已标为“未覆盖”
- [ ] 当实现与测试同由 Agent 编写时，已落实独立性验证措施或显式记录风险

## 集成与交付
- [ ] 从基线读取的自动化提交级与合并级检查全部通过
- [ ] 性质级覆盖表齐全，已查性质与未覆盖边界表述清晰无含糊
- [ ] **已承诺的性能与资源预算门禁全部通过，或持有经过正式批准的书面延期记录**
- [ ] 未在无充分理由与授权的情况下跳过关键回归测试
- [ ] 发布制品与构建版本、源码提交一一可追溯，且回滚方案经验证可用
- [ ] 发布过程与变更审批记录完整可审计
- [ ] 高风险发布或涉及显式未覆盖边界的变更，已通过 HITL 人工裁决或符合预设书面审批策略
- [ ] **结构化证据包完整且可直接打开查验**；本次变更未修改或放宽拦住自己的既有检查规则

## 持续演进
- [ ] 线上监控信号、CI 失败模式与审阅反馈已建立采集与定级机制（含预算指标漂移）
- [ ] 暴露出的问题已按根因溯源至正确层级并回流修订
- [ ] 修复补丁已附带可防止复发的永久性回归保护
- [ ] 代码、测试断言、验证资产与文档说明已保持同步演进
- [ ] 复盘结论已沉淀至对应工程资产、门禁或技能说明中
- [ ] 沉淀为门禁的缺陷模式至少重复出现两次且可从变更中自动识别；失效规则与长期不稳定的无效检查已清理

## 工具与技能生态
- [ ] 每个关键生命周期环节均已配备至少一种可自动执行的最小工具手段
- [ ] 核心 Agent Skill 均写明了清晰的触发条件与适用边界，且能准确路由生效
- [ ] 本地开发运行路径与 CI 门禁流水线调用的是同一套检查命令与配置基准
- [ ] 形式化验证、全系统仿真等重型工具已设定明确启用条件，而非默认全开
- [ ] 文本写作风格类辅助检查器未在未经决议的情况下误设为合入硬门禁
- [ ] 凡能固化为目录结构、Lint 规则或自动化验证的约束，均未仅滞留在自然语言规则或 Skill 中
