# AI-Native SDLC · 实现（Implementation）

## 1. 本章定位

**意图澄清 → 设计与架构 →「实现」→ 验证 → 集成与交付 → 持续演进**

实现是设计的执行，不是重新发明系统。

### 基本原则

- 设计先行：无设计基线不开始大规模编码
- 边界内实现：不随意打穿模块职责
- 契约优先：先满足接口约定
- 最小可行：先正确，再优化
- 为验证留钩子
- 显式优于隐式

---

## 2. 核心产物

| 产物 | 作用 |
|------|------|
| 模块代码 | 按职责落地 |
| 接口实现 | 满足契约 |
| 错误与边界处理 | 与设计一致的失败行为 |
| 可检查点 | 断言、状态暴露、harness 锚点 |
| 实现说明（极简） | 与设计对应关系及必要偏差 |

---

## 3. 规范执行流程

1. 确认输入基线（意图、边界、契约、风险路径）
2. 按模块落地（先公开契约，再内部逻辑）
3. 落实错误与边界行为
4. 为验证预留锚点
5. 保持实现说明极简
6. 自检后提交验证

### 质量门禁

- [ ] 代码落在既定模块边界内
- [ ] 关键接口行为符合契约
- [ ] 失败、超时、重试等行为已显式实现
- [ ] 高风险路径可被后续检查
- [ ] 无未批准的架构级偏差

---

## 4. 简洁实例

`acquireWriteLock`：在 `LockService` 内实现；先校验会话再占锁；失败返回明确错误；写锁唯一性可观察；不把锁算法散落到文档服务。

---

## 5. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 先写再补设计 | 先有基线再实现 |
| 打穿模块边界 | 严格按边界落地 |
| 模糊错误处理 | 错误语义显式化 |
| 隐式新协议 | 变更先回到设计 |
| 过度实现 | 最小正确版本优先 |

---

## 6. Agent 执行要点

1. 无设计基线时，不开始大范围编码
2. 一次聚焦一个模块或接口
3. 契约冲突时升级到设计层
4. 优先写清错误路径
5. 生成后先做边界与契约自检

---

## 7. 本章要点

- 实现是设计的执行
- 代码必须落在边界内并满足契约
- 高风险路径要为验证留出可检查点
