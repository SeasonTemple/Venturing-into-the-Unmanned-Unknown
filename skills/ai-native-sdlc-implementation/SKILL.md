# AI-Native SDLC · 实现（Implementation）

## 1. 范围与定位

**位置：** 意图 → 设计 → **实现** → 验证 → 测试 → 交付

Agent 为生产主体执行设计。实现之后必须进入正确性层（第 4–5 章），不得以「代码已生成」代替证据。

### 原则

- 无设计基线不大规模编码
- 边界内实现；契约与不变量优先
- 最小正确；显式错误路径
- 为验证、Expect、仿真留钩子
- 对 HITL 可读；不得用删测试换绿

---

## 2. 产物

| 产物 | 作用 |
|------|------|
| 模块代码 | 职责落地 |
| 接口实现 | 满足契约 |
| 错误处理 | 与设计一致 |
| 可检查点 | 断言、状态、仿真锚点 |
| 可读行为表面 | Expect/诊断（可选） |
| 极简说明 | 与设计对应及偏差 |

---

## 3. 流程与门禁

1. 确认意图/设计基线  
2. 按模块落地  
3. 错误与边界显式化  
4. 预留检查锚点  
5. 自检后提交验证/测试  

- [ ] 落在边界内；契约满足
- [ ] 失败路径显式
- [ ] 高风险路径可检查
- [ ] 无未批准架构偏差
- [ ] 对 HITL 可读

---

## 4. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 清晰基线与锚点约定 | 功能绿不等于性质成立 |
| HITL | 可读结构降低审阅成本 | 不应回到「人写主体」 |

---

## 5. 要点

- 实现是设计的执行，不是正确性证明
- 正确性由第 4–5 章与第 6 章门禁约束
