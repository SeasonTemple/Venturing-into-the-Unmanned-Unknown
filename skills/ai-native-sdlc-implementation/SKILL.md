# AI-Native SDLC · 实现（Implementation）

## 1. 范围与定位

**位置：** 意图 → 设计 → **实现** → 验证 → 测试 → 交付

Agent 为生产主体执行设计。实现后必须进入正确性层与约定的性能检查；不得以「已生成」代替证据。

### 原则

- 无设计基线不大规模编码
- 边界内实现；契约与不变量优先
- 最小正确；显式错误路径
- **不静默突破设计预算**（突破须记录并回流设计/意图）
- 为验证、Expect、仿真、**基准/剖析**留钩子
- 对 HITL 可读；不得用删测试或放松超时换绿

---

## 2. 产物

| 产物 | 作用 |
|------|------|
| 模块代码 | 职责落地 |
| 接口实现 | 满足契约 |
| 错误与背压 | 与设计一致的失败/过载行为 |
| 可检查点 | 断言、状态、仿真锚点 |
| 可度量点 | 指标、计时、资源采样钩子（按预算需要） |
| 可读行为表面 | Expect/诊断（可选） |
| 偏差说明 | 与设计差异，含性能相关 |

---

## 3. 性能与资源（实现检查点）

| 项 | 要求 |
|----|------|
| 对齐预算 | 热路径实现对照设计中的延迟/内存/句柄等预算 |
| 禁止隐性成本 | 避免热路径无界缓冲、同步阻塞、多余拷贝；必要时在说明中标注 |
| 安全失败优先 | 超时、OOM 风险、配额耗尽时行为符合契约，不为冲指标放松 fail-closed |
| 可测性 | 关键预算对应路径可被基准测试或剖析挂住（接口稳定或探针） |
| 偏差升级 | 无法在预算内实现 → 停并回流设计/HITL，不默发 |

实现阶段的本地快速检查（可选但推荐）：冒烟基准、分配/基本剖析；正式门禁在测试/交付章。

---

## 4. 流程与门禁

1. 确认意图与设计基线（含预算与未承诺）  
2. 按模块落地  
3. 错误、边界、背压显式化  
4. 预留正确性与度量锚点  
5. 自检后提交验证/测试（含约定的性能套件）  

### 质量门禁

- [ ] 落在边界内；契约满足
- [ ] 失败与过载路径显式
- [ ] 高风险路径可检查
- [ ] **未静默突破已承诺性能/资源预算**（或已记录回流）
- [ ] **关键预算路径具备可测钩子或已说明不可测风险**
- [ ] 无未批准架构偏差
- [ ] 对 HITL 可读

---

## 5. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 预算与钩子约束生成；可用基准闭环优化 | 功能绿 ≠ 性质成立 ≠ 预算满足 |
| HITL | 审偏差与「为速度牺牲安全」 | 不回到人写主体 |

---

## 6. 要点

- 实现执行设计，不证明正确性，也不自动证明性能
- 正确性由第 4–5 章约束；**已承诺预算由测试/交付门禁核对**
