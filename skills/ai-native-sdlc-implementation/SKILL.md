# AI-Native SDLC · 实现（Implementation）

## 1. 本章定位

**意图澄清 → 设计与架构 →「实现」→ 验证 → 集成与交付 → 持续演进**

实现是设计的执行，不是重新发明系统。

### 基本原则

- 设计先行：无设计基线不开始大规模编码
- 边界内实现：不随意打穿模块职责
- 契约与不变量优先：先满足接口与结构约束
- 最小可行：先正确，再优化
- **为验证、Expect 轨迹与仿真留钩子**
- 显式优于隐式；**简单、可读、可审**优于炫技
- Agent 优化「功能绿灯」时，人负责守住非功能属性（简单、少重复、少硬编码）

---

## 2. 核心产物

| 产物 | 作用 |
|------|------|
| 模块代码 | 按职责落地 |
| 接口实现 | 满足契约与类型/模型约束 |
| 错误与边界处理 | 与设计一致的失败行为 |
| 可检查点 | 断言、状态暴露、harness / 仿真锚点 |
| 可读行为表面 | 便于 Expect 测试或诊断的稳定输出（可选） |
| 实现说明（极简） | 与设计对应关系及必要偏差 |

---

## 3. 规范执行流程

1. 确认输入基线（意图、边界、契约、不变量、风险路径）
2. 按模块落地（先公开契约，再内部逻辑）
3. 落实错误与边界行为；保持非法状态不可构造或入口即拒
4. 为验证与测试预留锚点（含可替换时钟/IO，若设计要求）
5. 保持实现说明极简；避免无必要的架构级「顺手改」
6. 自检边界、契约与可读性后提交验证/审阅

### 质量门禁

- [ ] 代码落在既定模块边界内
- [ ] 关键接口行为符合契约
- [ ] 失败、超时、重试等行为已显式实现
- [ ] 高风险路径可被后续检查或仿真
- [ ] 无未批准的架构级偏差
- [ ] 关键逻辑对审阅者可读（命名、结构、错误路径清晰）

---

## 4. 简洁实例

`acquireWriteLock`：在 `LockService` 内实现；先校验会话再占锁；失败返回明确错误；写锁唯一性可观察；不把锁算法散落到文档服务；时钟依赖可注入以便仿真 TTL。

---

## 5. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 先写再补设计 | 先有基线再实现 |
| 打穿模块边界 | 严格按边界落地 |
| 模糊错误处理 | 错误语义显式化 |
| 隐式新协议 | 变更先回到设计 |
| 过度实现 | 最小正确版本优先 |
| 删测试或弱化断言换绿灯 | 禁止；失败应对齐真实契约 |
| 为 Agent 便利牺牲可读性 | 保持人类可审的结构与命名 |

---

## 6. Agent 执行要点

1. 无设计基线时，不开始大范围编码
2. 一次聚焦一个模块或接口
3. 契约或不变量冲突时升级到设计层
4. 优先写清错误路径与可观察性
5. 生成后先做边界、契约与「是否仍简单」自检
6. 不通过删除或空洞化测试来通过门禁

---

## 7. 本章要点

- 实现是设计的执行
- 代码必须落在边界内、满足契约，并为验证/仿真留钩子
- 在 Agent 加速编码时，简单性与可审性是一等公民
