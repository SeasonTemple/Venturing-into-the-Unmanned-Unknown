# AI-Native SDLC · 附录

## 1. 总检查清单

### 意图与需求
- [ ] 目标可观察
- [ ] 边界与非目标清晰
- [ ] 当前基线内验收可判定（不要求一次覆盖全部真实约束）
- [ ] 关键验收有表格或属性线索
- [ ] 重要「已知未知」已标明
- [ ] 关键歧义已消除
- [ ] 高风险线索已标记

### 设计与架构
- [ ] 模块职责清晰
- [ ] 关键接口有契约
- [ ] 关键非法状态已尽量不可表示或有显式校验层
- [ ] 高风险路径已识别并标明验证/仿真去向
- [ ] 失败与恢复策略已定义
- [ ] 非确定性依赖边界清晰（便于确定性仿真）
- [ ] 重要决策已记录

### 验证
- [ ] 属性已定义并可追溯（优先可执行形式）
- [ ] 高风险设计已完成相应检查
- [ ] 实现层关键检查已按目标语言选型并完成
- [ ] 结果可解释且可重复执行
- [ ] 反例/冲突已关闭或已反哺规格

### 实现
- [ ] 代码落在既定边界内
- [ ] 接口行为符合契约
- [ ] 失败路径显式实现
- [ ] 高风险路径保留可检查性
- [ ] 无未批准的架构级偏差
- [ ] 关键逻辑对 HITL 可读

### 测试
- [ ] 主验收标准有自动测试
- [ ] 关键失败路径有覆盖
- [ ] 关键性质有属性测试或等价可执行规格
- [ ] 高风险输入面有 fuzz 或等价加固（如适用）
- [ ] 关键协作路径有可读轨迹或库级仿真
- [ ] 分布式/恢复关键路径已评估 DST 或等价手段
- [ ] CI 可执行；失败可指向行为或契约
- [ ] （建议）关键区做过差异或变异抽检

### 集成与交付
- [ ] 集成后检查通过
- [ ] 关键回归未无故跳过
- [ ] 制品可追溯；回滚路径可用
- [ ] 发布可审计
- [ ] 变更粒度可供 HITL 审阅

### 持续演进
- [ ] 信号有采集与分级
- [ ] 问题能回流到正确层级
- [ ] 修复附带回归保护
- [ ] 资产与行为同步更新
- [ ] 复盘结论可执行

### 工具与技能
- [ ] 各关键环节有最小自动能力
- [ ] 核心 Skill 可触发
- [ ] CI 与本地路径一致
- [ ] 重型手段按风险启用；写作检查器非硬依赖

## 2. 术语表

| 术语 | 含义 |
|------|------|
| AI-Native SDLC | 以 Agent 为生产与执行主体，人提供意图输入并作为 HITL 裁决源之一，辅以可执行规格与自动门禁等系统保证的软件工程方法 |
| 生产主体 | 承担主要生成、修改、执行与推进工作的角色；在本书中指 Agent |
| 意图输入 | 原始目标、边界、优先级与约束的来源；主要来自人及业务渠道，可渐进完备 |
| HITL | Human-in-the-Loop：人在环内参与裁决；人是权威较高的裁决源之一，与系统门禁并列 |
| 系统保证 | 不依赖单次人工判断的可重复约束：测试、类型/契约、CI、验证、仿真等 |
| 意图 | 目标、边界与验收标准（当前迭代基线） |
| 验收标准 | 可观察、可判定的完成条件 |
| 已知未知 | 已承认尚未定义清楚的区域，并指定探索方向 |
| 低歧义表达 | 同一陈述尽量只有一种合理理解；手段可自选 |
| ASD-STE100 | 受控技术英语的一种规范；可选参考，非流程依赖 |
| STE 实用子集 | 借鉴 STE 中对降歧义最有用的习惯，而非全文合规 |
| 可执行规格 | 可用测试或证明器自动检查的规格 |
| 形式化验证 | 用数学方法证明或证伪模型/实现满足规格 |
| 模型检查 / 有界验证 | 状态空间探索 / 有限边界内检查 |
| 属性测试 / 模糊测试 / 差异测试 / 变异测试 | 见测试章 |
| Expect 测试 | 可读行为轨迹嵌入测试，失败以 diff 呈现 |
| 确定性仿真测试 (DST) | 可控时间/调度/随机/故障，轨迹可按种子重放 |
| Gobra / Verus / Frama-C / SPARK / Kani 等 | 各语言验证或有界检查工具；成熟度见验证章 |
| 门禁 | 未通过则不可进入下一阶段的强制检查 |
| Skill | 供 Agent 按需加载的结构化能力说明 |
| 止损 | 先限制损害，再根治 |

## 3. 反模式汇总

| 反模式 | 正确做法 |
|--------|----------|
| 把 AI-Native 当成「人写主体、AI 补全」 | Agent 为生产主体；人做意图输入与 HITL |
| 只有人盯、没有系统门禁 | HITL 与自动门禁并列 |
| 只有自动绿灯、从无 HITL | 风险与冲突处保留权威裁决 |
| 先做后想 | 先目标/边界/验收 |
| 幻想第一轮锁全全部性质 | 风险优先 + 已知未知 + 反馈补全 |
| 把某一写作标准当合格必要条件 | 以可判定、少歧义为准 |
| 模糊完成 | 可判定验收 |
| 只测成功路径 | 成功与关键失败成对 |
| 用测试替代一切验证 | 风险路径加强验证 |
| 无限加长自然语言规格 | 优先补表格/属性/差异用例 |
| 不可复现失败只靠重跑 | 控制非确定性或 DST |
| 默认全系统 DST / 重型证明 | 按风险启用 |
| 绑死单一语言或产品 | 原则中立，工具可替换 |
| 大爆炸合并 / 无回滚 | 小批量；先定退路 |
| 修症状不回归 | 修复必补保护 |

## 4. Agent 执行要点

- 先用清单定位缺口，再进入对应章节技能
- 术语冲突时以本附录为准
- 默认自己是生产主体：推进工作，但遇门禁失败与 HITL 要求时停止并上报
- 不把「未使用某工具/标准」 dual 成失败，除非门禁显式要求
