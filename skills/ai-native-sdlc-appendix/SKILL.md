# AI-Native SDLC · 附录

## 1. 总检查清单

### 意图与需求
- [ ] 目标可观察
- [ ] 边界与非目标清晰
- [ ] 验收标准可判定
- [ ] 关键歧义已消除
- [ ] 高风险线索已标记

### 设计与架构
- [ ] 模块职责清晰
- [ ] 关键接口有契约
- [ ] 高风险路径已识别并标明验证去向
- [ ] 失败与恢复策略已定义
- [ ] 重要决策已记录

### 验证
- [ ] 属性已定义并可追溯
- [ ] 高风险设计已完成相应检查
- [ ] 实现层关键检查已完成
- [ ] 结果可解释且可重复执行

### 实现
- [ ] 代码落在既定边界内
- [ ] 接口行为符合契约
- [ ] 失败路径显式实现
- [ ] 高风险路径保留可检查性

### 测试
- [ ] 主验收标准有自动测试
- [ ] 关键失败路径有覆盖
- [ ] 高风险场景有专项用例
- [ ] CI 可执行

### 集成与交付
- [ ] 集成后检查通过
- [ ] 制品版本化可追溯
- [ ] 回滚路径可用
- [ ] 发布过程可审计

### 持续演进
- [ ] 信号有采集与分级
- [ ] 问题能回流到正确层级
- [ ] 修复附带回归保护
- [ ] 资产与行为同步更新

### 工具与技能
- [ ] 各关键环节有最小自动能力
- [ ] 核心 Skill 可触发
- [ ] CI 与本地路径一致
- [ ] 权限最小化

## 2. 术语表

| 术语 | 含义 |
|------|------|
| AI-Native SDLC | 以 Agent 为一级生产力、人以意图与裁决、全流程可检查的软件工程方法 |
| 意图 | 目标、边界与验收标准 |
| 验收标准 | 可观察、可判定的完成条件 |
| 契约 | 接口的输入、输出、错误与约束 |
| 高风险路径 | 并发、状态机、权限、资源、失败恢复等易出严重缺陷的路径 |
| Safety | 坏事永不发生 |
| Liveness | 好事最终会发生 |
| 模型检查 | 系统化探索状态以寻找违反属性的反例 |
| 有界验证 | 在有限边界内检查实现性质 |
| 门禁 | 未通过则不可进入下一阶段的强制检查 |
| 回归保护 | 防止缺陷重现的测试/验证/规则 |
| Skill | 供 Agent 按需加载的结构化能力说明 |
| MCP | Agent 连接外部工具与数据源的协议/服务 |
| 制品 | 可版本化、可部署的构建结果 |
| 止损 | 先限制损害，再根治 |

## 3. 反模式汇总

| 反模式 | 正确做法 |
|--------|----------|
| 先做后想 | 先目标/边界/验收 |
| 模糊完成 | 可判定验收标准 |
| 无边界设计 | 先定边界与契约 |
| 隐式协议 | 变更先回设计 |
| 只测成功路径 | 成功与关键失败成对 |
| 用测试替代一切验证 | 风险路径加强验证 |
| 大爆炸合并 | 小批量集成 |
| 无回滚发布 | 先定义退路 |
| 修症状不回归 | 修复必补保护 |
| 工具收藏 | 最小集 + 按需扩展 |
| 本地与 CI 两套标准 | 统一命令与门禁 |
| 重型证明默认化 | 仅强保证场景启用 |

## 4. Agent 执行要点

- 先用清单定位缺口，再进入对应章节技能
- 术语冲突时以本附录为准
- 发现反模式时，先回到对应层级纠正，再继续生成
