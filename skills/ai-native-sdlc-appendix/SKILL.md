# AI-Native SDLC · 附录

## 1. 总检查清单

### 意图与需求
- [ ] 目标可观察
- [ ] 边界与非目标清晰
- [ ] 验收标准可判定
- [ ] 关键验收有表格或属性线索（可执行方向）
- [ ] 关键歧义已消除（人/Agent 不宜对同一句有第二种常理解释）
- [ ] 高风险线索已标记

### 设计与架构
- [ ] 模块职责清晰
- [ ] 关键接口有契约
- [ ] 关键非法状态已尽量不可表示或有显式校验层
- [ ] 高风险路径已识别并标明验证/仿真去向
- [ ] 失败与恢复策略已定义
- [ ] 非确定性依赖边界清晰（便于库级/全系统确定性仿真）
- [ ] 重要决策已记录

### 验证
- [ ] 属性已定义并可追溯（优先可执行形式）
- [ ] 高风险设计已完成相应检查（如模型检查）
- [ ] 实现层关键检查已按目标语言选型并完成
- [ ] 结果可解释且可重复执行
- [ ] 反例/冲突已关闭或已反哺规格

### 实现
- [ ] 代码落在既定边界内
- [ ] 接口行为符合契约
- [ ] 失败路径显式实现
- [ ] 高风险路径保留可检查性（含仿真/Expect 钩子，若需要）
- [ ] 无未批准的架构级偏差
- [ ] 关键逻辑对审阅者可读

### 测试
- [ ] 主验收标准有自动测试
- [ ] 关键失败路径有覆盖
- [ ] 关键性质有属性测试或等价可执行规格
- [ ] 高风险输入面有 fuzz 或等价加固（如适用）
- [ ] 关键协作路径有可读行为轨迹（Expect 类）或库级仿真
- [ ] 分布式/恢复关键路径已评估 DST 或等价可复现手段
- [ ] 高风险场景有专项用例
- [ ] CI 可执行；失败可指向行为或契约
- [ ] （建议）关键区做过差异或变异抽检
- [ ] 复杂度/静态门禁未无故放松

### 集成与交付
- [ ] 集成后检查通过
- [ ] 关键路径的属性/场景/仿真回归未无故跳过
- [ ] 制品版本化可追溯
- [ ] 发布前检查完成
- [ ] 回滚路径可用
- [ ] 发布过程可审计
- [ ] 变更粒度可审（避免不可审的巨型 Agent PR）

### 持续演进
- [ ] 信号有采集与分级
- [ ] 问题能回流到正确层级
- [ ] 修复附带回归保护（含可重放种子/轨迹，若适用）
- [ ] 资产与行为同步更新
- [ ] 复盘结论可执行（写入规则/Skill/门禁）
- [ ] 变更已经可理解的审阅或等价门禁

### 工具与技能
- [ ] 各关键环节有最小自动能力
- [ ] 核心 Skill 可触发
- [ ] CI 与本地路径一致
- [ ] 权限最小化
- [ ] 形式化/全系统 DST 等重型手段仅按风险与成熟度启用
- [ ] 写作检查类工具为可选辅助，未当作流程硬依赖

## 2. 术语表

| 术语 | 含义 |
|------|------|
| AI-Native SDLC | 以 Agent 为一级生产力、人负责意图与裁决、全流程可检查的软件工程方法 |
| 意图 | 目标、边界与验收标准 |
| 验收标准 | 可观察、可判定的完成条件 |
| 低歧义表达 | 同一陈述尽量只有一种合理理解；目的是人/Agent 对齐，手段可自选 |
| 受控技术写作 | 通过用词与句式约束降低技术文本歧义的一类实践 |
| ASD-STE100 | 受控技术英语的一种行业规范；本书仅作英语场景的**可选参考**，不要求全文合规，也不作为流程依赖 |
| STE 实用子集 | 借鉴 STE 中对降歧义最有用的习惯（约「用到大部分有用规则」的实践说法），而非认证级全量执行 |
| 契约 | 接口的输入、输出、错误与约束 |
| 契约式编程 / Design by Contract | 将前置/后置条件与不变量写入代码并由工具强制 |
| Spec-Driven Development (SDD) | 规格优先、实现服从规格的广义流程 |
| 可执行规格 | 可用测试或证明器自动检查的规格 |
| 高风险路径 | 并发、状态机、权限、资源、失败恢复等易出严重缺陷的路径 |
| Safety / Liveness | 坏事永不发生 / 好事最终会发生 |
| 模型检查 | 系统化探索状态空间以寻找违反属性的反例 |
| 有界验证 | 在有限边界内检查实现性质 |
| 形式化验证 | 用数学方法证明或证伪实现/模型满足规格；成熟度因语言而异 |
| 属性测试 (PBT) | 用通用性质 + 自动生成输入验证行为 |
| 模糊测试 (Fuzzing) | 用大量异常/随机输入挖掘崩溃与违例 |
| 差异测试 | 同一输入下比较多个实现是否一致 |
| 变异测试 | 故意改坏代码，评估现有测试能否发现 |
| Expect 测试 / 快照行为测试 | 将可读输出嵌入测试，失败时以 diff 呈现行为变化 |
| 确定性仿真测试 (DST) | 在可控仿真环境中运行系统，控制时间/调度/随机/故障，使轨迹可由种子完整重放 |
| 库级确定性仿真 | 对时钟、网络等依赖做可插拔内存实现，获得快速可复现协作测试 |
| 全系统 DST | 多节点/多组件在受控运行时中仿真并注入故障的整系统测试 |
| 圈复杂度 / 认知复杂度 | 代码结构复杂度度量 |
| 非法状态不可表示 | 用类型或模型使错误组合无法被构造 |
| Verus / Creusot / Prusti / Kani | Rust 侧证明或有界检查相关工具 |
| Frama-C / CBMC | C/C++ 侧分析、契约与有界模型检查 |
| SPARK | Ada 高保证子集与验证工具链 |
| Gobra | Go 验证器；偏研究原型，宜限关键模块 |
| 门禁 | 未通过则不可进入下一阶段的强制检查 |
| 回归保护 | 防止缺陷重现的测试/验证/规则 |
| Skill | 供 Agent 按需加载的结构化能力说明 |
| MCP | Agent 连接外部工具与数据源的协议/服务 |
| 制品 | 可版本化、可部署的构建结果 |
| 止损 | 先限制损害，再根治 |

## 3. 反模式汇总

| 反模式 | 正确做法 |
|--------|----------|
| 先做后想 | 先目标/边界/验收 |
| 模糊完成 | 可判定验收标准 |
| 把某一写作标准当成意图合格的必要条件 | 以是否可判定、是否仍歧义为准；标准仅可选辅助 |
| 无边界设计 | 先定边界与契约 |
| 隐式协议 | 变更先回设计 |
| 只测成功路径 | 成功与关键失败成对 |
| 用测试替代一切验证 | 风险路径按语言加强验证 |
| 无限加长自然语言规格 | 冲突时优先补表格/属性/差异用例 |
| 规格幻想穷尽每一行实现 | 锁定性质与禁止行为；细节用测试闭环 |
| 忽略 Agent 理解冲突 | 可执行规格 + 多实现差异测试 + 反哺 |
| 不可复现的偶发失败只靠重跑 | 控制时间/调度/随机或采用 DST |
| 无结构输出当 Expect | 刻意设计人类可读轨迹 |
| 普通业务默认全系统 DST | 按风险选用库级仿真或属性/集成 |
| 用混沌替代可复现手段 | 混沌管存活；DST 管重放 |
| 默认上重型定理证明 | 仅强保证内核启用 |
| 忽视语言工具成熟度 | 按生态现实选型 |
| 绑死单一语言或单一仿真产品 | 原则中立，工具可替换 |
| 只写测试从不评估测试强度 | 关键路径考虑变异或审查 |
| 复杂度失控仍堆功能 | 设计期限制 + 度量门禁 |
| 大爆炸合并 | 小批量集成 |
| 无回滚发布 | 先定义退路 |
| 修症状不回归 | 修复必补保护（含可重放种子） |
| 工具收藏 | 最小集 + 按需扩展 |
| 本地与 CI 两套标准 | 统一命令与门禁 |

## 4. Agent 执行要点

- 先用清单定位缺口，再进入对应章节技能
- 术语冲突时以本附录为准
- 发现反模式时，先回到对应层级纠正，再继续生成
- 涉及验证/测试/仿真时，先确认目标语言、系统形态与风险，再选型，避免默认某一种证明器、仿真平台或写作标准
