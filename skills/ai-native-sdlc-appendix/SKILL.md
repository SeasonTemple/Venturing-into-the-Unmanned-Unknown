# AI-Native SDLC · 附录

## 1. 总检查清单（摘要）

完整项见 `checklists/master-checklist.md`。正确性相关硬项：

- [ ] 意图基线可判定（允许已知未知）
- [ ] 关键性质有 ID
- [ ] 验证/测试通过项含「已查性质」与「未覆盖」
- [ ] 高风险路径有独立检查考虑（防实现-测试共错）
- [ ] 缺性质级证据不发布
- [ ] 若引入形式化：验证章 D1–D6 已满足且有维护 owner

## 2. 术语（增补）

| 术语 | 含义 |
|------|------|
| 正确性层 | 第 4 章验证 + 第 5 章测试 |
| 性质级证据 | 声明已查性质、未覆盖性质与证据指针的检查结果 |
| 验证闭环 | Agent 改→跑独立检查→读结果→再改 |
| 认知投降 | 将 Agent 输出不加检查地当作己见（HITL 失效模式） |
| 编排税 | 生成速度快于可负责审阅速度时的缺口 |
| 形式化引入决策 | 采纳模型检查/证明器等前须完成的性质缺口、增量、边界、维护与停止条件论证（见验证章第 4 节） |

其余：生产主体、HITL、系统保证、DST、形式化验证等见导论与各章。

## 3. 反模式（增补）

| 反模式 | 正确做法 |
|--------|----------|
| 一片绿即发布 | 性质覆盖表 + 未覆盖显式 |
| 同 Agent 自写自测当唯一证据 | 加独立规格/差异/验证手段 |
| 只扩生成并发、不扩门禁 | 先收紧检查或降并发 |
| 认知投降 | 假设、抽查、不能辩护则不合并 |
| 验证章与测试章当无关故事 | 统一为正确性层 |
| 未扣除已有 PBT/矩阵就开形式化 Issue | 先记账已有断言，再论证组合空间增量 |
| 为工具名寻找工作 | 先性质与缺口，再选手段 |
| 调研报告直接当实施授权 | 候选评估与实施分阶段；缺 D1–D6 不立项 |
| 机械翻译已有内存状态机到 TLA+ 并双维护 | 无增量与维护论证则不翻译 |
| 模型另立第五层产品规范 | 验证资产挂接既有契约/owner |

## 4. 本书局限、未知与不足

### 4.1 局限

- 工程方法骨架，**不是**合规、认证或法定签字替代
- 形式化与全系统 DST 受语言生态与成本约束，不得默认全开
- 无大规模对照实验证明「采用本书」的量化因果
- 不覆盖招聘、法务、预算政治等组织议题

### 4.2 未知

- Agent 能力变化后，HITL 最小必要集如何迁移
- 多 Agent 长期协作下的规格所有权与冲突协议
- 验证资产本身由 Agent 生成时，独立性如何制度保证

### 4.3 不足（版本演进中）

- 各章体例仍在向统一技术文档模板收敛
- 双受众（Agent / HITL）小节尚未铺满每一章
- 性质覆盖表的机器可读 schema 未标准化
- 站点与 `main` 合并前可能短时不一致

### 4.4 结构说明（v0.0.4-draft）

章节顺序：意图 → 设计 → **实现 → 验证 → 测试** → 交付 → 演进。  
正确性层在实现之后、交付之前；导论强调证据瓶颈；验证章含形式化引入决策。

## 5. Agent 执行要点

- 清单缺口 → 打开对应章 Skill
- 术语冲突以本附录与导论为准
- 默认生产主体；门禁失败停止；风险上升 HITL
- 用户问「要不要上形式化」→ 验证章第 4 节 D1–D6，禁止空泛推荐工具
