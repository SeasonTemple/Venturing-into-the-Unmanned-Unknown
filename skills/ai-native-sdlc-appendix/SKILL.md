# AI-Native SDLC · 附录

## 1. 总检查清单

### 意图与需求
- [ ] 目标可观察
- [ ] 边界与非目标清晰
- [ ] 验收标准可判定
- [ ] 关键歧义已消除（含受控表达或正反例）
- [ ] 高风险线索已标记

### 设计与架构
- [ ] 模块职责清晰
- [ ] 关键接口有契约
- [ ] 高风险路径已识别并标明验证去向
- [ ] 失败与恢复策略已定义
- [ ] 重要决策已记录

### 验证
- [ ] 属性已定义并可追溯（优先可执行形式）
- [ ] 高风险设计已完成相应检查（如模型检查）
- [ ] 实现层关键检查已按**目标语言**选型并完成
- [ ] 结果可解释且可重复执行
- [ ] 反例/冲突已关闭或已反哺规格

### 实现
- [ ] 代码落在既定边界内
- [ ] 接口行为符合契约
- [ ] 失败路径显式实现
- [ ] 高风险路径保留可检查性

### 测试
- [ ] 主验收标准有自动测试
- [ ] 关键失败路径有覆盖
- [ ] 关键性质有属性测试或等价可执行规格
- [ ] 高风险输入面有模糊测试或等价加固（如适用）
- [ ] 高风险场景有专项用例
- [ ] CI 可执行
- [ ] （建议）关键区做过差异或变异抽检
- [ ] 复杂度/静态门禁未无故放松

### 集成与交付
- [ ] 集成后检查通过
- [ ] 制品版本化可追溯
- [ ] 回滚路径可用
- [ ] 发布过程可审计

### 持续演进
- [ ] 信号有采集与分级
- [ ] 问题能回流到正确层级
- [ ] 修复附带回归保护
- [ ] 资产与行为同步更新

### 工具与技能
- [ ] 各关键环节有最小自动能力
- [ ] 核心 Skill 可触发
- [ ] CI 与本地路径一致
- [ ] 权限最小化
- [ ] 形式化/重型工具仅按风险与语言成熟度启用

## 2. 术语表

| 术语 | 含义 |
|------|------|
| AI-Native SDLC | 以 Agent 为一级生产力、人负责意图与裁决、全流程可检查的软件工程方法 |
| 意图 | 目标、边界与验收标准 |
| 验收标准 | 可观察、可判定的完成条件 |
| 契约 | 接口的输入、输出、错误与约束（可运行时检查或静态证明） |
| 契约式编程 / Design by Contract | 将前置/后置条件与不变量写入代码并由工具强制的实践 |
| Spec-Driven Development (SDD) | 规格优先、实现服从规格的广义流程；契约是其中一种落地手段 |
| 可执行规格 | 可用测试或证明器自动检查的规格（表格用例、属性、形式化契约等） |
| 高风险路径 | 并发、状态机、权限、资源、失败恢复等易出严重缺陷的路径 |
| Safety | 坏事永不发生 |
| Liveness | 好事最终会发生 |
| 模型检查 | 系统化探索状态空间以寻找违反属性的反例（如 TLA+/TLC） |
| 有界验证 / 有界模型检查 | 在有限边界内检查实现性质（如 CBMC、Kani） |
| 形式化验证 | 用数学方法证明实现满足规格；成熟度因语言而异 |
| ASD-STE100 | 受控技术英语标准，用于降低技术文档歧义 |
| 属性测试 (PBT) | 用通用性质 + 自动生成输入验证行为 |
| 模糊测试 (Fuzzing) | 用大量异常/随机输入挖掘崩溃与违例 |
| 差异测试 | 同一输入下比较多个实现是否一致 |
| 变异测试 | 故意改坏代码，评估现有测试能否发现 |
| 圈复杂度 / 认知复杂度 | 代码结构复杂度度量，用于健康度门禁 |
| Verus / Creusot / Prusti | Rust 侧契约或证明相关工具 |
| Kani | Rust 有界模型检查工具 |
| Frama-C / CBMC | C/C++ 侧静态分析、契约与有界模型检查 |
| SPARK | Ada 高保证子集与验证工具链 |
| Gobra | Go 的分离逻辑式验证器；目前偏研究原型，宜限关键模块 |
| 门禁 | 未通过则不可进入下一阶段的强制检查 |
| 回归保护 | 防止缺陷重现的测试/验证/规则 |
| Skill | 供 Agent 按需加载的结构化能力说明 |
| MCP | Agent 连接外部工具与数据源的协议/服务 |
| 制品 | 可版本化、可部署的构建结果 |
| 止损 | 先限制损害，再根治 |

## 3. 反模式汇总

| 反模式 | 正确做法 |
|--------|----------|
| 先做后想 | 先目标/边界/验收 |
| 模糊完成 | 可判定验收标准 |
| 无边界设计 | 先定边界与契约 |
| 隐式协议 | 变更先回设计 |
| 只测成功路径 | 成功与关键失败成对 |
| 用测试替代一切验证 | 风险路径按语言加强验证 |
| 无限加长自然语言规格 | 冲突时优先补表格/属性/差异用例 |
| 规格幻想穷尽每一行实现 | 锁定性质与禁止行为；细节用测试闭环 |
| 忽略 Agent 理解冲突 | 可执行规格 + 多实现差异测试 + 反哺 |
| 默认上重型定理证明 | 仅强保证内核启用 Lean/Coq 等 |
| 忽视语言工具成熟度 | 按 Rust/C/Ada/Go 等生态现实选型（如 Go 上 Gobra 不默认全量） |
| 绑死单一语言工具名 | 按项目语言替换等价工具 |
| 只写测试从不评估测试强度 | 关键路径考虑变异测试或审查 |
| 复杂度失控仍堆功能 | 设计期限制规模 + 度量门禁 |
| 大爆炸合并 | 小批量集成 |
| 无回滚发布 | 先定义退路 |
| 修症状不回归 | 修复必补保护 |
| 工具收藏 | 最小集 + 按需扩展 |
| 本地与 CI 两套标准 | 统一命令与门禁 |

## 4. Agent 执行要点

- 先用清单定位缺口，再进入对应章节技能
- 术语冲突时以本附录为准
- 发现反模式时，先回到对应层级纠正，再继续生成
- 涉及验证/测试工具时，先确认目标语言与风险，再选型，避免默认某一种证明器或测试框架
