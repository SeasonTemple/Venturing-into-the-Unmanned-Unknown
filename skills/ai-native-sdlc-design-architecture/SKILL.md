# AI-Native SDLC · 设计与架构

## 1. 范围与定位

**位置：** 意图 → **设计** → 实现 → 验证 → 测试 → 交付 → 演进

| 价值 | 说明 |
|------|------|
| 可分解 | 可独立理解与实现 |
| 可协作 | 多 Agent 按边界并行 |
| 可验证 | 高风险路径显式 |
| 可度量 | 性能与资源目标可检查 |
| 可演进 | 决策可追溯 |

### 原则

- 意图驱动；边界优先
- 非法状态尽量不可表示
- 风险显式；为验证与可复现测试服务
- **关键路径须有性能/资源预算或显式「本阶段不承诺」**

---

## 2. 核心产物

| 产物 | 作用 |
|------|------|
| 模块与边界 | 职责与非职责 |
| 接口契约 | 输入、输出、错误、前后置 |
| 不变量 / 类型模型 | 结构上收紧状态 |
| 关键路径视图 | 并发、状态、权限、**资源与热点** |
| 失败与恢复策略 | 出错与降级行为 |
| **性能与资源预算** | 延迟、吞吐、内存、句柄、启动等可检查目标 |
| 可仿真边界 | 时钟、IO、网络可插拔 |
| ADR | 重要取舍 |

### 类型与模型

优先使非法状态不可表示；无强类型时用状态机、校验层与契约近似。类型/结构错误是对 Agent 的快速反馈。

### 设计深度

| 层级 | 产出 |
|------|------|
| 概念 | 模块、主流程、边界 |
| 逻辑 | 接口、状态、失败路径、预算、可插拔依赖 |
| 详细 | 仅高风险：协议步骤、注入点、热点数据路径 |

默认逻辑设计；高风险再下钻。

---

## 3. 性能与资源（设计检查点）

功能正确性之外，设计基线**应**回答关键路径在约定条件下的表现预期。

| 项 | 要求 |
|----|------|
| 预算来源 | 对齐意图中的性能/体验目标；无目标则标「未承诺」 |
| 典型维度 | 延迟（含分位）、吞吐、CPU、内存、句柄/连接、启动/恢复时间、包体积（客户端） |
| 热点 | 标识可能的热路径、锁、大分配、同步阻塞点 |
| 背压与饱和 | 过载时拒绝、排队还是降级；是否 fail-closed |
| 可观测 | 需要哪些指标/日志才能在测试与运行中核对预算 |
| 环境假设 | 机器规格、OS、网络；客户端注明实验室 vs 真实机差异 |

**不得**用「实现后再看」代替关键路径的预算或显式非目标。预算可以粗糙（数量级），但必须可判定是否违反。

与正确性关系：超时与资源耗尽时的**安全失败**属于契约/性质；「足够快」属于性能预算；二者都要设计，门禁可分开。

---

## 4. 流程与门禁

1. 从意图提取功能与**性能/资源**驱动因素  
2. 划分模块与职责  
3. 定义接口契约  
4. 收紧非法状态；标注不变量  
5. 识别高风险路径（含性能热点）与验证/测试去向  
6. 失败/恢复/背压；可插拔非确定性边界  
7. 写下性能与资源预算或「未承诺」  
8. 关键 ADR；输出设计基线  

### 质量门禁

- [ ] 模块职责清晰
- [ ] 关键接口有可判定契约
- [ ] 关键非法状态尽量不可表示或有校验层
- [ ] 高风险路径已识别并标明验证/测试/仿真去向
- [ ] 失败与恢复已定义
- [ ] **关键路径有性能/资源预算或显式未承诺**
- [ ] **过载/耗尽行为已定义（背压或安全失败）**
- [ ] 非确定性依赖边界清晰
- [ ] 重要决策已记录

---

## 5. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 边界、契约、预算成为实现与基准测试的输入 | 不代替真实环境测量 |
| HITL | 审热点与「未承诺」是否可接受 | 不要求一次定死全部 SLA |

---

## 6. 要点

- 设计产出可检查边界，不只是框图
- 性能与资源是一等设计产物，进入实现与测试门禁
