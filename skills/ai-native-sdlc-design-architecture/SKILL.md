# AI-Native SDLC · 设计与架构

## 1. 本章定位

设计与架构位于意图澄清之后、实现与验证之前：

**意图澄清 →「设计与架构」→ 实现 → 验证 → 集成与交付 → 持续演进**

### 核心价值

| 价值 | 说明 |
|------|------|
| 可分解 | 系统可被拆成可独立理解与实现的部分 |
| 可协作 | 多 Agent 可按边界并行工作 |
| 可验证 | 高风险路径被显式识别 |
| 可反馈 | 结构与不变量对 Agent/人可读、可检查 |
| 可演进 | 决策有记录，变更有约束 |

### 基本原则

- 意图驱动，不先陷入技术细节
- 边界优先，先定责任再定实现
- **非法状态尽量不可表示**（用类型、模型或枚举收紧状态空间）
- 风险显式化；决策可追溯
- 为验证与**可复现测试/仿真**服务（时间、IO、网络等边界可插拔）
- 表达低歧义（可与受控写作衔接）

## 2. 理论框架

### 核心产物

| 产物 | 作用 |
|------|------|
| 模块与边界 | 组成与职责 |
| 接口契约 | 协作方式与约束 |
| 不变量与类型/模型约束 | 全局规则在结构上强制，而非仅靠约定 |
| 关键路径视图 | 并发、状态、权限、资源风险 |
| 失败与恢复策略 | 出错时的系统行为 |
| 可仿真边界 | 时钟、网络、存储等非确定性依赖的抽象 |
| 架构决策记录 | 重要取舍 |

### 类型与模型：从「保姆」到设计工具

在具备静态类型或等价建模能力的环境中：

- 用类型/模型表达**横切不变量**（例如：已转义文本、已校验 ID、互斥配置字段），使违规在编译期或检查期暴露。
- **Make illegal states unrepresentable**：优先用结构（记录字段、option/list、代数数据类型）表达「出现 0/1/多次」，避免「命令序列里同语义出现两次」一类模糊状态。
- 对 Agent：类型错误是**极快、按需**的反馈；全局不变量写入结构后，比长篇自然语言约束更难被遗忘。
- 无强类型语言时：用显式状态机、校验层、契约与代码生成达到相近目标，而非放弃「不可表示」原则。

### 设计深度控制

| 层级 | 何时使用 | 产出粒度 |
|------|----------|----------|
| 概念设计 | 早期对齐 | 模块、主流程、边界 |
| 逻辑设计 | 准备实现 | 接口、状态、数据流、失败路径、可插拔依赖 |
| 详细设计 | 仅高风险处 | 协议步骤、状态转移、约束、仿真注入点 |

默认做到逻辑设计；只对高风险路径下钻。

## 4. 规范执行流程

1. 从意图提取设计驱动因素
2. 划分模块与职责（做什么 / 不做什么）
3. 定义接口契约（输入、输出、错误、前后置条件）
4. 用类型或等价模型收紧非法状态；标注全局不变量
5. 识别高风险路径并标注验证/仿真去向
6. 定义失败与恢复策略；标出可插拔的时间/IO/网络边界（便于库级或全系统 DST）
7. 记录关键 ADR
8. 输出设计基线包

### 质量门禁

- [ ] 模块职责清晰，无重叠责任
- [ ] 关键接口有可判定契约
- [ ] 关键非法状态已尽量不可表示或有显式校验层
- [ ] 高风险路径已显式识别并标明验证/仿真方式
- [ ] 失败行为已定义
- [ ] 非确定性依赖边界清晰（便于测试仿真）
- [ ] 重要决策已记录
- [ ] 表达低歧义

## 5. 简洁实例

**意图：** 文档写锁，同一时刻最多一个写者。

**模块：** `LockService` / `DocumentService` / `SessionGateway`

**契约要点：** `acquireWriteLock(docId, userId, ttl)` — 成功返回 token；已锁 → `alreadyLocked`；会话无效 → `invalidSession`。

**不变量：** 「同一 docId 至多一个有效写锁」在模型或类型层可陈述；锁令牌与会话绑定不可伪造。

**高风险：** 并发申请、超时回收、释放与超时竞态 → 标注模型检查与/或库级确定性仿真。

**可仿真：** 时钟与会话存储可替换，便于加速 TTL 与故障注入。

## 6. Agent 执行要点

1. 先边界后细节，禁止一上来大段编码
2. 接口必须可判定，拒绝模糊词
3. 优先把全局规则写入结构（类型/状态机），再依赖自然语言约束
4. 高风险路径必须列出验证或可复现测试方式
5. 与意图冲突时回到意图层

---

## 7. 本章要点

- 设计在 AI 高速生成前固定结构、不变量与风险
- 核心产出：边界、契约、不可表示的非法状态、风险路径、可仿真边界、失败策略与 ADR
- 设计必须能映射到验证与可复现测试
