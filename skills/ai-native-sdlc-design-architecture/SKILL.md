# AI-Native SDLC · 设计与架构

## 1. 本章定位

设计与架构位于意图澄清之后、实现与验证之前：

**意图澄清 →「设计与架构」→ 实现 → 验证 → 集成与交付 → 持续演进**

### 核心价值

| 价值 | 说明 |
|------|------|
| 可分解 | 系统可被拆成可独立理解与实现的部分 |
| 可协作 | 多 Agent 可按边界并行工作 |
| 可验证 | 高风险路径被显式识别 |
| 可演进 | 决策有记录，变更有约束 |

### 基本原则

- 意图驱动，不先陷入技术细节
- 边界优先，先定责任再定实现
- 风险显式化
- 决策可追溯
- 为验证服务

---

## 2. 理论框架

### 核心产物

| 产物 | 作用 |
|------|------|
| 模块与边界 | 组成与职责 |
| 接口契约 | 协作方式与约束 |
| 关键路径视图 | 并发、状态、权限、资源风险 |
| 失败与恢复策略 | 出错时的系统行为 |
| 架构决策记录 | 重要取舍 |

### 设计深度控制

| 层级 | 何时使用 | 产出粒度 |
|------|----------|----------|
| 概念设计 | 早期对齐 | 模块、主流程、边界 |
| 逻辑设计 | 准备实现 | 接口、状态、数据流、失败路径 |
| 详细设计 | 仅高风险处 | 协议步骤、状态转移、约束 |

默认做到逻辑设计；只对高风险路径下钻。

## 4. 规范执行流程

1. 从意图提取设计驱动因素
2. 划分模块与职责（做什么 / 不做什么）
3. 定义接口契约（输入、输出、错误、前后置条件）
4. 识别高风险路径并标注验证去向
5. 定义失败与恢复策略
6. 记录关键 ADR
7. 输出设计基线包

### 质量门禁

- [ ] 模块职责清晰，无重叠责任
- [ ] 关键接口有可判定契约
- [ ] 高风险路径已显式识别
- [ ] 失败行为已定义
- [ ] 重要决策已记录
- [ ] 表达低歧义

---

## 5. 简洁实例

**意图：** 文档写锁，同一时刻最多一个写者。

**模块：** `LockService` / `DocumentService` / `SessionGateway`

**契约要点：** `acquireWriteLock(docId, userId, ttl)`
成功返回 token；已锁返回 `alreadyLocked`；会话无效返回 `invalidSession`。

**高风险：** 并发申请、超时回收、释放与超时竞态。

---

## 6. Agent 执行要点

1. 先边界后细节，禁止一上来大段编码
2. 接口必须可判定，拒绝模糊词
3. 高风险路径必须列出验证方式
4. 与意图冲突时回到意图层

---

## 7. 本章要点

- 设计是在 AI 高速生成前固定结构与风险的关键步骤
- 核心产出是边界、契约、风险路径、失败策略与决策记录
- 设计必须能映射到验证
