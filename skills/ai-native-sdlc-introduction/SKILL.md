# AI-Native SDLC · 导论

## 1. 范围

本章规定：

1. 术语与角色
2. 规范性要求 R1–R3
3. **瓶颈命题**：生成之后，稀缺的是可独立检查的正确性证据
4. 约束链与章节映射
5. 适用范围；详细局限见附录

不规定具体语言、证明器或 CI 产品。

---

## 2. 术语

| 术语 | 定义 |
|------|------|
| AI-Native SDLC | 以 Agent 为生产与执行主体，在生命周期各阶段推进工作，并以意图输入、HITL 与系统保证共同约束交付的方法 |
| Agent | 可调用工具、生成与修改产物、执行检查并推进多步任务的执行单元 |
| 生产主体 | 主要生成、修改、执行与推进的角色；本方法中为 Agent |
| 意图输入 | 目标、边界、非目标、优先级与硬约束；允许不完备并迭代 |
| HITL | 人在环内对指定事项的裁决；权重通常较高，但不是唯一否决源 |
| 系统保证 | 可执行规格、检查、测试、验证、仿真、CI 等可重复约束 |
| 门禁 | 未通过则不得进入下一阶段的强制检查 |
| 性质级证据 | 明确「检查了哪条性质」与「未覆盖哪条性质」的检查结果；区别于笼统「一片绿」 |
| 验证闭环 | Agent 修改后自行运行独立检查、读取结果并迭代，直到满足预定义完成条件或报告失败 |

---

## 3. 规范性要求

| ID | 要求 |
|----|------|
| R1 | 生产主体为 Agent。 |
| R2 | 人提供意图输入，并作为 HITL 裁决源之一。人不是默认编码生产主体。 |
| R3 | 系统保证可独立否决。硬门禁失败时不得晋级。 |

缺一则不按本文件称为 AI-Native SDLC。

---

## 4. 瓶颈命题（规范性背景）

在 Agent 可大规模生成产物的前提下，项目成败更常取决于：

1. 是否存在**独立于实现作者**的检查手段（规格、测试、模型检查、仿真、差异参考等）
2. 门禁是否按**性质**记录覆盖，而非仅显示通过
3. HITL 是否仍对残余风险与责任保持裁决能力（避免认知投降）

生成能力不是本方法的主优化目标。主优化目标是：**可判定意图 → 可执行规格 → 验证闭环 → 性质级门禁 → 有界 HITL**。

意图与设计不可省略：无可判定意图时，检查在验证错误问题。

---

## 5. 角色与职责

| 角色 | 应做 | 不应做 |
|------|------|--------|
| Agent | 在基线与门禁内生产；跑验证闭环；提交性质级证据 | 绕过硬门禁；把已知未知写成已锁定性质 |
| 人（意图源） | 提供与更新意图；标非目标与硬约束 | 要求首轮穷尽全部性质 |
| 人（HITL） | 裁决冲突、风险例外、发布/合规；审查未覆盖性质 | 默认逐行手写替代 Agent 生产 |
| 系统保证 | 可重复否决；保留命令与输出证据 | 替代价值与合规判断 |

**裁决顺序：** 硬门禁失败 → 停；通过且属 HITL 范围 → 等 HITL；否则 Agent 可继续。

---

## 6. 与相邻模式对照

| 模式 | 生产主体 | 人的主职责 | 系统保证 |
|------|----------|------------|----------|
| 传统 SDLC | 人 | 执行分析/实现/测试 | 可选 |
| AI 辅助开发 | 人 | 主体写作；模型补全 | 常仍按人为主路径 |
| AI-Native SDLC | Agent | 意图输入；HITL 之一 | 门禁为晋级必要条件 |

## 7. 约束链与章节映射

```
意图 → 设计 → 实现 → 验证/测试（正确性层）→ 集成交付 → 演进
ch1    ch2    ch3     ch4 + ch5                ch6        ch7
                                                    工具横切 ch8
```

| 章 | 标题 | 典型输入 | 典型输出 |
|----|------|----------|----------|
| 0 | 导论 | — | 术语、角色、瓶颈约定 |
| 1 | 意图与需求 | 原始描述 | 意图基线、验收、已知未知 |
| 2 | 设计与架构 | 意图基线 | 边界、契约、风险路径 |
| 3 | 实现 | 设计基线 | 模块代码与可检查点 |
| 4 | 验证 | 属性与设计 | 形式化/有界/契约检查结果 |
| 5 | 测试与质量 | 验收与契约 | 自动测试、轨迹、种子、性质覆盖 |
| 6 | 集成与交付 | 已检变更 | 制品、门禁记录、发布/回滚 |
| 7 | 持续演进 | 信号 | 修复、回归、基线修订 |
| 8 | 工具与技能生态 | 环节需求 | 最小工具集 |
| A | 附录 | — | 清单、术语、反模式、局限 |

阅读顺序与上表一致。正确性层（第 4–5 章）共同回答「如何知道对不对」；第 6 章强制其成为晋级条件。

## 8. 目标与原则

| ID | 目标 |
|----|------|
| G1 | 缩短意图到可运行版本周期（Agent 推进） |
| G2 | 高风险行为可检查、可证伪、可复现 |
| G3 | 规格/测试/门禁同源 |
| G4 | 缺陷修复附带回归 |
| G5 | 产物与证据可供 HITL 审查 |

| ID | 原则 |
|----|------|
| P1 | 意图先行（可含已知未知） |
| P2 | 风险驱动 |
| P3 | 可检查；重要结论映射到工具或测试 |
| P4 | 可执行规格优先 |
| P5 | 验证闭环与反馈可阻断晋级 |
| P6 | 表达服务对齐；不强制特定写作标准 |
| P7 | 资产化 |
| P8 | 主体与约束分离 |
| P9 | 门禁性质显式：通过项须写明已查/未查性质 |

## 9. 双受众（全书默认）

| 受众 | 本书用法 |
|------|----------|
| Agent | 按各章输入/输出与门禁执行；提交证据；失败时停止并报告 |
| 人（意图/HITL） | 配置意图与门禁；审查未覆盖性质与风险例外；承担发布责任 |

各章可含「对 Agent / 对 HITL」小结。详细局限与未知见附录。

---

## 10. 适用范围

**适用：** 意图可逐步可判定，并可为晋级定义门禁的软件交付。  
**非目标：** 替代认证或法定签字；指定唯一工具链；保证无 HITL 或零缺陷。

---
