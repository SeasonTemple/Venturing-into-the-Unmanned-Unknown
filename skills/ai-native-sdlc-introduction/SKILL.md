# AI-Native SDLC · 导论

## 1. 本章定位

本章是全书起点，回答三个问题：

- 什么是 AI-Native SDLC
- 它解决什么问题
- 如何理解后续各章的位置与关系

---

## 2. 定义

**AI-Native SDLC**（AI-Native Software Development Life Cycle）是指：

> 以 **AI Agent 为生产与执行的主体**，在软件全生命周期中系统化地完成澄清、设计、实现、验证、交付与演进；人主要提供**原始意图输入**，并作为 **HITL（Human-in-the-Loop）裁决源之一**（通常权重更高），与可执行规格、自动门禁、测试与验证结果共同构成「能否进入下一阶段」的约束体系。

它不是「人写主体、AI 补几行」，也不是简单的「AI 生产 + 人拍板」二元口号，而是：

- **主体**：Agent（可多个）承担主要分析、生成、修改、跑检查与推进流程的工作
- **输入**：人（及产品/业务渠道）给出原始意图、优先级与不可让步的约束
- **裁决**：人是权威较高的 HITL 源，但不是唯一闸门——CI、类型/契约、测试、模型检查、仿真种子等同样可否决推进
- **纪律**：全程可检查、可回归、可协作，避免 Agent 在模糊意图下高速放大错误

目标不是「人不写、不读代码」，而是在 Agent 主体化之后，**仍然保持意图可追溯、关键路径可证伪、系统对人可理解**——否则后续 Agent 也无法持续有效工作。

---

## 3. 角色分层（理解层次）

| 角色 | 在 AI-Native SDLC 中的位置 |
|------|---------------------------|
| **Agent** | 生产与执行主体：设计草案、实现、测试草稿、修复、工具调用、多步编排 |
| **人（意图源）** | 原始意图、价值排序、非目标、组织约束的主要输入；意图可不完备，但须可迭代（见意图章） |
| **人（HITL 裁决）** | 对冲突规格、风险例外、发布与伦理/合规等做权威较高的裁决；审阅偏「理解与定调」，而非逐行代替 Agent 生产 |
| **系统保证** | 可执行规格、门禁、自动测试/验证/仿真：不依赖某次人工心情，可重复否决不合格产物 |

因此：从「AI 帮忙」到 AI-Native，关键转变不是多一个助手，而是 **工作主体切换为 Agent**，人退到**输入与（权威较高的）环内裁决**，质量靠**系统化保证**托底。人的稀缺资源是注意力与判断，不是键入速度。

---

## 4. 与相关概念的区别

| 模式 | 特征 | 局限 |
|------|------|------|
| 传统 SDLC | **人**是生产主体；工具辅助 | 速度受人力瓶颈限制 |
| AI 辅助开发 | **人**仍是生产主体；AI 补全、生成片段 | AI 产出缺少系统验证与流程约束；主体未切换 |
| **AI-Native SDLC** | **Agent** 是生产主体；人是意图输入 + HITL 裁决源之一；系统门禁可独立否决 | 需要新的表达、验证、反馈与协作规范；意图与门禁设计成为杠杆 |

---

## 5. 核心目标

1. **速度**：缩短从意图到可运行系统的周期（由 Agent 主体推进）
2. **可靠性**：高风险路径可被检查、可被证伪、关键失败可复现
3. **可协作**：多 Agent 与人类共享同一套表达与质量基准
4. **可演进**：知识、属性、测试与模型可沉淀、可回归
5. **可理解**：仓与行为对 HITL 保持可读，裁决才有依据，后续 Agent 才接得住

---

## 6. 基本原则

- **意图先行**：先有可迭代的意图输入，再大规模生成；不要求一次穷尽全部性质（见意图章）
- **风险驱动**：对高风险路径施加更强保证
- **可检查性**：重要结论必须可被工具或测试验证——系统保证与 HITL 并列，而非只靠人盯
- **可执行规格优先**：表格、属性、契约比纯自然语言更抗歧义，也更适合 Agent 与门禁消费
- **快速可读反馈**：类型/结构错误、Expect 轨迹、仿真种子等缩短闭环
- **表达以对齐为目的**：降歧义；具体写作标准可选，非流程依赖
- **资产化**：把属性、模型、测试、决策变成可维护资产
- **主体与裁决分离**：Agent 生产与执行；人提供意图并参与 HITL；自动门禁提供可重复约束

## 8. 适用边界

- 适用于可将意图逐步可判定、并愿意建立门禁的软件交付
- 高保证领域仍须按行业标准叠加形式化与认证；本书是工程方法骨架，不是合规替代
- 工具与语言成熟度差异大：原则跨语言，落地按生态选型
- 不承诺「无人裁决、全自动正确」：Agent 为主体时，**HITL + 系统保证**仍是必要组件；承诺的是可检查、可回归、角色清晰的流程
