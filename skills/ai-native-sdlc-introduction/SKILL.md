# AI-Native SDLC · 导论

## 1. 本章定位

本章是全书起点，回答三个问题：

- 什么是 AI-Native SDLC
- 它解决什么问题
- 如何理解后续各章的位置与关系

---

## 2. 定义

**AI-Native SDLC**（AI-Native Software Development Life Cycle）是指：

> 以 AI Agent 为一级生产力，人负责意图、约束与裁决，在软件全生命周期中系统化地完成需求、设计、实现、验证、交付与演进的工程方法。

它不是「用 AI 写一点代码」，而是把 Agent 纳入标准流程，并配套可检查、可回归、可协作的工程纪律。

---

## 3. 与相关概念的区别

| 模式 | 特征 | 局限 |
|------|------|------|
| 传统 SDLC | 人主导分析、设计、编码、测试 | 速度受人力瓶颈限制 |
| AI 辅助开发 | 人写主体，AI 补全、生成片段 | AI 产出缺少系统验证与流程约束 |
| **AI-Native SDLC** | Agent 承担主要生产，人定义意图与门禁 | 需要新的验证、表达与协作规范 |

关键转变：从「AI 帮忙」到「AI 生产 + 人裁决 + 系统保证」。

---

## 4. 核心目标

1. **速度**：缩短从意图到可运行系统的周期
2. **可靠性**：高风险路径可被检查、可被证伪
3. **可协作**：多 Agent 与人类共享同一套表达与质量基准
4. **可演进**：知识、属性、测试与模型可沉淀、可回归

---

## 5. 基本原则

- **意图先行**：先澄清要什么，再生成怎么做
- **风险驱动**：对高风险路径施加更强保证
- **可检查性**：重要结论必须可被工具或测试验证
- **表达纪律**：用低歧义语言减少误解
- **资产化**：把属性、模型、测试、决策变成可维护资产
- **人机分工**：Agent 负责生产与执行，人负责目标、约束与最终裁决

---

## 6. 全书结构

| 章 | 标题 | 作用 |
|----|------|------|
| 0 | 导论 | 定义、原则、总览 |
| 1 | 意图与需求 | 澄清要什么 |
| 2 | 设计与架构 | 决定怎么组织 |

| 4 | 实现 | 如何约束 Agent 产出代码 |
| 5 | 测试与质量保障 | 行为层保证 |

| 7 | 持续演进 | 反馈与回归 |
| 8 | 工具与技能生态 | Skill / MCP / CLI 体系 |

---

## 7. 适用边界

**适合：**
- 需要快速迭代且有一定质量要求的产品与平台
- 多 Agent 协作开发
- 存在并发、状态机、安全边界等风险路径的系统

**需谨慎加码：**
- 强监管、高保证、安全关键系统（需额外引入更强形式化手段）
- 纯探索性、无明确验收标准的实验

---

## 8. 本章要点

- AI-Native SDLC 的本质是「Agent 生产 + 人裁决 + 系统验证」
- 速度与可靠性必须同时设计，不能只追求生成
- 后续章节都服务于：让意图可执行、让结果可检查、让过程可重复
