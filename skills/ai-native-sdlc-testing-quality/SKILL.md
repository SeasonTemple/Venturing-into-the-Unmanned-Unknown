# AI-Native SDLC · 测试与质量保障

## 1. 范围与定位

本章与第 4 章验证共同构成**正确性层**。

| 项 | 约定 |
|----|------|
| 主问题 | 在具体场景与生成输入下行为是否符合验收与契约 |
| 与验证 | 验证偏设计/局部强性质；测试偏行为、轨迹、规模化生成输入与回归 |
| 瓶颈关系 | Agent 须能自跑测试形成验证闭环；HITL 审查「绿了什么」 |

### 原则

- 验收驱动；风险优先分层
- 可执行规格优先（表格 + 属性）
- 失败可解释；证据可重放
- 测试杀伤力可评估（差异/变异）
- 并发与分布式优先可复现（DST），而非只靠偶发重试

---

## 2. 性质级证据（与验证章同一字段）

| 字段 | 含义 |
|------|------|
| 性质 / 验收 ID | 对应哪条验收或属性 |
| 手段 | 单元 / PBT / fuzz / 差异 / Expect / DST / e2e 等 |
| 结果 | 通过 / 失败 / 未跑 |
| **未覆盖** | 本测试不声称的行为 |
| 证据指针 | 日志、报告、种子、轨迹 diff |

**禁止**将「CI 全绿」解读为「全部性质成立」。须能回答：这条绿检查了什么、故意没检查什么。

同模型既写实现又写测试时，**应**增加独立来源：人工规格、参考实现、差异测试或验证章手段。

---

## 3. 测试分层（语言中立）

| 层级 | 目标 |
|------|------|
| 单元 / 表驱动 | 局部逻辑 |
| Expect / 行为轨迹 | 可读 diff，利于 HITL 与 Agent |
| 属性测试 (PBT) | 普遍性质 + 生成输入 |
| 模糊测试 | 输入面健壮性 |
| 差异测试 | 多实现一致；多 Agent 冲突暴露 |
| 库级确定性仿真 | 可控时钟/网络下的协作 |
| 全系统 DST | 故障与调度可复现（高成本） |
| 集成 / e2e | 真实路径 |
| 变异测试 | 评估测试杀伤力 |
| 复杂度度量 | 结构健康度 |

---

## 4. 手段摘要

**属性测试：** 用「永远应成立」替代少量例子；与验证后置条件草稿对齐。  
**Fuzz：** 解析/协议输入面；坏例固化回归。  
**差异测试：** 同输入多实现；失败则回流规格。  
**Expect：** 刻意可读的轨迹嵌入测试；无结构 dump 无价值。  
**DST：** 控制时间/调度/随机/故障；种子可重放。库级优先；全系统按风险。  
**变异测试：** 抽检关键区，防止假绿。

---

## 5. 流程与门禁

1. 从验收与契约列出性质/场景 ID  
2. 按风险分配层级与手段  
3. Agent 实现测试并进入验证闭环  
4. 填写性质覆盖表（已查 / 未覆盖）  
5. 关键路径评估独立性（防实现-测试共错）  
6. 接入 CI；失败可定位到性质 ID  

### 质量门禁

- [ ] 主验收有自动测试且映射性质 ID
- [ ] 关键失败路径有覆盖
- [ ] 关键性质有 PBT 或等价可执行规格
- [ ] 每条合并相关绿灯附带「未覆盖」说明（可汇总表）
- [ ] 高风险输入面有 fuzz 或等价手段（如适用）
- [ ] 关键协作有 Expect 或库级仿真
- [ ] 分布式/恢复路径已评估 DST 或显式接受风险
- [ ] CI 可执行；证据可取回
- [ ] （建议）关键区差异或变异抽检

---

## 6. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 闭环迭代直至检查过关；轨迹与种子可机器消费 | 自写自测会共盲点；不知未声明性质 |
| HITL | 用未覆盖表与轨迹 diff 分配注意力 | 无法审完所有生成用例；编排过载时质量下降 |

---

## 7. 要点

- 测试是正确性层的行为网，不是「有单测即可」
- 性质级证据与验证章同一套字段
- 可复现性（种子、DST、Expect）优先于偶发重跑
