# AI-Native SDLC · 测试与质量保障

用户路径决定做完没有，单元测试只决定回归快不快。

## 1. 范围与定位

与第 4 章验证共同构成**正确性层**；并承担设计/实现中**已承诺**的性能与资源预算核对。

| 项 | 约定 |
|----|------|
| 主问题 | 场景下行为是否符合验收；约定负载下是否满足预算 |
| 与验证 | 验证章定义用户路径上的运行时证据，并覆盖更强性质；本章覆盖场景、回归、性能与变异 |
| 瓶颈关系 | Agent 自跑检查；HITL 审「绿了什么 / 未覆盖什么」 |

### 原则

- 验收与**已承诺预算**驱动
- 可执行规格优先；失败可解释；证据可重放
- 正确性门禁与性能门禁可分开，但都用性质级字段
- 并发优先可复现（DST）；性能数字须带环境标签

---

## 2. 性质级证据

| 字段 | 含义 |
|------|------|
| 性质 / 验收 / 预算 ID | 对应功能性质或 PERF/资源目标 |
| 手段 | 单元 / PBT / fuzz / Expect / DST / 负载 / 浸泡 / 基准 等 |
| 结果 | 通过 / 失败 / 未跑 |
| **未覆盖** | 本检查不声称的行为或环境 |
| 证据指针 | 日志、报告、种子、指标导出路径 |

禁止「CI 全绿 = 全部性质与性能成立」。

---

## 3. 测试分层

| 层级 | 目标 |
|------|------|
| 单元 / 表驱动 | 局部逻辑 |
| Expect / 轨迹 | 可读行为 diff |
| PBT | 普遍性质 |
| Fuzz | 输入面健壮性 |
| 差异 / 变异 | 一致性与杀伤力 |
| 库级仿真 / DST | 可控时序与故障 |
| 集成 / e2e | 真实路径 |
| **基准 / 负载 / 压力 / 浸泡** | 核对性能与资源预算 |
| 复杂度度量 | 结构健康 |

### 单元测试与端到端

- 单元测试快、稳，适合纯函数和局部不变量。Agent 会把它写到自己理解的任务上，于是测试是绿的，用户路径是坏的。
- 端到端难骗：路径要么走通，要么走不通。失败最好是一张图，而不是一句超时。它慢、更脆，放在提交前，不要放进每一个小步。
- 门禁权重不同。用户路径决定「做完没有」；单元测试决定「局部回归快不快」。若只能先建一种完成定义，先建端到端。端到端的做法见验证章的运行时验证。
- 属性测试补没人写到的例子。差异测试补迁移有没有走样。二者都不替代端到端。

### 变异测试的耗时

变异测试问的是测试在不在睡觉，不是产品对不对。Agent 连测试一起写时，用它抓住两边一起放水。能写成性质或证明的，不要用变异去近似。

全量变异在大仓库里是小时级，不能进内环。只做这三件事：

1. 只变异这次改动覆盖到的代码。
2. 先跑条件边界、返回值和逻辑连接。跳过编译失败和语义等价的变异体。
3. 内环不跑。提交前对改动模块限时，或限制变异体数量。夜间全量只留给关键模块。没跑完写成「未覆盖」：不得记成通过，也不得因为超时就当门禁失败。

变异分数不做默认硬门禁，除非模块小，并且预算事先写明。

## 4. 性能与资源测试

| 类型 | 用途 |
|------|------|
| 微基准 | 热路径回归（须控环境噪声） |
| 负载 | 目标并发/吞吐下是否达标 |
| 压力 | 过载退化是否符合背压设计 |
| 浸泡 | 泄漏、句柄、延迟漂移 |
| 资源约束 | 限内存/CPU/FD 下是否安全失败 |
| 客户端 | 启动、恢复、IPC、CPU/内存快照 |

### 规则

1. 只把**设计已承诺**的预算设为阻塞门禁；探索性压测可夜间跑。  
2. 报告须含环境标签（机型、OS、构建选项）；基线版本化。  
3. 性能通过**不得**解释为协议性质通过。  
4. 为冲分放松超时或 fail-closed → 门禁失败。  
5. 与极限故障组合时，优先断言「安全失败 + 可恢复」，再看是否仍满足降级预算。

---

## 5. 手段摘要（正确性）

属性测试、fuzz、差异、Expect、DST、变异：见既有约定；与验证章性质 ID 对齐。

---

## 6. 流程与门禁

1. 从验收、契约、**预算**列出 ID  
2. 按风险分配手段  
3. Agent 验证闭环（功能 + 约定基准）  
4. 填写覆盖表（已查 / 未覆盖）  
5. 关键路径防实现-测试共错  
6. 接入 CI；性能可用单独流水线  

### 质量门禁

- [ ] 主验收有自动测试且映射 ID
- [ ] 关键失败路径有覆盖
- [ ] 关键性质有 PBT 或等价
- [ ] **已承诺的性能/资源预算有对应检查或显式延期记录**
- [ ] 性能证据含环境与基线指针
- [ ] 合并相关绿灯可汇总未覆盖
- [ ] 高风险输入面 fuzz（如适用）
- [ ] 关键协作 Expect 或库级仿真
- [ ] 分布式/恢复已评估 DST 或接受风险
- [ ] CI/约定流水线可执行
- [ ] 实现-测试同源时有独立性措施或风险记录
- [ ] **「做完」由用户路径的端到端证据定义；单元测试不单独充当完成定义**
- [ ] **若跑变异：只覆盖本次改动，有时间或数量预算；未跑完记为未覆盖**

---

## 7. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 功能与基准闭环 | 环境噪声；自测共盲点 |
| HITL | 用未覆盖与基线漂移分配注意力 | 无法审尽所有曲线 |

---

## 8. 要点

- 正确性与已承诺性能都是可门禁证据
- 性能数字无环境标签则证据不完整
- 端到端定义做完没有；变异测试只衡量测试是否在睡觉，且不进内环
