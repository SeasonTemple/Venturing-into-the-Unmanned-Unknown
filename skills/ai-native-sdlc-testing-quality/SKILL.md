# AI-Native SDLC · 测试与质量保障

## 1. 本章定位

测试关注「在具体场景下是否表现正确」，与验证互补。

### 基本原则

- 验收驱动
- 分层建设
- 风险优先
- 可自动化
- 可维护
- 结果可解释

---

## 2. 测试分层

| 层级 | 目标 | 特点 |
|------|------|------|
| 单元测试 | 局部逻辑正确 | 快、定位准 |
| 属性测试 | 普遍性质成立 | 规则生成多组输入 |
| 集成测试 | 模块协作正确 | 发现边界错误 |
| 端到端测试 | 用户路径正确 | 接近真实，成本较高 |
| 专项场景 | 风险路径可靠 | 并发、故障、超时、权限 |

---

## 3. 规范执行流程

1. 从验收标准生成主路径测试
2. 按模块补齐单元测试
3. 对通用性质增加属性测试
4. 构建集成测试
5. 补齐端到端与风险场景
6. 纳入 CI 与质量门禁
7. 维护测试资产

### 质量门禁

- [ ] 主要验收标准均有对应自动测试
- [ ] 关键模块有单元级保护
- [ ] 关键接口有集成级检查
- [ ] 高风险场景有专门用例
- [ ] 测试可在 CI 自动执行
- [ ] 失败信息能指向行为或契约

---

## 4. 简洁实例

写锁验收 → 单元测互斥 → 集成测无效会话 → 端到端测 A 持锁 B 被拒 → 超时回收场景 → CI 固化。

---

## 5. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 只测成功路径 | 成功与关键失败成对 |
| 全靠端到端 | 分层测试 |
| 测试实现细节 | 优先测行为与契约 |
| 测试与需求脱节 | 从验收标准映射用例 |

---

## 6. Agent 执行要点

1. 先写能判定验收标准的测试
2. 失败信息要指向「哪个行为错了」
3. 高风险路径优先补场景
4. 意图或契约变更后同步更新测试

---

## 7. 本章要点

- 测试是最广泛的行为质量网
- 以验收标准为源头，按风险分层建设
- 与验证分工：测试管场景行为，验证管更强性质
