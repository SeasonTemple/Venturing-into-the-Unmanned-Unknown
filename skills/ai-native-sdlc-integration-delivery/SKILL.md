# AI-Native SDLC · 集成与交付

## 1. 本章定位

把「局部正确的变更」变成「可安全进入目标环境的系统版本」。

### 基本原则

- 门禁先于发布
- 小批量集成（**尤其约束 Agent 大 PR**）
- 环境一致（构建一次，多环境复用）
- 可回滚、可审计
- 自动化默认；失败可止损

---

## 2. 门禁分层

| 门禁层级 | 检查内容 | 失败策略 |
|----------|----------|----------|
| 提交级 | 格式、静态检查、快速测试、必要类型/契约检查 | 阻断合并 |
| 合并级 | 完整测试、属性/关键路径、构建；按风险的验证或仿真种子回归 | 阻断进入主线 |
| 发布级 | 冒烟、配置与迁移、制品校验 | 阻断上线 |
| 运行级 | 健康检查、关键指标 | 触发回滚或止损 |

门禁应与《测试》《验证》章对齐：能自动化的可执行规格、Expect 轨迹、DST 种子失败必须能阻断合入或发布。

---

## 3. Agent 变更的合入纪律

- 默认拆成可审阅的变更栈，避免「一句提示生成巨大不可审 diff」
- 合入说明应能指向：意图/契约、测试或轨迹证据、风险与回滚
- 禁止以删除测试、空洞断言、过度 mock 换取绿灯
- 自动化气味扫描可辅助；发布裁决仍依赖门禁结果与人类对变更意图的确认

---

## 4. 规范执行流程

1. 准备集成（范围、契约、验证/测试证据、迁移影响、回滚点）
2. 小批量合并
3. 执行集成级检查（含关键回归与可重放失败用例）
4. 发布前审查
5. 分阶段发布
6. 完成或回滚；异常优先止损

### 质量门禁

- [ ] 集成后的自动检查全部通过
- [ ] 关键路径的属性/场景/仿真回归未无故跳过
- [ ] 制品已版本化并可追溯
- [ ] 发布前检查完成
- [ ] 有明确回滚路径
- [ ] 发布过程可审计
- [ ] 关键观察指标已接入

---

## 5. 简洁实例

锁超时逻辑升级：小批量合并 → 跑相关测试、属性与（若有）仿真种子回归 → 预发 → 小流量 → 观察失败率与等待时长 → 平稳后全量；异常立即停量并回滚。

---

## 6. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 大爆炸合并 | 小批量集成 |
| Agent 一次性巨型 PR | 拆栈 + 证据化说明 |
| 本地通过就上线 | 集成后再门禁 |
| 无回滚发布 | 先定义退路 |
| 环境配置漂移 | 制品与配置受控 |
| 人工神秘步骤 | 脚本化与记录化 |
| 跳过失败的可重放用例「以后再说」 | 阻断或显式风险签核 |

---

## 7. Agent 执行要点

1. 不跳过门禁直接交付
2. 默认假设会失败，先准备回滚
3. 发现异常优先止损
4. 每次交付留下可追溯证据（含测试/种子/轨迹引用）
5. 变更粒度以可审、可回滚为准

---

## 8. 本章要点

- 集成解决「合在一起是否仍正确」
- 交付解决「如何可控地进入环境」
- 门禁、分阶段发布与回滚是高频与 Agent 加速变更下的必要纪律
