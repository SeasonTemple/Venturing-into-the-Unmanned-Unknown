# AI-Native SDLC · 集成与交付

## 1. 范围

将附带正确性与**约定性能证据**的变更变为可进入目标环境的版本。

**硬约束：** 无性质级证据不得发布；**已承诺**的 PERF/资源 ID 未通过或未签核延期不得发布。

---

## 2. 门禁分层

| 级 | 内容 | 失败 |
|----|------|------|
| 提交 | 格式、静态、快速测试 | 阻断合并 |
| 合并 | 完整测试、关键验证、构建；性质覆盖表 | 阻断主线 |
| 发布 | 冒烟、迁移、**承诺的性能/资源核对**、制品 | 阻断上线 |
| 运行 | 健康与关键预算指标 | 回滚/止损 |

合并/发布说明须能回答：功能性质覆盖与未覆盖；承诺预算是否核对及环境标签。

---

## 3. Agent 合入纪律

- 小批量；可审栈
- 说明含：意图/契约指针、性质覆盖摘要、**预算结果或未承诺**、风险与回滚
- 禁止删测试、空断言、放宽超时换绿

---

## 4. 流程与门禁清单

1. 准备：范围、证据包、迁移、回滚  
2. 小批量合并  
3. 合并级检查 + 覆盖表  
4. 发布前审查（含承诺性能）  
5. 分阶段发布  
6. 完成或回滚  

- [ ] 自动检查通过
- [ ] 性质覆盖表齐全
- [ ] **已承诺性能/资源门禁通过或书面延期**
- [ ] 关键回归未无故跳过
- [ ] 制品可追溯；回滚可用
- [ ] 风险发布已经 HITL 或书面策略

---

## 5. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 晋级条件含预算 ID | 不决定商业上是否该发 |
| HITL | 审未覆盖与性能签核 | 编排过载时先加严自动门禁 |

---

## 6. 要点

- 交付把正确性与**已承诺表现**变成组织约束
- Agent 推进，系统否决，HITL 裁决残余风险
