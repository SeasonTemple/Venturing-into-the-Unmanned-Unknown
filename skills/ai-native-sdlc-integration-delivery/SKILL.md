# AI-Native SDLC · 集成与交付

## 1. 范围

将已实现且附带正确性证据的变更变为可进入目标环境的版本。

**硬约束：** 无性质级证据不得发布。Agent 推进准备，不得跳过门禁。

---

## 2. 门禁分层

| 级 | 内容 | 失败 |
|----|------|------|
| 提交 | 格式、静态、快速测试、必要类型/契约 | 阻断合并 |
| 合并 | 完整测试、关键验证、构建；性质覆盖表齐全 | 阻断主线 |
| 发布 | 冒烟、迁移、制品；必要时 HITL | 阻断上线 |
| 运行 | 健康与关键指标 | 回滚/止损 |

合并级**必须**能回答：本变更相关绿灯各覆盖哪些性质 ID，以及明确未覆盖项。

---

## 3. Agent 合入纪律

- 小批量；可审栈
- 说明含：意图/契约指针、性质覆盖摘要、风险与回滚
- 禁止删测试、空断言、过度 mock 换绿
- 实现与测试同源时，合并说明须指出独立性措施或残余风险

---

## 4. 流程与门禁清单

1. 准备：范围、证据包、迁移、回滚点  
2. 小批量合并  
3. 合并级检查 + 性质覆盖表  
4. 发布前审查  
5. 分阶段发布  
6. 完成或回滚  

- [ ] 自动检查通过
- [ ] 性质覆盖表存在且无空「未覆盖」字段（可写「无额外已知缺口」）
- [ ] 关键回归未无故跳过
- [ ] 制品可追溯；回滚可用
- [ ] 风险发布已经 HITL 或书面策略

---

## 5. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 明确晋级条件；失败可自动停 | 不能解释「业务是否该发」 |
| HITL | 只审风险与未覆盖 | 编排税过高时应减并发、加严自动门禁 |

---

## 6. 要点

- 交付把正确性层的证据变成组织约束
- **Agent 推进，系统否决，HITL 裁决残余风险**
