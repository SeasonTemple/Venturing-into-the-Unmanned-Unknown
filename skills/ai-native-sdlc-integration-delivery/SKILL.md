# AI-Native SDLC · 集成与交付

## 1. 本章定位

把「局部正确的变更」变成「可安全进入目标环境的系统版本」。

### 基本原则

- 门禁先于发布
- 小批量集成
- 环境一致（构建一次，多环境复用）
- 可回滚
- 可审计
- 自动化默认

---

## 2. 门禁分层

| 门禁层级 | 检查内容 | 失败策略 |
|----------|----------|----------|
| 提交级 | 格式、静态检查、快速测试 | 阻断合并 |
| 合并级 | 完整测试、关键验证、构建 | 阻断进入主线 |
| 发布级 | 冒烟、配置与迁移、制品校验 | 阻断上线 |
| 运行级 | 健康检查、关键指标 | 触发回滚或止损 |

---

## 3. 规范执行流程

1. 准备集成（范围、契约、验证/测试证据、迁移影响）
2. 小批量合并
3. 执行集成级检查
4. 发布前审查
5. 分阶段发布
6. 完成或回滚

### 质量门禁

- [ ] 集成后的自动检查全部通过
- [ ] 制品已版本化并可追溯
- [ ] 发布前检查完成
- [ ] 有明确回滚路径
- [ ] 发布过程可审计
- [ ] 关键观察指标已接入

---

## 4. 简洁实例

锁超时逻辑升级：小批量合并 → 跑相关测试与验证回归 → 预发 → 小流量 → 观察失败率与等待时长 → 平稳后全量；异常立即停量并回滚。

---

## 5. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 大爆炸合并 | 小批量集成 |
| 本地通过就上线 | 集成后再门禁 |
| 无回滚发布 | 先定义退路 |
| 环境配置漂移 | 制品与配置受控 |
| 人工神秘步骤 | 脚本化与记录化 |

---

## 6. Agent 执行要点

1. 不跳过门禁直接交付
2. 默认假设会失败，先准备回滚
3. 发现异常优先止损
4. 每次交付留下可追溯证据

---

## 7. 本章要点

- 集成解决「合在一起是否仍正确」
- 交付解决「如何可控地进入环境」
- 门禁、分阶段发布与回滚是高频变更下的必要纪律
