# AI-Native SDLC · 集成与交付

## 1. 本章定位

把「局部正确的变更」变成「可安全进入目标环境的系统版本」。

**系统门禁是默认否决权**；Agent 推进集成与发布准备，但不得跳过门禁。HITL 在发布风险、例外放行与合规上提供权威较高的裁决。

### 基本原则

- 门禁先于发布（系统保证）
- 小批量集成（约束 Agent 大 PR，便于 HITL 与回滚）
- 环境一致；可回滚、可审计
- 自动化默认；失败可止损

---

## 2. 门禁分层

| 门禁层级 | 检查内容 | 失败策略 |
|----------|----------|----------|
| 提交级 | 格式、静态检查、快速测试、必要类型/契约 | 阻断合并 |
| 合并级 | 完整测试、属性/关键路径、构建；按风险的验证或仿真种子 | 阻断进入主线 |
| 发布级 | 冒烟、配置与迁移、制品校验；必要时 HITL 确认 | 阻断上线 |
| 运行级 | 健康检查、关键指标 | 回滚或止损 |

与《测试》《验证》对齐：可执行规格、Expect、DST 种子失败应能阻断合入或发布。

---

## 3. Agent 合入纪律

- 拆成可审变更栈，避免不可审巨型 diff
- 说明指向：意图/契约、测试或轨迹证据、风险与回滚
- 禁止删测试、空洞断言、过度 mock 换绿灯
- 气味扫描是系统辅助；**放行** = 门禁通过 +（按风险）HITL 确认意图与例外

---

## 4. 规范执行流程

1. 准备集成（范围、证据、迁移、回滚点）
2. 小批量合并
3. 集成级检查
4. 发布前审查（系统 + 必要 HITL）
5. 分阶段发布
6. 完成或回滚；异常优先止损

### 质量门禁

- [ ] 自动检查通过
- [ ] 关键回归未无故跳过
- [ ] 制品可追溯；回滚路径可用
- [ ] 发布可审计；关键观察已接入
- [ ] 风险发布已经 HITL 或明确签核策略

---

## 5. 简洁实例

锁超时升级：小批量合并 → 测试/属性/仿真种子 → 预发 → 小流量 → 观察 → 全量；异常停量回滚。

---

## 6. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 大爆炸合并 | 小批量 |
| Agent 巨型 PR | 拆栈 + 证据 |
| 本地通过就上线 | 集成门禁后 |
| 无回滚 | 先定退路 |
| 跳过可重放失败用例 | 阻断或显式风险签核 |
| 无人门禁、只靠口头同意 | 系统保证与 HITL 分层 |

---

## 7. Agent 执行要点

1. 推进交付准备，但**不跳过门禁**
2. 默认会失败，先准备回滚
3. 异常优先止损
4. 留下可追溯证据
5. 粒度以可审、可回滚为准

---

## 8. 本章要点

- 集成：合在一起是否仍正确（系统检查为主）
- 交付：可控进入环境（门禁 + 分阶段 + 回滚）
- **Agent 推进，系统否决，HITL 在风险点裁决**
