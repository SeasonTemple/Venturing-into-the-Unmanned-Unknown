# AI-Native SDLC · 意图与需求

## 1. 本章定位

### 1.1 所属环节

意图与需求是 AI-Native SDLC 的起点，位于所有设计、实现与验证之前。

**「意图澄清」→ 设计 → 实现 → 验证 → 交付 → 演进**

### 1.2 地位与意义

在 AI-Native 模式下，生成成本极低，错误意图的成本被放大。
若意图模糊，Agent 会高速产出错误实现，并沿错误方向自动化扩散。

本章解决：

- 要做什么（目标）
- 不做什么（边界）
- 怎样算完成（验收）
- 如何减少误解（表达纪律）

### 1.3 核心价值

- 降低返工
- 为验证提供可追溯属性来源
- 为多 Agent 提供统一任务理解
- 使人的裁决集中在目标，而不是细节修补

---

## 2. 理论框架

### 2.1 意图层的三个产物

| 产物 | 作用 |
|------|------|
| 目标陈述 | 说明系统要达成的结果 |
| 约束与边界 | 说明范围、非目标、限制条件 |
| 验收标准 | 说明如何判定完成 |

三者必须可被观察、可被判定，避免空泛描述。

### 2.2 表达纪律

推荐使用受控技术写作风格（如 ASD-STE100 的 80% 实用模式）：

- 短句
- 主动语态
- 一词一义
- 一句一意
- 明确主体与动作

### 2.3 从意图到验证的映射

| 意图要素 | 后续用途 |
|----------|----------|
| 必须永远成立的规则 | Safety 属性 |
| 最终必须发生的结果 | Liveness 属性 |
| 边界与异常 | 测试场景与失败路径 |
| 接口约定 | 契约与模块验证 |

## 4. 规范执行流程

1. **收集原始意图** — 记录原始描述，不急于设计
2. **澄清与消歧** — 明确主体、成功行为、失败行为、非目标、限制
3. **结构化表达** — 输出目标、约束、验收标准
4. **识别风险线索** — 并发、状态机、权限、边界、失败恢复
5. **确认与冻结** — 形成当前迭代意图基线，变更需显式记录

### 质量门禁

- [ ] 目标可观察
- [ ] 边界清晰（含非目标）
- [ ] 验收标准可判定
- [ ] 关键歧义已消除
- [ ] 表达简短、主动、无堆砌
- [ ] 已标出高风险线索

## 5. 简洁实例

**原始：** “做一个文档锁定功能，别让人同时改。”

**澄清后：**

- 目标：同一文档在同一时刻最多一个编辑者可以写入。
- 约束：允许多个用户同时打开只读视图；网络断开时，持锁方在超时后释放锁。
- 验收：
  1. 第二位用户请求写锁时收到明确拒绝或等待状态。
  2. 锁持有者释放或超时后，其他用户可以获得写锁。
  3. 只读用户始终可以打开文档。
- 风险线索：并发获取锁、超时释放、重复进入。

---

## 6. Agent 执行要点

1. 先澄清，后生成方案或代码
2. 把模糊词逼成可判定语句
3. 强制区分：目标 / 非目标 / 验收
4. 为验证预留属性线索
5. 保持短句与主动语态

---

## 7. 本章要点

- 意图层决定后续一切方向
- 清晰表达是 AI-Native 的基础设施
- 验收标准必须可判定
- 需求要为验证提供可追溯输入
