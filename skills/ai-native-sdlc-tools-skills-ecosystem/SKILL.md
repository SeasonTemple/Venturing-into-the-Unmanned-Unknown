# AI-Native SDLC · 工具与技能生态

## 1. 本章定位

横切能力章：支撑全书所有环节可执行、可维护、可审计。

### 基本原则

- 任务驱动选型，不追求堆满
- 先通用、后专用
- 有 CLI / 可脚本化优先
- 技能说明必须含触发条件与边界
- 权限最小化
- 变更可追溯

---

## 2. 工具分层

| 层级 | 类型 | 作用 |
|------|------|------|
| L1 | Skill / 规则 | 表达、流程、质量纪律 |
| L2 | CLI / SDK | 构建、测试、检查、部署 |
| L3 | 验证工具 | 模型检查 / 有界检查 / 契约 |
| L4 | MCP / Plugin | 连接外部系统与专业能力 |
| L5 | CI / 自动化 | 强制执行路径 |

---

## 3. 最小工具集

| 环节 | 最小需要 |
|------|----------|
| 意图 | 低歧义表达规范 |
| 设计 | 边界/契约模板 + 决策记录 |
| 实现 | 语言工具链 + lint/format |
| 验证 | 按风险至少一种强检查能力 |
| 测试 | 自动测试框架 + CI |
| 交付 | 构建、发布、回滚脚本 |
| 演进 | 日志/指标/告警 + 回归入口 |

### 安装示例

```bash
npx skills add danyuchn/asd-ste100-skill
npx skills add younes-io/agent-skills --skill tla-check
npx skills add younes-io/agent-skills --skill tla-proof
```

---

## 4. 规范执行流程

1. 盘点任务链路
2. 补齐最小工具集
3. 技能化稳定流程
4. 接入 CI 与统一调用面
5. 真实变更试运行并裁剪
6. 版本化维护

### 质量门禁

- [ ] 每个关键环节至少有一种可自动执行手段
- [ ] 核心 Skill 可被发现并正确触发
- [ ] CI 能调用同一检查路径
- [ ] 权限最小化已落实
- [ ] 无大量长期不用的冗余技能

---

## 5. Agent 执行要点

1. 先看任务属于哪个环节，再选工具
2. 同一目的只保留一个主技能
3. 工具失败时输出可解释原因
4. 禁止无限扩装

---

## 6. 本章要点

- 以环节完成标准反推工具
- Skill 负责规范与触发，CLI/MCP 负责能力，CI 负责强制
- 最小、稳定、可审计，优于大而全
