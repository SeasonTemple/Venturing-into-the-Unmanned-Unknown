# AI-Native SDLC · 验证（Verification）

## 1. 范围与定位

本章属**正确性层**（与第 5 章测试共同回答「如何知道对不对」）。

**生命周期位置：** 意图 → 设计 → 实现 → **验证** → 测试衔接 → 集成交付 → 演进

| 项 | 约定 |
|----|------|
| 主问题 | 在规格与假设下，关键性质是否成立或可否证伪 |
| 与测试 | 测试覆盖场景与回归；本章覆盖更强/设计层/局部实现性质 |
| 瓶颈关系 | 生成廉价后，无独立检查则项目无法证明可交付 |

### 原则

- 风险驱动；分层保证
- 可执行规格优先
- 按语言成熟度选工具
- 结果可重复、可解释
- 默认不上重型交互式定理证明（仅强正确性内核）
- 接受规格无法穷尽每行实现

---

## 2. 性质级证据（门禁字段）

每条通过的检查**必须**可填写：

| 字段 | 含义 |
|------|------|
| 性质 ID / 陈述 | 检查的是哪条 Safety/Liveness/契约/不变量 |
| 手段 | 模型检查 / BMC / 证明器 / 静态分析等 |
| 结果 | 通过 / 反例 / 有界内通过 |
| **未覆盖** | 本检查**不**声称的内容（明确写出） |
| 证据指针 | 日志、命令、报告路径或可重放脚本 |

禁止仅用「验证通过」作为晋级理由。绿灯只证明已声明的性质。

---

## 3. 形式化验证

用数学/逻辑方法检查模型或实现是否满足形式化规格中的性质。产出为反例或通过/证明类结论，而非单组用例。

| 手段 | 含义 | 代表方向 |
|------|------|----------|
| 模型检查 | 状态空间搜索违反性质的路径 | TLA+/TLC、PlusCal、Alloy、Spin |
| 有界模型检查 | 有限边界内检查 | CBMC、Kani、ESBMC |
| 契约 / 演绎验证 | requires/ensures/invariant + 证明器 | Verus、Creusot、Frama-C、SPARK、Gobra |
| 交互式定理证明 | 人工引导证明 | Lean、Coq/Rocq、Isabelle |

默认优先级：可执行规格 → 设计层模型检查 → 实现层契约/BMC（按语言）→ 测试章补场景。

### 语言与成熟度（摘要）

| 语言 | 契约/证明 | BMC/安全 | 建议 |
|------|-----------|----------|------|
| Rust | Verus、Creusot、Prusti | Kani | 关键模块可积极 |
| C/C++ | Frama-C | CBMC、ESBMC | 安全关键成熟 |
| Ada | SPARK | — | 高保证领域 |
| Go | Gobra | — | 研究原型；仅极高价值模块 |
| 其他 | 视生态 | 静态分析/BMC | 无证明器则规格+测试为主 |

---

## 4. 分层模型

| 层 | 目标 | 手段 |
|----|------|------|
| L0 | 意图可判定 | 见意图章 |
| L1 | 设计协议/状态机 | 模型检查 |
| L2 | 实现局部正确与安全 | 契约、BMC、静态分析 |
| L3 | 行为符合性 | 第 5 章测试 |
| L4 | 持续保证 | CI |
| L5 | 可审计 | 反例解释、性质覆盖表 |

---

## 5. 规格歧义

歧义与 Agent 冲突为常态。策略：规格分层；可执行优先；冲突反哺；差异测试；非关键细节不微管理。

---

## 6. 流程与门禁

1. 确认意图中的属性与已知未知  
2. 定义可执行性质  
3. L1 高风险设计检查  
4. L2 按语言选型实现检查  
5. 将性质覆盖表交给测试章与交付门禁  
6. 反例关闭或回流规格  

### 质量门禁

- [ ] 关键性质有 ID 与陈述（可执行优先）
- [ ] 每条通过检查填写「已查性质」与「未覆盖」
- [ ] 高风险设计检查已完成或显式签核跳过
- [ ] 实现层检查按语言成熟度选型并完成
- [ ] 证据可重放（命令/报告/脚本）
- [ ] 反例已关闭或已建回流项

---

## 7. 对 Agent / 对 HITL

| 受众 | 帮助 | 局限 |
|------|------|------|
| Agent | 获得可跑的检查闭环；失败可自动迭代 | 不选择业务目标；与测试同源时可能共错；工具不成熟时不可硬闯 |
| HITL | 聚焦未覆盖性质与反例；不必假装读完所有证明 | 带宽有限；不能把「证明器绿了」当成业务正确 |

---

## 8. 要点

- 验证与测试同属正确性层；本章偏性质与更强保证
- 性质级证据是门禁单位
- 形式化按风险与语言成熟度启用，不是装饰
