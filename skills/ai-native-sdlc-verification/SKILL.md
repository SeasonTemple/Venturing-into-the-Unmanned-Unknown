# AI-Native SDLC · 验证（Verification）

## 1. 本章定位

验证是 AI-Native SDLC 中的核心质量环节：

**意图澄清 → 设计 → 实现 →「验证」→ 集成与交付 → 持续演进**

### 基本原则

- 风险驱动，而非全面铺开
- 分层保证，而非同等强度
- 可自动化，可被 Agent 调用
- 结果可解释、可追溯
- 默认不启用重型定理证明（Lean/Coq 等仅用于强正确性场景）

---

## 2. 分层验证模型

| 层级 | 名称 | 目标 | 主要手段 |
|------|------|------|----------|
| L0 | 意图与表达层 | 需求清晰、无歧义 | 受控技术写作 |
| L1 | 设计正确性层 | 协议 / 状态机 / 并发行为正确 | 模型检查（TLA+ 等） |
| L2 | 实现安全与局部正确性层 | 内存安全、溢出、断言、契约 | 有界模型检查、契约验证、静态分析 |
| L3 | 行为符合性层 | 功能与场景符合预期 | 测试 |
| L4 | 持续保证层 | 变更不破坏已有保证 | CI 自动化 |
| L5 | 可理解性与审计层 | 结果可解释、可追溯 | 清晰文档 + 反例解释 |

---

## 3. 工具准备

### 按问题类型

| 问题类型 | 推荐方向 | 代表工具 |
|----------|----------|----------|
| 并发、分布式、状态机 | 模型检查 | TLA+ + TLC |
| 内存安全、溢出、UB | 有界模型检查 | Kani、ESBMC / CBMC |
| 函数契约与不变量 | 契约验证 | Verus、Creusot、Frama-C |
| 功能与场景 | 测试 | 测试框架 + Property-based |
| 表达清晰 | 受控写作 | ASD-STE100 80% |
| 算法强正确性（可选） | 定理证明 | Lean、Coq |

### 安装示例

```bash
npx skills add danyuchn/asd-ste100-skill
npx skills add younes-io/agent-skills --skill tla-check
npx skills add younes-io/agent-skills --skill tla-proof
```

## 4. 规范执行流程

1. 意图澄清
2. 属性定义（Safety / Liveness / 边界 / 契约）
3. 设计验证（高风险路径建模与检查）
4. 实现验证（有界检查或契约）
5. 行为验证（测试场景）
6. 持续回归（CI）
7. 解释与沉淀

### 质量门禁

- [ ] 相关属性已明确记录
- [ ] 高风险设计已验证通过
- [ ] 实现层关键检查通过
- [ ] 自动化测试与 CI 通过
- [ ] 失败与反例已解释并关闭
- [ ] 说明表达清晰、可追溯

---

## 5. 简洁实例

资源写锁：定义互斥与活性属性 → TLA+ 检查协议 → 关键路径有界检查 → 并发场景测试 → CI 回归。

---

## 6. Agent 执行要点

1. 先澄清意图与属性，再选工具
2. 高风险路径优先模型检查
3. 实现层按语言选有界检查或契约
4. 结果必须可解释
5. 默认不引入 Lean/Coq

---

## 7. 本章要点

- 验证是质量中枢，不是事后补充
- 分层、风险驱动，而非全面定理证明
- 固定流程 + 自动化门禁 + 可解释结果
