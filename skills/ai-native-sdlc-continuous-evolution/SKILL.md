# AI-Native SDLC · 持续演进

## 1. 本章定位

**交付 →「持续演进」→（回到意图或设计）**

把运行中的信号，转化成下一轮受控改进。

### 基本原则

- 信号驱动
- 分层回流
- 先止损，后根治
- 资产同步
- 小步演进
- 可追溯

---

## 2. 问题回流模型

| 问题类型 | 回流层级 |
|----------|----------|
| 目标理解错误 | 意图层 |
| 结构或契约错误 | 设计层 |
| 协议/并发性质被打破 | 验证层 |
| 局部逻辑错误 | 实现层 |
| 场景覆盖不足 | 测试层 |
| 发布或配置问题 | 交付层 |

---

## 3. 规范执行流程

1. 采集信号
2. 止损
3. 定位层级
4. 受控修改
5. 补齐回归
6. 沉淀知识
7. 恢复常态观察

### 质量门禁

- [ ] 问题已止损或影响可控
- [ ] 根因层级判断明确
- [ ] 修复已完成并经过相应检查
- [ ] 回归保护已补齐
- [ ] 知识记录已更新
- [ ] 相关资产与行为保持一致

---

## 4. 简洁实例

线上偶发双写者 → 回滚止损 → 判定为协议并发缺陷 → 补模型检查与场景测试 → 修复实现 → 复盘落地为固定回归项。

---

## 5. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 只修症状 | 定位层级并补回归 |
| 线上直接大改 | 先止损，再受控变更 |
| 测试不更新 | 行为与资产同步演进 |
| 复盘不落地 | 结论变成规则或检查 |

---

## 6. Agent 执行要点

1. 先问证据，再改代码
2. 修 bug 必须附带防回归手段
3. 不把所有问题都当成实现层缺陷
4. 复盘写短事实

---

## 7. 本章要点

- 核心闭环：信号 → 止损 → 分层回流 → 受控修复 → 回归保护 → 知识沉淀
- 代码、验证、测试、文档必须一起演进
