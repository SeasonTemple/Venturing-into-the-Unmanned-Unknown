# AI-Native SDLC · 持续演进

## 1. 本章定位

**交付 →「持续演进」→（回到意图或设计）**

把运行中的信号转化成下一轮受控改进。**Agent 仍是修复与推进的生产主体**；人提供新的意图输入（若有）并在环内做 HITL 裁决；系统保证（回归、门禁、可重放种子）防止倒退。

稀缺的是 HITL 的注意力与理解，不是「由人重新成为编码主体」。工具与流程应放大杠杆，并保持仓对后续 Agent 可接续。

### 基本原则

- 信号驱动
- 分层回流
- 先止损，后根治
- 资产同步（代码、测试、验证、文档一起变）
- 小步演进、可追溯
- **可理解**：演进后系统仍对 HITL 可读，Agent 才可持续作为生产主体

---

## 2. 问题回流模型

| 问题类型 | 回流层级 |
|----------|----------|
| 目标理解错误 | 意图层 |
| 结构、契约或不变量错误 | 设计层 |
| 协议/并发性质被打破 | 验证层 |
| 局部逻辑错误 | 实现层 |
| 场景覆盖不足、不可复现失败 | 测试层（含 Expect/DST 种子） |
| 发布或配置问题 | 交付层 |
| 仓结构腐化、交叉复杂度上升 | 设计 + HITL 纪律 |

---

## 3. HITL 审阅与系统门禁

Agent 为主体之后，**理解型审阅与自动门禁都更重要**，而非更可省：

- Agent 善于把红灯变绿、完成功能目标，拙于主动保全简单性、可扩展性、少重复与少硬编码
- 脏仓会让后续 Agent 同样越改越碎
- 审阅目标：正确性、可理解性、实践传播、抑制交叉复杂度——**定调与裁决**，不是重新手写主体实现

**纪律建议：**

| 做法 | 说明 |
|------|------|
| 尊重 HITL 带宽 | 避免一句提示甩大 PR；拆成可理解变更栈 |
| 逻辑 diff + 行为轨迹 | 结合 Expect/仿真，让行为变化可见 |
| 区分两类检查 | 全仓气味扫描（系统/harness）≠ HITL 理解型 review |
| 持久化改进 | 会话易忘；结论写入 Skill、清单、门禁 |
| 警惕 reward hacking | 删测试、空断言、过度 mock 换绿灯 → 门禁与 HITL 打回 |

自动化审计可规模化扫气味；**价值与风险上的裁决仍可上升至 HITL**，与系统门禁并列。

---

## 4. 规范执行流程

1. 采集信号（线上、CI、仿真种子、HITL 意见）
2. 止损
3. 定位层级
4. Agent 受控修改（小步、可回滚）
5. 补齐回归（测试、属性、可重放种子、必要验证）
6. 沉淀知识（短事实、规则、Skill）
7. 恢复常态观察

### 质量门禁

- [ ] 问题已止损或影响可控
- [ ] 根因层级判断明确
- [ ] 修复已完成并经过系统检查
- [ ] 回归保护已补齐
- [ ] 知识记录已更新
- [ ] 资产与行为一致
- [ ] 风险变更已经 HITL 或等价门禁

---

## 5. 简洁实例

线上偶发双写者 → 回滚止损 → 判定协议并发缺陷 → 补模型检查与/或 DST 种子 → Agent 修复实现 → 复盘写入回归与设计不变量。

---

## 6. 常见反模式

| 反模式 | 正确做法 |
|--------|----------|
| 只修症状 | 定位层级并补回归 |
| 线上直接大改 | 先止损，再受控变更 |
| 测试不更新 | 行为与资产同步 |
| 复盘不落地 | 结论进规则或门禁 |
| 大而不可审的 Agent PR | 拆栈、附轨迹 |
| 删测试换绿灯 | 禁止 |
| 只用自动扫描冒充 HITL review | 扫描辅助；裁决按风险升级 |
| 倒退回「人重写主体、Agent 旁观」 | Agent 继续作为生产主体，受门禁与 HITL 约束 |

---

## 7. Agent 执行要点

1. 默认自己是生产主体：取证后修改并补回归
2. 不把所有问题都当成实现层缺陷
3. 复盘写短事实；持久化到 Skill/门禁
4. 变更粒度考虑 HITL 认知负荷
5. 门禁失败时停止推进并报告，不绕过

---

## 8. 本章要点

- 闭环：信号 → 止损 → 回流 → Agent 修复 → 回归 → 沉淀
- 代码、验证、测试、文档一起演进
- **Agent 主体 + HITL 定调 + 系统门禁**；自动化 harness 不替代理解型裁决
