# 迈向无人区：体验目标、参考研究与实现路径

日期：2026-10-26（Asia/Shanghai）

状态：研究与设计建议，尚未做产品实现；本文不代表美术方向已确认。

配套研究板：[experience-research-board.html](./experience-research-board.html)。

**同日方向更新**：用户已认可通过玩家职责、空间运行和产物流转表现人类主导与 AI 原生 SDLC 的差异。当前细化见[双时代微型探索体验](./mini-exploration-design.md)。本文保留背景调研；其中“仅探索与访问记录”的范围建议已扩展为一个可选微型工程任务。阅读继续完整开放，任务通过、访问记录与现实掌握程度分别表达。

## 1. 已确认的目标

依据本次用户的三项明确说明：

1. 不进入空间时，首页就是完整、正常可用的预览页。
2. 用户可以选择进入 **Three.js 实时三维空间**，在其中互动、发现章节、查看具体内容；内容如何呈现也是设计对象。
3. 整体围绕“迈入未知”：每个章／环节的发现帮助破除一部分未知；探索全部环节之后，未知仍然存在，包括 AI 输出的概率性以及其他未知。

由此得到的产品目标：**让读者在一个可进入的空间中，逐步理解如何面对未知、建立约束、取得证据并继续探索；普通首页和直接阅读仍然成立。**

需要设计的是一段完整旅程：

> 首页认识这本书 → 主动跨入未知 → 发现工作环节 → 查看章节与方法 → 将局部线索连成工程循环 → 带着对剩余未知的认识继续探索。

### 已确认与建议的边界

“可选进入、真实 Three.js、空间内可读章节、未知不会清零”已经确认。以下空间形态、镜头时长、光照变化、进度记录和阅读面形式是本轮建议，仍可调整。

追加确认：两种 SDLC 的区别应在操作职责与世界运行中显著可见，恢复局部秩序可以作为探索任务。场景任务与具体规则仍是待评审的设计细化。

## 2. 现状为什么容易反复

本次实际读取了首页、场景模块、内容同步脚本、章节配置、设计主提示词，以及 `frontier-live`、`frontier-finish` 等候选说明；查看了最新候选的已有完整截图。

| 现状 | 对体验的影响 | 处理建议 |
|---|---|---|
| 正式首页使用测绘石板，后续候选探索前哨、岩壁、断沿和脚影 | 同时维护了不同空间隐喻 | 先确定完整体验，再判断各资产是否有用 |
| 最新候选主要是静态构图，按钮直接链接普通章节页 | 还不能验证“进入后怎样互动、阅读和返回” | 把完整旅程作为下一阶段原型的最小单位 |
| 设计主提示词既写室内前哨，也写“没有房间、具体道具”的抽象测绘 | 继续照着旧条款实现会自相矛盾 | 保留历史，本轮先列冲突；方向确认后再统一主提示词 |
| 旧方案存在充能与放行语义，当前正式场景又冻结在既定构图 | 视觉状态与真实阅读行为没有稳定对应 | 为发现、查看、阅读进度分别定义准确含义 |
| 模型、雾、阴影已有多轮局部修整 | 局部完成度不能证明整段体验成立 | 复用可用的技术，暂停继续堆局部美术细节 |

可复用：Astro + Starlight 阅读能力、章节唯一数据源、真实场景海报的降级思路、按条件加载、资源释放经验、来源明确的岩石材质。需要重新验证：整体构图、镜头路径、内部布局和章节交互。

脚影、具体断沿和旧充能机制均不自动成为新方案的硬要求。已有实验价值在于提供经验和资产，并不意味着必须保留其造型。

## 3. 核心叙事：认知扩大，未知不归零

### 三种“未知”在空间中的不同表达

| 类型 | 含义 | 建议的空间表达 |
|---|---|---|
| 尚未发现的内容 | 本书已经提供、读者尚未查看的方法 | 局部雾后有可辨识的结构与入口；可直接用章节导航到达 |
| 在约束下可以检查的部分 | 当前意图、契约、实现与验证建立的局部秩序 | 轮廓、编号、测绘线和环节联系逐步稳定；明确“在什么边界内成立” |
| 仍然存在的开放问题 | 模型局限与输出随机性、需求和环境变化、遗漏的假设与风险 | 工作区域之外持续存在未完成的地形与测绘边界；全部章节看过后仍不消失 |

这三者不宜共用一个“黑暗百分比”。否则看完章节时只能选择全亮，或让用户误以为没有探索完成。

“破除未知”可以作为叙事，但方法的作用应更准确：澄清、约束、暴露、检验和管理不确定性。模型输出的随机性与未知并不完全等价：某种波动可以被认识和测量，具体一次输出依然可能出错。也有来自上下文、假设、需求和真实环境的未知。

### 进度的含义

- **未发现**：还没有在空间中定位这个入口。
- **已发现**：已经找到该环节，显示名称和联系。
- **已查看**：已经打开章节；这是访问记录。
- 可选的“标记已读”由读者明确操作，不用打开一次或滚到底自动判定掌握。

本轮建议仅做探索与访问记录。若以后加入练习和验证，它们应有自己的明确判据；不能用读过一章、充满一条光线替代“验证通过”。所有章节仍可直接访问，探索进度不阻断阅读。

### 探索全部环节后的结尾

画面完成的是一块**有限的、可继续运转的前哨**：各环节连通，演进与新意图相接，视野外仍有未知。不要全场点亮、倒计时清零或“100% 掌握”的结束画面。

建议文案：

> 你已发现全部环节。未知仍在边界之外。
>
> 带着意图、约束与证据，开始下一次探索。

“已探索 6 / 6 环节”只描述本书的导航范围。总图可提供“查看仍需面对的不确定性”和“从当前问题重新开始”两个后续动作。

## 5. 首屏：既是一页完整介绍，也是空间的入口

### 建议的第一眼

首屏让人站在“已知边界”旁：近处有少量可辨识的测绘基线／前哨结构，远处失去细节；能看见可以迈入的方向。避免把远处画成壮丽风景，也避免只剩大面积黑色而没有空间线索。

默认首页建议保留以下内容：

- 书名：**迈向无人区**。
- 定位：**AI 原生软件工程指南**。
- 一句话：**以 AI Agent 为一级生产力，人负责意图、约束与裁决。**
- 紧凑元信息：真实版本、许可、10 章；可下载制品在页面后续给出。
- 操作：**进入未知**、**直接阅读**；章节与制品正常向下展开。

“进入未知”的优先级略高，用来解释特色体验；“直接阅读”保持清晰，不藏在菜单里。安装长命令建议移到首屏之后的制品／使用部分，让首屏只承担认识与选择。此处是建议调整，未修改当前首页。

首次内容不等待 WebGL。首屏若展示实时场景，先用同机位的真实场景海报兜底，场景准备完再接替。若资源还没准备好，点击进入后保留首页画面，给出真实状态、取消和直接阅读；不要黑屏，不伪造百分比。

### 首屏要留下的疑问

用户应能理解“这是一份工程指南”，同时想知道“越过这条边界，会发现什么”。未知应来自可辨认线索之外的缺失，不靠把网站用途也一起藏起来。

## 6. 进入：从边界到可操作的前哨

### 推荐形态

建议先研究 **半开放的测绘前哨**：有有限的核心工作区，朝向外界的一侧开放或保留巨大观察面。已知与未知在同一坐标系中；章节探索形成内部秩序，外部未知始终可见。这个形态比十个互不相干的房间，更容易连贯进入，也更适合章节间来回比较。

另外两条可选方向：完全抽象的测绘场域容易保持克制，但容易再次变成石板陈列；完整封闭设施容易做出进入感，但未知可能只剩一幅窗景。推荐半开放前哨是基于当前主题与工作量的取舍，尚未锁定最终造型。

### 进入分镜（时长为待验证的设计目标）

| 时刻 | 空间／镜头 | 文字与交互 | 目的 |
|---|---|---|---|
| 点击之前 | 可见的边界、近处结构和进入方向 | 首页文字完整；两条路径清晰 | 自主选择进入 |
| 资源准备阶段，时长不固定 | 保留首页构图 | 真实加载状态、取消、直接阅读 | 等待有反馈，不把等待伪装成叙事 |
| 就绪后约 0–0.3 秒 | 沿既有视线起步 | 首页文案收起，退出方式保留 | 交代模式改变 |
| 约 0.3–1.5 秒 | 跨过测绘基线，短距离进入核心区 | 不要求复杂操作 | 首屏与内部是同一个地方 |
| 约 1.5–2 秒 | 停稳在总览机位 | 出现“选择一处线索”与环节导航 | 清楚落点和下一步 |

只做有意义的短路径，避免连续旋转、穿模、镜头翻滚。相机轨迹与朝向分别定义，转场时暂停浏览控制，落稳后恢复；一个状态只能有一个系统控制相机。

减少动态效果时直接到总览。再次进入提供跳过与快速返回，不强迫重复观看。退出恢复原首页滚动位置与触发按钮焦点。进入只是网页内模式变化，浏览器全屏可以以后作为独立选项。

## 7. 内部结构：六个工程环节，十章完整可达

不把“十章”机械做成十个等权、等距门洞。配置中已有六环骨架，可以让空间关系解释方法论；章名与数量仍严格来自唯一数据源。

| 空间角色／环节 | 对应章节 | 本环节主要面对的未知 | 发现后的空间变化建议 |
|---|---|---|---|
| 入口总览／意图台 | 第 0 章 导论 | 这是什么方法、人的位置在哪里 | 识别有限边界与环节总图 |
| 意图 | 第 1 章 | 要解决什么、怎样才算成功 | 目标与验收基准变得可见 |
| 设计 | 第 2 章 | 系统边界、接口、假设与代价 | 原本模糊的结构显露约束线 |
| 实现 | 第 4 章 | 方案落地时的依赖与行为 | 可见部件与连接开始组成系统 |
| 验证 | 第 3、5 章 | 哪些判断有证据、哪些仍待检查 | 显示检查范围与证据联系，而不是全场染绿 |
| 交付 | 第 6 章 | 真实环境中的集成、发布与回退 | 工作区与外部环境形成明确接口 |
| 演进 | 第 7 章 | 新反馈、漂移与变化 | 连接回新意图，边界延伸而不闭合世界 |
| 工具／参考区 | 第 8 章、附录 | 如何选工具、复用清单、定位术语与反模式 | 辅助资料在需要时可直接取用 |

六环覆盖七章，另有导论、工具生态、附录三章，共十章。主路径采用现有 `stages.ts` 的 1 → 2 → 4 → 3/5 → 6 → 7，不用目录章号硬排工程顺序。

### 空间交互的最小规则

1. 总览一眼看出可探索区域、当前位置和回到总览的方式。
2. 物件形态应有功能差异：基准、结构、装配、检查、交接、反馈；不要六个换了标题的相同方块。
3. 经过指向／键盘聚焦，给出局部轮廓或结构反馈；激活后到该区域的近景，而不是无提示瞬移。
4. 名称始终有可读 DOM 对应和键盘入口；物件遮挡、雾和镜头位置不能让章节永久不可达。
5. 环节允许任意选取。完成一圈帮助读者建立关系，不当作读正文的门票。

探索状态建议存本地、可清除、可重新开始；首次访问不做账号系统。变亮表达“这部分被定位、被阅读”，不宣称真实项目已经可信。

## 8. 内容的呈现也是空间设计

建议采用三层，而不让所有信息挤在模型表面。

| 层次 | 呈现 | 读者任务 |
|---|---|---|
| 空间线索 | 模型、形态、短标签、相互联系 | 发现这是什么环节、为什么在这里 |
| 环节近景 | 镜头靠近工作站；出现问题、核心方法、章内目录与具体章节选择 | 判断本章是否能帮助当前问题 |
| 展开阅读 | 该工作站的阅读面正向展开，Three.js 场景仍作为真实空间存在；文字保持舒适列宽 | 连续阅读、复制代码、查看图表、切换小节 |

对“验证”环节，近景先明确区分第 3 章和第 5 章，不在两个正文之间随机决定。对“工具／参考区”，能直接查找工具、术语或清单。

### 三种具体方案的取舍

- **全文作为三维贴图**：空间感强，但长文、小字号、搜索、选择与代码复制都困难。适合短编号、仪表与示意，暂不推荐承载整章正文。
- **始终贴在任意斜面上的 HTML 文字**：可复制，但透视、遮挡、输入坐标与清晰度需要额外处理。适合近景短说明；未验证前不把它定为全文唯一方案。
- **三维工作站过渡到正向阅读面**：镜头和实体负责空间连续性；落稳后，以与阅读面视觉对齐的 HTML/CSS 承载正文，长读时可进一步展开。推荐先验证这一方案。

这里的 HTML 是真实 Three.js 空间中的内容层，不代替空间建模。相机、工作站、物件反馈、前后景、章节入口仍由 Three.js 实时渲染。HTML 层与 Three.js 深度并不会自动互相遮挡，因此全文阅读时应锁定稳定机位，并明确内容层优先；不能假设 CSS3D 自动解决遮挡。

阅读时冻结无关镜头和环境运动，正文滚动不驱动相机。提供“返回此环节”“空间总览”“普通阅读页”的可见操作。空间模式内可以完成阅读，不强迫每次跳到普通章节页。

正文列宽沿用现有 65–75ch 约束，但中文的 `ch` 并不等于汉字数量，仍需实际视口检查。手机可让阅读面占据视口，并保留返回空间的位置，不把桌面三维机位简单裁切成竖屏。

### 内容资产的来源

仍由 `book.config.json` 和 `skills/*/SKILL.md` 驱动。当前 `sync.mjs` 已生成 Starlight 章节和首页数据，不能另写一套空间正文。建议构建时从同一内容管线输出空间阅读所需的章节片段和元信息，按章加载。

最先验证代码块、语义块、公式／图表、目录锚点、复制按钮在空间阅读面是否正常。此处需要实际验证，不能仅因普通章节页能显示就认为嵌入后也能显示。刷新、深链和浏览器返回也要保留所选章节与合理退路。

## 9. 建模与工程的实践路线

### 推荐资产管线

**空间草图与比例 → 灰盒体块 → 镜头与交互路径 → 一处工作站精做 → 复用模块扩展 → UV／烘焙 → GLB → Three.js 集成 → 实机量测。**

首屏美术和内部空间共享比例、材质语言、光源方向与可见地标。不能用一张外景参考图决定首屏，再另造一个无关系的内部世界。

| 对象 | 合适做法 | 原因 |
|---|---|---|
| 墙体、台面、基线、通道与环节布局 | 先用 Three.js 基础几何／模块做灰盒，再按需要替换 | 容易判断比例、通行、取景与命中区 |
| 近处主工作站与识别性部件 | Blender 或来源清晰的可编辑模型，保留建模源文件 | 轮廓、倒角与部件关系需要有意设计 |
| 重复机械构件 | 模块复用；适合者实例化／按材质合并 | 避免大量不可见螺栓拖累 draw call |
| 静态结构的间接光与环境遮蔽 | 在合适区域烘焙；与动态部件分离 | 有机会用较少实时光照取得可信层次 |
| 可动部件与状态反馈 | 独立 mesh／材质／动画，必要时少量实时光照 | 避免把应变化的状态烘死 |
| 远处未知 | 低细节轮廓、深度衰减与局部遮蔽；复杂体积雾后置 | 主题需要未知，不需要给不可见区域建满细节 |
| 标题与章节正文 | 可访问的文字层 | 可读、可选、可搜索、可复制 |

全烘焙场景中若还要表现移动投影，必须事先拆分静态间接光与动态直接光；不能把全光照颜色烘焙后再次直接叠加实时 PBR 光照。合并静态 mesh 之前先保存可交互部件和语义；几何合并后不能继续假定每个原部件还可独立操作。

### 最小模型契约（命名为建议）

- `static_*`：静态建筑与支撑体。
- `stage_intent` 等语义分组：六个环节。
- `hit_*`：简化拾取代理，不用装饰网格决定点击体验。
- `anchor_*`：标签、灯光或内容锚点。
- `camera_*`／`target_*`：已验证的镜头落点与视线目标。
- 动态部件保留独立节点，静态部分按材质批处理。

导出前检查单位、坐标约定、法线、变换、UV、材质槽、贴图色彩空间、包围盒和可见面的轮廓。压缩选择基于资产实际检查，不为小文件盲目增加解码器。

### 技术选择

延续 Astro + Starlight + 原生 Three.js。单个 renderer、单个受控动画循环，场景内使用 group 分区；章节视图不再另开 WebGL 上下文。进入镜头可由小型时间轴驱动；只有复杂程度确实需要时才增加动画依赖。

状态至少区分：首页、加载、进入、总览、环节近景、章节阅读、返回、降级。转场期间控制器不得同时写相机；加载可取消，过期异步结果不得再挂到已退出的页面。

加载顺序：首页 HTML／海报先到 → 进入意图后加载核心场景 → GLB／贴图解码与材质准备 → 用 `compileAsync` 等手段减少首见编译卡顿 → 核心场景就绪再播放进入 → 其他细节与按章正文延后。不能把模型网络下载完成当成可顺畅进入的证明。

场景静止时按需渲染；后台暂停；阅读时停掉无关动画；离开时释放事件、纹理、几何、渲染目标与控制器。上下文丢失回到有内容的降级界面，提供重试与直接阅读。

### 初始预算：待原型实测，不是已达到的成绩

| 项目 | 初始约束／验证目标 |
|---|---|
| 默认首页 | 文字与阅读链接不等待完整三维场景；不预先下载全部内部资产 |
| 核心进入资源 | 先以新增模型／贴图传输量约 3MB 以内为候选预算；Three.js、解码器和缓存情况另列，按实际网络验证 |
| 桌面／移动 DPR | 上限 2／1.5；低端可继续下降 |
| 场景复杂度 | 先沿用 ≤40 draw calls、<50k 三角面的保守起点；分别记录可见几何和包含阴影／后处理的每帧总开销 |
| 阴影 | 先限定一个实时投影光、1024 阴影贴图；其余用静态方案或普通补光 |
| 动画流畅度 | 声明设备与分辨率后测量；桌面先看 p95 帧间隔能否接近 16.7ms，移动以 33.3ms 为初始目标，同时报告明显卡顿 |
| 重复进入与退出 | 三次挂载／销毁后，无持续增加的资源和重复循环；记录可复用缓存与实际泄漏的区别 |

50k 面和 40 draw calls 是预算，不保证帧率。体积采样、透明覆盖、像素比、纹理内存、首次编译与浏览器合成都可能成为瓶颈。压缩后的文件大小也不等于 GPU 内存。

## 10. 真正动手前后的顺序与停点

### A. 当前研究阶段

产物为本文与配套研究板：目标、叙事、参考、镜头、布局、内容方案、建模管线与验收。未修改生产实现，未生成新美术候选，未部署。

### B. 下一阶段建议：一段完整灰盒旅程

只验证：首页入口 → 短镜头 → 三维总览 → 一个环节 → 一章真实内容 → 返回环节 → 返回首页；另用可重置的演示状态检查“全部环节已发现但未知仍存在”的结尾。

先做意图或验证中的一个工作站，其余用体块标记。灰盒需能判断真实空间关系，但不做最终岩石、鞋影、复杂雾和十章精模。默认首页、直接阅读与 Three.js 进入三者必须连通。

通过条件：初次使用者知道往哪里去，能找到并阅读一章，能退回原处；能理解局部认知与剩余未知的区别。如果做不到，调整路径、布局与交互，不进入精模阶段。

### C. 再做一处视觉样板

只精做同一工作站的首屏可见角度、进入落点、交互近景和阅读状态。必须同一套空间关系都成立；成功的单张海报不能替代四个状态的验证。

### D. 最后扩展全部章节

依据共享章节数据补齐六环与辅助入口，连接探索状态、按章加载、键盘与移动方案，再完成生产集成。每阶段有新证据才扩展，不继续无判据的版本堆叠。

## 11. 验收清单

### 体验与叙事

- [ ] 首屏 5 秒内能回答：这是什么、为何可信、怎样直接阅读／进入空间。

- [ ] 进入后的相机、透视、遮挡、物件反馈和导航都由真实 Three.js 场景承担。

- [ ] 至少能在空间模式内完整阅读一章并返回所处环节。
- [ ] 已探索状态不冒充掌握、工程验证或风险消除。
- [ ] 全部环节探索后，有限秩序与剩余未知同时可见，演进能指向新意图。

### 阅读与交互

- [ ] 章名与正文有 DOM 语义，键盘能找到与激活所有章节。
- [ ] 代码复制、公式／图表、语义块、小节目录和搜索行为经过验证。
- [ ] 正文滚动与相机控制分离；长读时无无关动态。
- [ ] 返回、浏览器后退、刷新与章节深链行为明确。
- [ ] 减少动态效果仍可进入静止三维总览并阅读；无 WebGL 时保留正常阅读。
- [ ] 模态层的焦点进入、Tab、Escape、焦点返回符合 WAI-ARIA 实践。
- [ ] 窄屏机位和阅读布局独立验证；不以裁图代替移动设计。

### 工程与视觉

- [ ] 记录资源传输、GPU 资源、每帧总绘制、实际帧间隔和首见卡顿。
- [ ] 连续三次进入／退出、缩放、后台恢复均无重复循环和持续资源增长。
- [ ] 图文最差背景下对比度实测，正文维持既有列宽要求。
- [ ] 美术阶段取得成功的真实参考截图，并与实现并排说明差距。
- [ ] 区分“文章已读／画面已看／交互已测／性能已测”，不混为完成。
