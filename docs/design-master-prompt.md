# 设计主提示词（Design Master Prompt）

本文件是本仓库**所有前端与视觉工作的唯一基准**。任何设计改动开始前先读它；与该文件冲突的实现一律视为缺陷。

## 当前体验方向更新（2026-10-26）

**2026-10-27 观测站异步加载与窄屏释放。** 用户要求继续优化，按 modern-web-guidance 核对后，复现天空解码阻塞记录入口、加载中跨断点后桌面入口无法恢复的问题。记录与镜头先就绪，环境动态独立加载；断点监听在异步工作前注册，过期任务取消，窄屏销毁桌面纹理、程序、缓冲与镜头监听，回桌面保留当前页核对进度和暂停选择。WebGL 恢复保留现场视图。画面、美术与交互内容沿用已认可版本，不恢复错误朝向行走；验证见 [加载与资源记录](./homepage-lifecycle-revision.md)。

**2026-10-27 首屏内场景与持续负载补正。** 用户指出控制区掉到画外、设施静止与久开卡顿。桌面改为完整视口场景，手记与控制区均留在画面内，同一原画用镜头推进连接工位、旧桩、风标；这不代表人物已能行走。屋顶暂按硬质风向标与上部转子处理，檐灯、墙面反光、设备采样灯均有对应动态，三张纹理与单次绘制不增加。默认30fps、1152×648，持续超预算才向下调档；静态图保持原生清晰度，不再以60fps作为默认目标。旧版2分钟未复现内存累积，新版用3分钟持续运行与独立交互检查核验；不能据此排除用户机器的GPU／温度问题。详见 [首屏修正与性能边界](./homepage-scene-revision.md)。

**2026-10-27 观测站现场对照与首页风向。** 用户确认继续观测站交互。沿用认可原画，接入查旧记录、任意顺序核对临水旧桩／上游风标、主动留下待查线索的短流程。吻合与偏差分别保留，不凭两点推断原因已知；完成后可阅读“验证”。退出保留当前页面进度，显式重新核对才清除；角色仍为静态，不恢复错误朝向行走。手机继续满屏静态。云层独立于固定建筑沿同一风向平移，目标60fps并实测约60fps，保持单次绘制与1440px缓冲上限。离线补齐天空并按物体轮廓遮挡，不新增生成用量；首页滚动条同步浅草绿／深绿。此条覆盖早先24fps／两张纹理预算，现三张纹理，新增天空约269KB；重复云形与固定镜头的限制见 [观测站记录](./homepage-station-flow.md)。

**2026-10-27 翻章抵达与主题焦点。** 主题选择器用细线呈现键盘焦点，避免粗橙色方框。上下章切换先展示目标章页头约一秒，再平滑滚入正文；用户主动滚动、触摸、点击或按键立即取消。直接访问、锚点、刷新和历史返回不触发自动滚动；减少动态效果时直接定位而不做滚动动画。链接与全页导航保持正常，不改变章节URL。108项阅读检查通过，细节见 [阅读修正记录](./reader-experience-revision.md)。

**2026-10-27 页头栏位与目录滚动补正。** 工具栏和翻章栏必须在章首同为深色，进入正文同步过渡到阅读配色；状态样式优先级必须覆盖生产默认样式。左右阅读目录不设内部滚动，短栏吸附、长栏随文档自然滚动。保留页面及表格／代码必要的滚动条样式。章节换页采用原生跨文档淡入淡出，继续完整导航，遵循减少动态效果；不能用客户端路由破坏搜索初始化。具体修正和98项验证见 [阅读修正记录](./reader-experience-revision.md)。

**2026-10-27 阅读体验与动效修正。** 左侧恢复全书章节，中间约72ch原文，右侧展示本章全部小节和真实批注／子标题；窄屏使用目录弹窗，常驻翻章入口覆盖手机。搜索恢复居中且与主题一致，代码与夜间表面统一配色；构建刷新内容缓存并验证静态资源引用。手机章首改为从共享高度场离线生成的二维等高线，免下载透视地形图。地形节点用贴地测绘桩及真实遮挡路线；正式阅读仍无Three.js和WebGL。首页云、草、水连续动态，页头只动未测绘边界，统一暂停与降级；山体和人物保持静态，不宣称动态光照或完成步态。另接入山脊与测绘主题的SVG站点图标。此条覆盖旧版“左侧选取三站路线”和手机透视页头的规定，详见 [修正记录](./reader-experience-revision.md)。

**2026-10-27 2K页头与一次视频样片。** 地形裁去共享底图的空边，以同一坐标系放大形体、路线和节点；桌面按可用高度取景，手机分开开始入口、节点索引和图注。正式首页继续使用 `hero-v04`；`hero-v02` 与 `cast-v02` 保留为过程参考，旧角色表不作为当前动作身份。现有MMX额度可用，本轮仅创建1条Hailuo-2.3视频，确实得到侧／背面，但输出反复旋转而非固定方向步态，不通过动作验收、不接生产行走、不继续消耗额度；原片和候选朝向帧均保存。此条更新上轮视频被额度阻止的状态，详见 [取景与样片记录](./reader-scale-video-study.md)。

**2026-10-27 正式阅读与手机首页修正，人物朝向待新资产。** 统一地形保留为共享预渲染材质，各章恢复独立路线、语义节点和未解边界，节点链接真实小节；正式阅读不再运行三维地形或全屏透射WebGL。移除默认与手记双重页尾，复制Markdown移到正文前，回到正文只保留页边入口。手机首页改为满屏画面与天空上的标题，仅阅读与章节入口，免加载交互环境与人物动作。用户指出沿左后方路线仍展示正面人体、白框标签粗糙：正式首页撤下方向错误的行走，保留认可原画站姿、环境动态和记录查阅，测点仅留贴地环。mmx视频调用返回Token Plan用量上限，没有生成样片；多方向转身／步态未完成，不能继续宣称人物动作已解决。此条覆盖上一条的生产行走状态，详见 [修正记录](./reader-homepage-refinement.md)。

**2026-10-27 用户指出同手同脚、躯干和头部缺少动作，并授权替换正式首页、提交推送。** 步态修正为对侧手脚领先，左手负重限制摆幅，加入骨盆承重、肩部回摆与头部视线稳定；从完整拆件重新合成帧，不恢复此前胸腹部矩形贴图形变。正式首页接入认可原画、同场所短路线和同色导航，章节、安装、下载、阅读顺序与 Agent 入口保留在首屏下方，真实搜索保留；打开搜索暂停场景，Esc优先关闭搜索。现仍是固定取景的二维分层体验；模式、天气和后续区域尚未完成。生产记录见 [首页发布](./homepage-publication.md)，此条授权覆盖此前“只预览、不接正式首页”的限制。

**2026-10-27 用户授权开始同场所短探索：独立像素体验稿03。** 沿用已认可首屏，加入“进入观测站 → 檐下出发 → 经过前景器材 → 沿维护路抵达岸边旧桩 → 主动查阅记录器”的一段。两轮生成动作稿因比例／方向／装备连续性失败而弃用；实际人物动作取自原画，拆分肢体与随身器物后离线合成12帧步态、站立与查阅姿态。人物离开后的背景已补齐，原器材前景重新覆盖人物形成遮挡，脚点沿岸边而非水面行进；书名在进入后收起，控制条置于画面下方。当前是固定取景的二维分层路线验证，未实现自由三维、后续区域、天气切换或两种职责模式；不能以本轮动作宣称完整探索完成。独立预览仍为 `meadow-study.html?revision=first-walk`，正式站点未替换、未提交或推送。完整实走约15.3秒，42项行为检查通过；详细资产、来源和限制见 [体验稿记录](../prototypes/visual-direction/meadow-study.md)。

**2026-10-27 用户指出人物胸腹部局部动画含义不清，并澄清skill要通用产出这种风格。** 已撤掉人物胸腹部纹理位移，原意为呼吸／衣物受风，但局部变形破坏了身体与装备连续性；当前保留完整静态人物，仅草、云和水有动态。人物未来动作需有明确行为及连贯资产。`unmapped-pixel-art` 已重构为通用“叙事像素美术”技能，按任意请求题材提炼构图、光色、像素组织、材质和角色关系；观测站原画只作风格示例。删除技能对本站路径、玩法、端口和流程的依赖，补充通用提示词模板及雨夜街巷、雪后室内、林间渡口三种配方，未另行调用生成服务。已有技能调用名保留，更新入口说明与UI元数据。

**2026-10-27 用户授权精修与环境动态，并要求提炼为可复用 skill。** 已在认可的 `hero-v03` 原画上作记录器、巡检车接口和接线端点的局部像素修订，输出 `hero-v04.webp`；同构图加入独立遮罩控制的慢云、草梢、水面和局部衣摆变化，建筑、道路与脚点固定。当前仍是原画分区动效，没有三维行走或新的探索流程。独立预览沿用 `meadow-study.html`，保留暂停、系统减少动态、离屏停绘和静态回退；运行验证见 `.lab/meadow-motion/browser-report.json`。美术与制作规范已提炼为 `.agents/skills/unmapped-pixel-art/SKILL.md`，附带认可原画和两份按需参考；本机技能目录通过 junction 指向这一仓库源，避免维护两套副本。规范验证通过，不把未验收的角色表和轮数漂移固化为规则。正式站点未替换。

**2026-10-27 用户对 meadow-study 明确反馈“就是这个味”，要求说明后续调整。** 以首屏 `hero-v03` 的像素色块、明亮天空、冷暖侧光、开阔原野、近景右侧站房与远行路径为已认可的美术方向；不是对动作、人物参考表、载体细节或完整探索玩法的验收。后续先校准门窗／台阶／人物的实际尺度、统一首屏和角色表的身份及装备、明确檐下工位与巡检载体的用途；原先灰绿低饱和与人物占画高 7% 只是先前规格，不应机械套回已获认可画面。再拆层制作克制风感，最后验证从檐下沿维护路到首个测点的短行进与遮挡；详细推进顺序见 [视觉稿记录](../prototypes/visual-direction/meadow-study.md)。当前回复阶段只更新设计记录，未新增生成或替换正式站点。

**2026-10-27 用户在明确方向后要求继续制作：进入“原野观测站”首屏与角色视觉稿阶段。** 主方案为像素美术、自然成人二维角色与有限三维环境，开阔场所、持续风感和具体设施共同组织画面；制作规格与可直接执行的角色／首屏提示词见 [美术规格](../prototypes/visual-direction/meadow-art-brief.md)。用户指定采用 mmx，已找到全局安装及有效 OAuth，使用 image-01；未调用 OpenAI 图像 API。先统一人物和载体，再用其身份参考生成完整首屏。生成稿是独立美术评审，不能称已实现三维探索或完成动作图集。生产站点不接入未评审图像，不用程序占位人物替代本轮美术稿。

**2026-10-27 用户补充七条 B 站视频并要求判断参考价值：研究获积极反馈，具体路线尚未确定。** 已核对原视频、作者与简介并查看 77 张分时画面；长课程为抽查，不称完整观看，见 [逐条研究](./homepage-user-video-research.md)。优先研究第 6、7 条的开阔场所与整体动态、第 5 条的环境光照、第 1 条的 AI 动作／立绘拆件流程。人物不必全部手工逐帧；二维人物与环境是否三维分开决定，前一轮固定二维建议继续开放。研究板只放视频链接与分析，不导入作者人物和场景、不调用生成服务、不启动实现。

**2026-10-27 像素方向仅先调研：用户认为近景粗糙，提出可换方法并询问像素是否更简单，随后明确要求“先调研”。** 本轮新增 [像素方向研究](./homepage-pixel-research.md) 与 [可视研究板](../prototypes/visual-direction/pixel-research.html)，对照五款作品、13 张官方商店原图与文档。优先建议评估固定俯斜视角的二维精灵和分层场景，但尚未获用户确定；不启动像素场景、不替换首页、不将原作素材作为本站资产。像素可降低部分三维人物建模负担，动作、绘制和一致性仍需制作；此前泛称“2.5D 更简单”应修正，混合三维效果和低分辨率三维不等同于纯二维。二维自由镜头的限制与原先真实三维目标的变化必须明确。

**2026-10-27 人物素材纠正与工作近景 02：用户明确指出 Quaternius Universal Base Characters 预览与三个参考作品的形象、风格均不符。** 该预览仅用于调查素材，未下载或导入其人物模型，不作为人物设计依据。当前新增 [檐下接线局部试作](../prototypes/visual-direction/bench-study.md)，用原生几何验证双手、接点、遮蔽与天气关系；人物仍有程序模型的生硬感，不能宣称人物风格或首页美术已通过。Jusant 的形体概括、Death Stranding 的装备与行动关系、INSIDE 的构图克制是不同研究维度，并非三种画风的混合指令。正式首页不替换。

**2026-10-27 用户授权开始制作视觉样张：已完成观测站原生三维美术稿 01。** 同场景提供固定取景、晴雨雪、工作近景、边界和人物／巡检载体。当前是待评审候选，程序资产与材质仍需深化，尚超历史生产性能预算，不能替换正式首页。25 项实现检查通过仅证明浏览器行为与资源调度；见 [样张记录](../prototypes/visual-direction/field-study.md)。

**2026-10-27 气候补充：用户认可当前研究方向，并提醒环境也包括气候。** 后续同时设计长期气候、当前天气与时段光照，关联建筑防护、植被、地表干湿、人物装备和行动、风声与能见度；天气效果由这些关系推导。研究板新增凉冷多风高地、降水后放晴的片段提案，具体设定仍待校准；不把永久浓雾当作未知的唯一表达。

**2026-10-27 首页参考板：已查看 8 张官方画面并完成独立分析板。** 按环境、人物、设施分别研究三部作品，比较观测站、旧设施与流动营地三个场所，建议先评审观测站，尚未获用户确认。原作静帧、画面观察与本站提案明确分开；未实机操作，不推断原作渲染实现。见 [参考研究](./homepage-reference-study.md) 与 [可打开的研究板](../prototypes/visual-direction/reference-board.html)。下一阶段先做关键构图和同尺度人物／设备造型表，暂不继续替换场景。

**2026-10-27 参考与技术边界：用户认可 Jusant、INSIDE、Death Stranding 三个参考例子，并明确后续技术说明只吸收有价值事项。** 主参考与最终风格尚未确定；不把港口、水彩、雨景、全程序建模及效果清单当作需求。采纳共享材质、空间与资源契约、合批和可控解析动效，其他按视觉需要实测，见 [技术取舍补充](./threejs-technical-review.md)。

**2026-10-27 用户要求重新澄清：首页与人物过于抽象，应学习优秀作品后梳理设计与目标。** 暂停裂隙方案的细节深化。既有目标与未确认的世界观、角色和镜头分开，见 [首页设计简报](./homepage-design-brief.md)。裂隙、六处工位、三台 Agent、越肩镜头均非已确认要求。下一步先参考实际作品画面、明确美术与角色方向，再评审少量关键构图；不继续以功能通过或程序灰盒替代视觉质量。

**2026-10-27 继续首页：场景本身仍未通过，不能只扩大距离或补移动来宣布完成。** 本轮独立候选为 [裂隙前哨](../prototypes/visual-direction/rift-design.md)：以地层切壁作为主体，工程依附局部，靠路径、遮挡与越肩抵达边界组织六个镜头。继续保留同世界进入与两种职责方向，不复用阅读页山脊。当前是程序几何的空间样片，尚无最终资产、自由行走或完整任务流；线上首页不替换。样片为检验近景与工位采用透视相机、缓存太阳阴影 2048 与局部工位阴影 1024；这属于待评估实验，不是变更下文生产性能基准。

**2026-10-27 正式阅读页接入：用户确认将已选阅读设计应用到正式站点。** 首页场景本身仍未获认可，暂停深化并作为快照保存，不随阅读页发布。阅读页沿用原章节 URL、原文、搜索、Markdown 与代码复制；接入整幅地形页头、探索手记排版、表层与底图分离的背景、按需章节目录及回到正文开头。批注按标题主题匹配最新原文，不能依赖旧版章节序号；新增阅读辅助不算入原文。远端主分支的新章节与搜索修复已合并，不能回退。

**2026-10-27 空间尺度纠正：用户指出工程剖面的主要问题仍是场景太小。** 六处工作区不能继续压在一眼看完的展台上。新候选先用总图、人体比例和镜头分镜组织约 140×210m 的连续工程区域，再用实际间距、道路、高差、遮挡和不同观察点表达探索。首屏仅显露世界的一部分；跨区镜头经过连接路线，阅读后回到原区域。详见 [空间尺度设计](../prototypes/visual-direction/territory-design.md) 与 [总图及新旧对照](../prototypes/visual-direction/territory-review.html)。这是独立预览，尚未获用户验收；程序建筑用于核对空间骨架，不代表最终美术或完整 SDLC 玩法。生产首页不变。

**2026-10-27 首屏纠正：用户指出“首页不如阅读页”是完成度比较，并没有要求照搬阅读地形，也没有要求放弃已有工程探索方向。** 后续先诊断构图、尺度、装置用途与空间组织，再制作独立设计预览。可进入作品、同世界转换、多区域工程探索继续保留；圆台和大拱门未经美术验收，不等于必须保留的造型。本轮 [工程剖面设计推导](../prototypes/visual-direction/outpost-design.md) 与 [设计评审板](../prototypes/visual-direction/outpost-review.html) 是待评审候选，不代表用户已确定新方向。生产首页不变，先前首页地形版只作比较稿。

用户指出上版墨迹几乎不可感知，章首地形应直接成为页头，右侧小线图缺少实际信息且文字过小。最新阅读样张改为无图框的整幅深色三维页头，标题与场景同处一个连续背景；删除泛化的页边小线图，保留文字批注，窄于1400px时随对应小节排在正文之后，批注正文至少15px。背景改为覆盖阅读区域的可见晕染轮廓，而非仅在窄页边轻微缩放。正文、辅助文字和链接通过更深的色阶维持对比度。此反馈优先于上一段“墨迹只在页边”的实现选择；统一暂停、减少动态效果与原文完整性要求继续适用。

用户进一步要求阅读页带有淡墨扩散的动感，《验证》章首改用深底、彩色粒子与波浪起伏；本章小节收成右侧贴边目录签，鼠标悬停展开，同时支持键盘和触屏。独立预览已加入上述效果，正文仍保留纸色和完整原文；墨迹只在页边扩散，主页面、代码和目录使用统一细滚动条。用户明确提出的彩色与持续动效优先于下文旧版单色、唯一渐变和禁止循环动画的规则。总开关可暂停背景及章首，系统减少动态效果优先，离屏章首和后台页面停止动画。此轮范围仍是阅读样张，未完成首页最终空间。

用户后续反馈：路线栏不应出现局部原生滚动条；《验证》章首可尝试三维网格、粒子峰谷；首页“安装与下载”应直接展开并重新编排。预览已修正路线宽度与错位边距，矮视口使用整页滚动；章首加入独立、按需绘制的原生 Three.js 地形，保留 SVG 回退；安装区提供系统命令切换、复制与真实发布文件。此处三维章首是阅读插图，不代表首页最终世界已建成。首页旧平台仍是流程原型，用户认为其无聊且用途不清，尚未接受为美术方向；重设计建议是让探查、显现、取证与剩余未知成为场景行为，而非只让展台或镜头运动。

**最新阅读方向：用户已选择探索手记，并指出此前两种样张除顶部外骨架雷同，左目录与右侧分段仍枯燥。** 后续以章节的观察、方法、证据和剩余未知组织阅读辅助，不以换底色或重命名菜单冒充风格。当前《验证》样张采用可跳读的探索路线、保留全文的纸面正文、对应小节的图解批注，以及两张章内图版；完整章节与小节目录按需打开。该要求优先于下文旧版固定左章目录、右小节目录的规定。宽屏展开图表，长段落保持 72ch 上限；专注阅读收起辅助。仅《验证》完成针对内容的编排，其他章节保留通用阅读。详见 [探索手记重设计记录](../prototypes/visual-direction/journal-study.md)。

用户已确认：默认首页完整可用；可选择进入真实 Three.js 空间，在其中互动与阅读；通过人类主导和 AI 原生两种 SDLC 的操作职责、空间活动和产物流转，表现“迈入未知、恢复局部秩序，未知仍然存在”。具体玩法见 [mini-exploration-design.md](./mini-exploration-design.md)，参考和技术路径见 [experience-plan-2026-10-26.md](./experience-plan-2026-10-26.md)。两份材料中的细节仍属设计草案，不代表美术或原型已验收。

用户最新纠正：仓库现有首页同样过于嘈杂，尤其左侧堆叠文字。首屏的主体是一件概念展示作品；进入前看似概念图，进入后揭示为同一个可交互的 Three.js 世界。书名、一句主题与进入入口保持克制；版本、长标题、安装命令与章节摘要移到首屏下方。人类主导 / AI 原生的探索职责切换只在进入交互空间后提供，不前置为首页选择题。

之前复用仓库首页的方案仅是质量回退基线，不是最终布局要求。确定作品方向时，同时提供首页下方与普通阅读页样张，验证配色、版式和交互是否连贯。新候选见 [visual-direction 独立预览](../prototypes/visual-direction/README.md)：以“未完成的测绘环”试验作品首屏、同场景进入镜头与真实章节阅读。场景形态和候选色板尚未验收；不得据此宣称最终美术已确定。生产站点继续保持不变。

用户对第一轮的反馈：单一圆台场景过于呆板，普通阅读布局不满意。第一轮仅证明进入与阅读可以联通，不能据此锁定场景规模或固定三列的文档版式。用户希望先看“图解技术书”与“探索手记”两种实际样张，见 [第二轮阅读与空间组织](../prototypes/visual-direction/reading-study.md)。后续空间建议为同一个连续世界中的多个不同区域，需以行进、遮挡、高差、装置用途与状态变化表达探索；不是在圆台上增加同形标签。

用户认可第二轮两种阅读样张的方向，同时指出 2K 显示屏两侧偏空。宽屏应扩大整页构图并适度提高字号，保持正文行长；页边按宽度承担章节导航、本章路线与相关旁注，专注阅读可收起。窄屏继续使用按需目录，不将宽屏导航挤进正文。当前 [2K 预览](../prototypes/visual-direction/reading-wide.html) 可模拟 100% / 125% / 150% 缩放对应的内容视口；生产阅读页尚未替换。

本更新优先于下文旧方案中首页信息优先级必须全部落在首屏、“只做固定首屏”“不出现人物或具体道具”“石板充能满后才能进入章节”等与新方向冲突的规定。后文保留历史依据；章节阅读保持开放，访问、任务应用、检查通过分别记录。既有信息可读性、可访问性、资源纪律与先预览后实现的要求继续适用。两种模式均保留人的判断责任，传统模式包含合理自动化。

## 一、专业场景定位与工作流认知

**产品形态**：一本中文技术书的在线阅读站，同时是可直接加载的 Agent Skills 发行物。
**读者**：写代码的工程师、技术负责人、以及把站点内容喂给本地 Agent 的使用者。
**他们来的目的**：确认"这本书值不值得读"，然后找到自己要的那一章。

因此**页面首先要可信，其次才要好看**。任何视觉效果若让人怀疑"这是一张宣传页还是一个技术仓库"，都判为失败。

**工作流铁律**

1. 先出**可打开的预览**（HTML/SVG/图），再写实现；预览未确认前不动线上站点。
2. 每个视觉决定都要能回答"少了它会丢什么"，答不出来就删掉。
3. 同一信息在页面上只出现一次。
4. 先测再交：给出实测数值（对比度、字节数、帧率、宽度），不接受"已实现"。

---

## 二、需求解析与信息架构设计

**首页信息优先级（不可调换）**

1. 这是什么（书名 + 一句话定位）
2. 凭什么可信（版本、许可、章节数、可下载制品）
3. 怎么开始（开始阅读 / 走进场景 / 安装命令）
4. 全书结构（10 章，唯一一次列举）
5. 给 Agent 的入口（llms.txt / llms-full.txt）

**禁止**：同一批章节在页面上出现两次；把内容藏在一次交互之后才可见；首屏与正文之间出现超过 80px 的无意义空白。

**阅读页结构**：左侧只放页面级导航（章），右侧只放当前页小节（h2/h3）；两者不得内容重复。

## 三、设计系统与视觉语言规范

**令牌优先**：字号、行高、间距、圆角、颜色一律走 CSS 变量（`--mt-*`），禁止在组件里写魔法数字。

**色彩**
- 中性冷灰阶为基底；**单一强调色**：信号橙（亮 `#b93a0a` / 暗 `#ff7a3d`）。
- 不引入第三个色相。语义块（公理/不变量/约束/反模式）是唯一例外，各有一色但同属低饱和。
- **禁止纯黑纯白**：正文 `#1f2328`/`#e6edf3`，背景取近白/近黑。

**线条**：装饰线一律 **1px**；焦点环 2px。禁止模糊阴影（`box-shadow` 带 blur），用 1px 细线与底色差异建立层次。

**字体**
- 正文：系统 UI 栈 + 中文字体优先级（PingFang SC / Microsoft YaHei / Noto Sans CJK SC），行高 1.85。
- 等宽：元信息、章号、表头、eyebrow 一律等宽 + `tabular-nums`。
- 显示字体仅用于拉丁字母与数字；中文标题靠**字号 + 字重 + 负字距**立气场，不依赖衬线。

**对比度**：正文 ≥4.5:1；大标题与其最差像素也须 ≥4.5:1；弱化文字 ≥4.5:1。计算后写入报告。

## 四、视觉层级与信息主次

- 每屏只允许**一个**视觉焦点。首屏焦点是场景或书名，不应两者同时抢。
- 正文列宽锁 **65–75ch**（当前 68.63ch），不改。
- 标题节奏：h2 上 2.4em / 下 0.8em；h3 上 1.9em / 下 0.6em。上间距必须明显大于下间距，让标题属于下文而非上文。
- 元信息（版本、日期、章号）在层级上必须比正文低一档，用等宽小字表达。

## 五、设计风格哲学

**一句话**：工程图纸的克制，加上一间**无人值守**的前哨。

**「迈向无人区」的双关是全部视觉的出发点，不是文案**

- 字面：未被测绘的地域、边境、旷野——人类尚未进场之处。
- 隐喻：Agent 在一线生产，人退到意图与裁决的位置——**人在物理上不在场，系统仍在运转**。

因此画面必须同时包含两件事，缺一不可：
1. **一小片已知**：室内被一束暖光照亮的一角。暖光不是温馨，是「人类已经点亮并定下规则的那一小块」。
2. **大片未知**：窗外深暗、无细节、无人类痕迹的旷野或虚空，越远越失去结构。不得把窗外画成风景名胜，未知必须是**没有特征**的。

**禁止的误读**：把场景做成温馨书房、咖啡馆一角、居家工位。任何一种「让人想坐下来喝杯东西」的氛围都判为失败——那是「有人」，不是「无人区」。椅子可以是空着并被推开的，机器可以还在跑，但**人不出现，且刚刚离开的痕迹要能被读出**。」

- 表现"技术感"靠**结构**（网格、发丝线、等宽元信息、编号），不靠发光与渐变堆砌。
- 表现"温度"靠**一束光**：全页允许且仅允许一处渐变——光源。其余一律纯色。
- 动画只为**解释状态变化**服务（进入、当前项、复制成功）。禁止无意义的漂浮与循环闪烁；所有动画在 `prefers-reduced-motion: reduce` 下停用。
- 密度优先于留白：宁可多给内容，不要用大留白冒充高级感。

## 六、配图、插画与品牌视觉

- 主视觉只允许两种形态：**内联 SVG**（几何/线稿）或**真实 3D 场景**（Three.js）。禁止概念图、禁止来路不明的位图、禁止 AI 图片直接当产品界面。
- 允许使用生成图作为**美术方向参考**（不直接上线），实现须在 Three.js 中按参考重做。
- 3D 场景规格：等距/长焦透视；唯一投影光为暖橙平行光（窗光），冷灰半球光补光；低多边形 `flatShading`；DPR ≤2（移动端 1.5）；阴影贴图 1024、单光源；draw call ≤40、三角面 <50k；页签隐藏即暂停渲染；canvas 就绪前先显示静态参考图（同时作为无 WebGL 的降级）。
- 章名不得烘焙进贴图作为唯一载体：贴图负责观感，可读文字用 DOM 叠加与 `aria-label` 承载。

## 七、复杂交互与数据呈现

- 表格：表头等宽大写 + 上下 1px 强线；行悬停淡底；数值列 `tabular-nums` 右对齐；窄屏横向滚动而非挤压列。
- 代码块：圆角、1px 边框、无阴影；终端命令用终端框并过滤提示符；复制成功需有可见反馈。
- 可交互元素：命中区 ≥24×24px；`:focus-visible` 2px 强调环；`Enter` 与 `Space` 等价触发。
- 全屏浮层：打开时锁背景滚动、焦点入内、Tab 循环、`Esc` 关闭、关闭后焦点与滚动位置还原。

## 首屏机制：光 = 已知的边界（2026-10 定案）

首屏不是一张图，是一次**尚未完成的测绘**：绝对黑暗中一个不稳定的光源在扫，光扫到哪里，世界才在那里存在；光移开后缓慢退回未知。没有房间、飞船、屏幕、书等具体道具。

**刻线 = 充能，充满才可放行**

- 光照到石板时脊上刻线从根部向上生长；光移开缓慢衰减（衰减速率约为增长速率的四分之一）。
- charge = 1 才可点击进入该章；未满时点击只显示充能百分比。已充满者在光移开后**保持满亮**（已获授权不撤回）。
- 这一机制对应书中的「验证通过才放行」，是设计的一部分，不是加载动画。

**可达性底线（不可违反）**

- 真实章节链接始终在 DOM 中，可 Tab、可被索引，与 canvas 状态无关。
- prefers-reduced-motion 或无 WebGL：所有石板视为已充满，交互不受限。
- 必须提供键盘可达的替代路径，不允许「只能用鼠标且必须等充能」。

## 技术选型：为什么不用 R3F（附切换触发条件）

本站是 Astro + Starlight，首屏只有一个 3D 场景。R3F 的常规优势（水合、StrictMode、状态同步）在这里不成立，而代价是首屏负载约翻倍（React + fiber + drei + 后处理约 110 到 135KB gzip，叠加在 three 之上）。

**不采纳不等于不承认风险。** 以下三项任一失败，即切换到 React 岛 + R3F：

1. mount/destroy 连续三次后 renderer.info 的 geometries/textures 仍在增长（泄漏）
2. 窗口缩放后画面异常或相机错位
3. 存在 animation loop 冲突或重复渲染

验收时必须逐项报告，不接受「已处理」。


## 截图与浏览器进程纪律（所有子代理必须遵守）

一次事故：子代理每截一张图就新起一个 headless 浏览器实例且不退出，机器上累积到 313 个进程、约 25GB 占用。

规则：

1. 一个会话只起**一个**浏览器实例，连续截完所有图；不要每张图起一个进程。
2. 运行结束必须收尾：显式 browser.close() 或按唯一的 user-data-dir 精确结束；禁止 taskkill /IM msedge.exe 这类整体击杀。
3. 一次交付最多 6 张截图，不要反复重拍同一角度。
4. user-data-dir 固定放在仓库内临时目录（如 .lab/<task>/.pw-profile），跑完删除，不要散落到系统 Temp。
5. 交付报告里必须写清收尾方式与运行结束时的残留进程数。
6. **浏览器统一用 Chrome，不用 Edge**：本机日常使用 Edge，用 Edge 做无头截图会与用户自己的浏览器进程混在一起，排查与清理都容易误伤。固定路径 C:/Program Files/Google/Chrome/Application/chrome.exe。
7. **截图只允许走 scripts/shot.mjs**：一次运行一个 Chrome、退出前杀进程树并删除 profile。不要自己写 spawn + --remote-debugging-port 的脚本——那类会话会常驻不退出，曾累积到 78 个进程 / 7.16GB。若确实需要 CDP 交互，必须在 finally 里 taskkill /PID /T /F，并在报告里给出运行结束时的残留进程数。
