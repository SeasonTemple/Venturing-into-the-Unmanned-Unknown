# 迈向无人区：双时代微型探索体验

日期：2026-10-26（Asia/Shanghai）

状态：用户已认可双时代对照的体验方向；本文将其细化为待评审的玩法设计。未实现游戏、未精细建模、未修改线上站点。

配套：[研究板](./experience-research-board.html#era-comparison) · [背景研究与技术路径](./experience-plan-2026-10-26.md)。本文更新背景研究中仅做参观和访问记录的范围建议：引入一个可选的微型工程任务，阅读仍然完整开放。

## 1. 玩家带走的理解

**同一片未知，两种工程组织方式；人的认知边界持续影响两者的正确性。**

- 人类主导：人主要承担理解、组织与直接生产，工具和自动化辅助完成工作。
- AI 原生：人主要定义意图、约束、证据要求并做关键裁决，Agent 承担被委派的生产与探索。
- harness 将任务、上下文、权限、工具、检查、运行反馈和恢复机制组织起来；其中的门禁只能检查已表达且可执行的条件。
- 产物快速出现不代表条件已满足；条件通过也不代表覆盖了所有未知。

传统工程同样可以并行、自动化、持续交付。两种模式的主要区别是生产责任与判断责任如何分布；这里是一种工程组织方式的对照，不作为所有团队的历史分期，也不宣称固定的效率倍数。

## 2. 同一场所与任务

推荐 **一个连续主世界 + 六个环节区域 + 随时可达的阅读层**。世界是一座朝向未知的半开放测绘前哨。首次原型只做总览、一个中继工作区和阅读落点，其余区域用体块标记。

主任务：“恢复测绘中继网络，让已知区域重新获得可靠观测。”

最小任务包含源端、中继、检查装置、接收端与两条可修复路径。两种模式使用相同拓扑、部件兼容信息、初始故障、可用工具和验收条件。场景内具体装置是设计假设，尚未锁定美术。

### 明确的验收条件

1. 测绘数据通过兼容接口到达指定接收端。
2. 测试注入主线路故障后，备用线路能接替传输。
3. 出现异常时可以隔离问题段，并返回可定位的检查记录。

演示使用确定的事件集：接口不兼容、备用链路遗漏，以及后续环境变化。它们来自相同的任务配置，不为不同模式暗改难度。数量与时间仅是游戏规则，不是现实 AI 可靠性的测量。

### 一项具体错误

一条近路在几何上能连通，但接头规格不兼容。人和 Agent 都可能选中它；都能通过规格检查识别问题。差别在于人如何检查自己的工作，以及 Agent 的提交如何进入预先配置的检查和修正流程。

## 3. 两种模式如何从操作上被认出

| 设计层 | 人类主导 | AI 原生 |
|---|---|---|
| 默认视点 | 接近现场的人形角色与可切换的局部总览 | 意图台的场域总览；可跟随某个 Agent 看现场 |
| 核心动词 | 观察、判断、操作、检查、交接、修正 | 定义、委派、约束、审阅、放行、隔离、回退 |
| 主要生产责任 | 人选择和实施修复步骤，自动化工具可执行已有检查 | Agent 在任务与权限范围内提出方案并执行候选修复 |
| 空间节奏 | 注意力随人的任务移动；工具留下工单、测量和检查记录 | 多个任务区同时活动，候选成果、证据和异常在不同位置汇集 |
| 可见的负担 | 需要理解现场、实施变更并核对交接 | 需要维护任务完整性、约束、上下文与证据，处理并行依赖和例外 |
| 失败后的反馈 | 指向具体误判、操作或遗漏条件，允许用工具查找 | 指向具体任务、提交、失败条件和依赖影响，允许重试或回退 |
| 进入运行的条件 | 由相同验收条件检查并记录 | 由相同验收条件检查并记录；预配置部分可以自动执行 |

### 光的含义

- 人的手电表示当前注意力和观察方向。知识影响识别、解释与判断，不直接换算成光束长度或“正确率”。
- Agent 探照表示被分派的任务范围和正在进行的工作。光可以多束并行、快速移动；不设为天然比人短窄。
- harness 显示目标标记、任务边界、检查位置、允许工具与回退节点。光照到了某处，不等于那里已被证实。
- 人与 Agent 的灯都不能照出根本没有提出的问题。新知识可以让已有场景出现新的可解释线索。

人形与机器人造型辅助识别，工作组织方式负责核心表达。机器人数量仅为演示规模选择，首个样板可用三个任务角色，不推导真实生产效率。

## 4. 同一任务的对照分镜

| 镜头 | 人类主导的操作与反馈 | AI 原生的操作与反馈 |
|---|---|---|
| 接到任务 | 人走近受损中继，查看目标与测绘结果，识别接口和线路 | 人在意图台确认接收目标、备用要求、权限与证据要求，发布任务 |
| 开始修复 | 人选择一个修复步骤；现场装置变化，工具可以辅助检查 | Agent 分别调查接口、提出路线和处理备用任务；多个区域出现活动 |
| 候选出现 | 已装配的近路仍标记为待检查，人物或工具靠近检查点 | 多条候选以临时结构出现，提交与对应证据等待检查，不自动接入运行 |
| 检查与修正 | 规格工具暴露不兼容接头；玩家选择替换并复查 | 已配置的规格门禁隔离该提交；Agent 依照失败记录修正，未配置条件仍需人识别 |
| 局部恢复 | 相同检查通过，备用线路也经故障注入验证，局部供能与测绘恢复 | 相同检查通过，人裁决关键例外后，受控提交接入同一局部系统 |
| 环境改变 | 人查看新的现场信号，定位影响范围，调整相关工作 | Agent 提交运行告警与影响关系；人修订意图和约束，再调度修复并重新验证 |
| 回望未知 | 恢复区域稳定可用，远处仍有结构不可辨识 | 恢复区域稳定可用，远处仍有结构不可辨识；Agent 活动范围也有边界 |

### 玩家怎样比较

正式体验建议第一次自主选择一种模式；关键节点可查看另一模式在同一条件下的短对照。愿意深入的人可以从同一任务快照重玩另一模式。不要求每位读者把同一任务重复完成两遍。

研究板中的分镜选择只用于解释规则，尚未构成游戏运行。原型阶段要实测：持续切换会不会打断任务理解；若会，保留节点对照和重新体验即可。

## 5. 章节作为可以使用的方法

阅读入口可以表现为测绘档案、维护记录或工作站手册。发现档案后，先看一句“这个方法帮助解决什么问题”；展开可阅读原始章节，并获得可尝试的操作。知识载体的最终造型留给美术阶段。

| 环节／章节 | 人类主导模式的玩法作用 | AI 原生模式的玩法作用 | 可以观察到的局部秩序 |
|---|---|---|---|
| 导论 0 | 理解任务、人的位置和有限目标 | 理解委派范围与人的裁决责任 | 总图出现已知范围和任务起点 |
| 意图与需求 1 | 明确目标、接收端和验收要求，修订自己的任务清单 | 将目标、约束和证据要求编入委派任务 | 模糊目标转化为可观察的交付条件 |
| 设计与架构 2 | 识别接口与依赖，选择兼容的修复结构 | 给任务配置接口契约、依赖和可修改边界 | 候选线路有结构、有归属、有边界 |
| 实现 4 | 实施修复、使用工具、留下变更记录 | Agent 在限定范围内形成候选提交 | 候选部件可见，仍区分待检查与已接入 |
| 验证 3、测试 5 | 使用检查与故障注入，记录已覆盖与未覆盖的条件 | 将可执行检查加入持续门禁，回传失败证据 | 已检查范围与未检查部分都可定位 |
| 集成与交付 6 | 选择接入时机，隔离故障，保留回退点 | 给并行产物配置接入门禁与回退动作，处理依赖影响 | 合格产物进入运行，异常可隔离 |
| 持续演进 7 | 根据运行反馈修订理解与方案 | 将反馈变成新任务与约束，检查旧假设是否失效 | 已恢复的系统能够在变化中继续调整 |
| 工具生态 8、附录 A | 选用工具，查术语、清单和反模式 | 维护工具权限、上下文资料和重复可用的流程 | 工具能力与使用边界可被识别 |

“发现／查看章节”只影响访问记录。任务中的方法是否应用、某项检查是否通过、当前系统是否运行，另存明确状态。打开章节不自动获得正确答案，读完章节也不宣称掌握现实工程。

## 6. 不确定性与剩余未知怎样进入玩法

首个体验样板使用可复放的事件和候选集，让玩家能将结果追溯到目标、约束与检查。不要用无原因的频繁失败或灯光随机闪烁充当 AI 概率性。

若后续需要表现输出波动，可让同一条件下出现不同候选方案，并显示检查如何筛选、修正它们。演示的候选分布不是实际模型的统计分布，不展示虚构的成功率或“可靠性提升百分比”。Harness 约束行动、检测部分错误、管理失败成本；它不使模型底层随机性归零。

环境变化使用同一个事件，例如外部干扰导致此前未考虑的信号条件失效。两种模式均会受影响：之前的验收记录仍说明它曾满足当时的已知条件，现在需要补充假设和检查。不能设计成凭空惩罚某个模式。

结尾显露一块稳定、有限的测绘区域，六环形成持续循环。全部章节被发现后，外界仍有未测绘部分、尚未提出的问题和新的机会。未知不全部等同于危险。

## 7. 建模范围与输入方式

### 第一处样板的资产

- 一块共享工作区：源端、受损中继、检查装置、接收端、两条线路的明确落位。
- 一个人形体块、三类 Agent 体块、意图台；姿态和活动能读懂即可。
- 临时、隔离、已检查、已接入四类产物状态，使用线型、形态与标签共同表达，避免只靠颜色。
- 入口基线与远处未知边界；方向和空间比例保持连续。
- 章节档案锚点与稳定阅读面。

首次不做骨骼精模、复杂物理碰撞、战斗、生存资源或大地图程序生成。采用点击可达位置移动和明确的操作点，降低控制门槛。Agent 模式提供总览与跟随机位，仍能理解实际空间位置。

### 技术组织建议

延续原生 Three.js。将场景渲染、任务规则、角色职责和章节访问状态分开：

- 任务配置包含拓扑、目标、契约、初始故障与公共事件。
- 两种执行策略读取同一配置，各自产生任务、候选、证据和运行事件。
- 检查器读取明确条件，不能通过读取“模式名称”决定成功与失败。
- Three.js 将语义事件呈现为角色行为、线路形态、物件状态和局部照明。
- 章节源继续使用 `book.config.json`、`stages.ts` 与 `skills/*/SKILL.md`；游戏说明不复制正文。

第一版为规则驱动的教学演示，不需要接入真实 LLM 或外部 Agent 服务。若未来引入真实生成，须重新设计延迟、成本、失败、权限和可复放性，不能无缝当作同一个问题。

## 8. 原型的最小闭环与验收

### 最小闭环

首页认识用途 → 选择进入 → 三维总览 → 选择工程模式 → 在中继任务中经历候选与检查 → 展开一章真实内容 → 使用对应方法 → 局部恢复 → 同一次环境变化 → 查看剩余未知 → 返回首页。

首次只完整实现“设计／验证”的一个错误案例和一章内容，其余六环关系可先示意。核心是验证操作职责的差异，而不是一次完成全部关卡。

### 通过条件

1. 隐去角色名称与模式标题，观察者仍能从任务、活动和产物流转解释两种组织方式的区别；给出实际观察记录，不凭实现者自评通过。
2. 玩家能说清楚“人直接完成工作”和“人组织 Agent 工作”中各自的判断责任，并能指出人的认知盲区如何影响两者。
3. 玩家能定位至少一个候选被拒绝的具体原因，并识别已检查与未检查的范围。
4. 相同任务快照、故障和验收对两种模式一致；事件记录能够复放核对。
5. 人类模式保留合理自动化，AI 模式保留人的关键裁决；不以故意削弱一方制造差异。
6. 未完成小游戏仍可完整阅读所有章节；阅读和任务状态互不冒充。
7. 局部恢复后仍能看见开放边界，玩家理解验收通过的适用范围。
8. 键盘、减少动态效果、无 WebGL 阅读降级及资源生命周期沿用背景研究的要求。

建议用少量首次接触的读者进行形成性观察；人数与结果据实记录，不将小样本当作效果统计。当前尚未做用户观察或游戏性能测量。

## 9. 补充参考与读取范围

2026-10-26 已读取以下官方页面：

- [Human Resource Machine](https://tomorrowcorporation.com/humanresourcemachine)：以明确输入／输出和一位执行者的可见动作解释程序执行。借用“动作使规则可理解”，不将它直接等同于传统 SDLC。
- [7 Billion Humans](https://tomorrowcorporation.com/7billionhumans)：官方明确对比前作的单一执行者和多个执行者同时运行程序。借用“组织方式变化成为可见玩法”，不推导多 Agent 自然更正确。
- [Explorable Explanations](https://explorabl.es/)：交互与学习结合的参考。借用让人通过操作和反馈理解系统的方向，不宣称该站提供了本项目玩法的实证验证。

本轮核验为官方页面文字读取，未实际游玩这些游戏。其执行模型不能当作 LLM 行为模型。此前 Three.js、资产、镜头与阅读资料仍见背景研究。
