# 首页人物制作路线与闸门

## 唯一目标（持续推进到完成）

让访客在首页完成一段可信的原野探索：进入观测站、沿限定维护路主动行走、在停点收步并转身回望，人物的朝向、脚底接触、重心、装备和像素尺度始终连续。第一段样片通过后，再把同一套状态接入正式首页；在此之前不扩展新天气、新视频或新的角色制作路线。

**完成定义：**

- 四向身份源和正面→侧面转身帧可追溯；
- 左向 8–12 帧完整像素行走在原生尺寸、场景尺寸和窄屏下都能读出接触、抬脚、前摆、承重和上身响应；
- 独立路线原型支持手动移动、停步、停点点击、转身，以及自动行进被手动输入接管；
- 减少动态、失焦、离屏和连续运行不会持续增加帧序、资源或内存；
- 右向移动只有在另行手绘并通过右向资产闸门后才加入，不用镜像或倒退伪装。

**当前唯一闸门：** 在保持认可人物身份的条件下，取得可信的完整负重姿态与连续步态。`pixel-walk-v01` 已被用户否决；转身中间帧和负重姿态也只有技术检查证据，不应继续标为美术通过。原画、转身中间帧与失败行走的原生尺寸对照已放回原行走页。静态精确端点编辑与首尾帧动作试验分别评价，不再将某一种静帧编辑方法作为所有动画路线的前置条件。不扩展方向或接入首页，直到完整角色的身份、体积、受力与像素组织成立。最新试验结果见本文末尾，早期阶段描述不代表已放行。

这份路线把当前工作从“不断试图改善观感”收敛成四个有明确退出条件的阶段。每个阶段只交付一个可检查结果；未通过就回到该阶段修源，不扩展帧数、方向或首页交互。

## 阶段一：像素身份源（仅源契约通过）

**目的：** 让正面、侧面、背侧、背面四套原画成为同一个可追溯的像素源，并建立前视图的可编辑边界。

**已交付：** `pixel-native-master-v01`，包含原画锁定层、前视图分层、四向参照、方向契约、像素一致性检查和[阶段报告](../prototypes/visual-direction/pixel-native-master-v01/stage-report.json)。

**通过条件：**

- 原生尺寸下四向都能读成同一个人；
- 关闭锁定底图后，前视图仍能逐像素复原；
- 工具箱、记录器、衣摆、双脚和基线有明确归属；
- 被遮挡的手指、袖内和转身中间结构明确列为未知，不用三维渲染填空。

这一道闸门按“源契约通过”收口；它不等于人物美术或动作通过。当前只剩轮廓清理和必要的隐藏区域补绘。通过前不制作行走。

## 阶段二：一个真实转身（技术候选，视觉未确认）

**目的：** 用像素原生帧完成一次停步转身，验证方向变化时人物身份和装备关系不丢失。

**当前小样的作用：** `pixel-turn-proof-v01` 保留为早期载入记录；`pixel-turn-keyframes-v01` 是完整中间帧候选，尚不具备正式采用的视觉依据。

**当前交付：** `pixel-turn-keyframes-v01`，包含正面、3 张按坐标绘制的中间帧和侧面端点，以及原生尺寸、3× 对照图和 OpenRaster 源。文件、顺序与宽度诊断存在，但没有用户视觉确认；旧“人工通过”记录已撤回。

**复核结论：** 中间帧的脸型、肩背体积和色簇密度与原画有明显差异。共享画布、脚底行与单调变窄均不能证明同一身份或可信转身；该项阻塞继续扩展。

**通过条件：**

- 头、胸廓、骨盆和脚底在转向中保持连续；
- 人物朝向与移动意图一致；
- 工具箱和记录器随所属手臂转动，手掌方向可读；
- 3 倍放大检查没有撕裂，原生尺寸轮廓仍然成立。

如果三个中间帧无法成立，停止动作制作，回到阶段一补绘源层。

## 阶段三：四个负重关键姿态（技术候选，视觉未确认）

**目的：** 在一个已经通过的方向上验证完整身体动作，而不是只动腿。

**当前交付：** `pixel-loaded-keyposes-v01`，保留四张候选、对照图、OpenRaster 源与检查器。四帧曾被用于行走，但上身像素质心有变化只能证明图像变化，不能证明负重、人体或自然度；旧放行结论撤回。

固定四帧：右腿承重、左腿前摆、左脚跟落地、换到左腿承重。每帧同时检查骨盆、胸廓、肩、肘、头、两件装备和支撑脚。

**通过条件：**

- 重心随支撑脚变化，膝盖没有内凹或反向折角；
- 上身不是冻结层，肩肘和器物对承重有响应；
- 手掌、袖口与装备接触在每帧可解释；
- 四帧放在同一张原生尺寸对照图中仍像同一个人。

未通过时只修关键帧源层，不生成中间循环。

## 阶段四：短行走与首页接入（视觉闸门未通过）

早期试作未经可靠的视觉确认，就将四个关键姿态扩成了 8 帧左向短行走，并接入停步、上一测点移动和转身。该扩展不代表阶段三通过。移动任务与转身任务各自使用独立时间基准，按钮状态在贴图加载和任务完成时同步更新。行为预览入口通过自动检查，但正式首页已用 `actorPreview=1` 闸门隔离，避免把粗糙源当成产品视觉。

**当前交付：** `pixel-walk-v01` 保留为用户已否决的失败样本，八帧不再标记源美术通过；`pixel-route-v01` 的行为与压力记录仅作为技术证据。正式首页不显示角色，`pixel-route-v01/home-checks.json` 仅说明预览入口能运行。

**首页接入条件：** 先通过原生尺寸静帧的比例、轮廓、重心、装备接触和可读性复核，再验证场景尺度、窄屏、长时间运行与正式首页移动。当前只完成行为预览，不满足正式接入条件。

后续若扩展方向，只允许在当前样片稳定后另开资产闸门；三维 v03、转身小样和未通过帧不回流到正式首页。用户指定继续使用 MMX，按小批候选核验，不在身份与姿态未成立前扩大方向、帧数或视频。每个扩展阶段都要有独立的源、行为和性能证据，避免用工具数量代替视觉验收。

## 制作管线约束（2026-10-30）

三个生成器统一经过 `scripts/pixel_review.py` 写候选记录，不能自行写入美术、动作或首页接入通过。用户否决绑定有序帧的 RGBA 摘要：重复构建和 PNG 重新编码保留否决；像素改变时保留旧否决依据，新候选恢复待检查。`scripts/check-pixel-review.py` 在隔离副本中检验该行为。文件完整性检查以 `integrity-ok` 报告，不再把期待的“人工通过”状态作为测试成功条件。

当时拟定的下一个美术交付为一张与保留原画一致的完整负重静帧；后续 AGY 精确落脚编辑未通过，因此已在本文末尾更新为分别检验静帧控制与源动作，不再把该编辑能力作为共同前置。完整人物的头颈、胸背、肩肘、髋膝踝、握持和接地仍须先成立。

## 源修复与制作能力复核（2026-10-30）

复核旧调研中已经指出的尺寸问题：156×348 原图缩为 78×174 再放回，实际改变 11,112 个 RGBA 像素。因此此前页面所谓“原生尺寸”只能解释为试作工作尺度，不证明原画的像素网格。`pixel-native-master-v01/full-resolution-source/` 新增保留完整原图的 ORA 与 PNG；实际保存图层重新合成与原图逐像素一致。分层仍为已有边界指南，未补隐藏衣料，不是新的负重姿态或动画源。

本轮用原始人物图（而非旧三维稿）作为 MMX 人物参考，只生成一张同机位小步候选，记录在 `pixel-loaded-keyposes-v01/candidates/source-reset01/`。制作者已拒用：输出偏写实、增加兜帽与背包带、转成近正面、器物握持与尺度改变。不将缩小、像素化或拆层当作补救，不追加此类生成。这次结果再次支持旧调研对缺少精确编辑控制的判断，不能把它算作新的路线已走通。

用户明确要求使用 MMX，因此未调用 OpenAI 图像 API，未使用的编辑输入移入 `.scratch/unused-openai-inputs/`。本机 MMX 1.0.28 的图像命令实际提交 `image-01`，提供人物参考但没有遮罩编辑字段；不能把命令说明中出现的其他模型名算作已能选择的能力。

连同第一次候选，这批共四张，尺寸 768×1024、种子 301031。01/02 保持英文提示词不变，只移除人物参考；两张仍偏写实。03/04 使用相同的风格前置中文提示词，对比无人物参考和有原画人物参考：03 能出现像素笔触，但朝向相反、步幅过大、工具箱抱在胸前；04 又趋于平滑写实，道具与手的关系不成立。四张均由制作者拒用，未取得用户认可。记录与缩览分别在 `pixel-loaded-keyposes-v01/candidates/source-reset-review.json`、`source-reset-overview.jpg`；缩览不作原生像素验收。

本批结论仅限这些输入与配置：MMX 已显示能生成像素外观，但尚未同时保住身份、朝向、握持和小步承重，不能宣称人物生产管线已走通。结束这批生成，不用增加帧数、事后像素化或拆层掩盖缺少姿态控制的问题。下一步若继续 MMX，需要先改变已核实的控制条件，再做有停止标准的小样；不能默认换一份长提示词就能解决。

## 原画首帧的一次小步试验（准备与凭据排查历史）

用户同意改用认可原画作首帧、固定镜头检验一次小步换重。此次只验证一个动作，不制作循环、转身或整套方向。`pixel-loaded-keyposes-v01/candidates/first-frame-step01/` 保存输入、逐时段提示词与来源记录：原图完整保留，最近邻等比放大两倍，放入 768×1024 平色背景；没有重绘身体、裁断装备或使用被拒绝的四张人物。计划 4 秒，0–1 秒站稳、1–3 秒小步换重、3–4 秒收稳；拟使用 MMX 的 H3 首帧模式。

预检确认请求结构有效，尚未创建视频任务。`mmx auth status` 显示 OAuth；`mmx quota show --output text` 明确显示视频“不在当前套餐中”；配置中无 API Key，进程也无 MINIMAX_API_KEY。这些只支持当前认证方式和套餐额度的结论，不证明账户没有独立积分包，也不能据此断言所有视频扣费通道均不可用。

用户指出积分包可能可支付后，读取[官方 FAQ](https://platform.minimax.cn/docs/token-plan/faq)确认：积分包支持视频，可单独购买、无需 M Plan 订阅，1,000 积分等值 ¥7、有效期一年；订阅 Key 与普通按量付费 API Key 消耗的余额不同。先前直接要求换普通 API Key 的建议下早了。当前尚未查询账户积分余额，也未验证现有 MMX/OAuth 的 H3 扣积分通道；本地 H3 技能对凭据的限制仍须与当前官方接口说明分别核对，不将套餐查询当作完整计费预检。不自动购买积分，不试探性重复创建视频，不切换到 OpenAI。

权限就绪后先复查认证，单次提交并等待原任务。输出存在时按完整原片和相邻帧检查身份、画风、关节、手与器物连接和负重；失败则记录并停止这一条试验，不通过追加视频或补间帧扩大投入。

用户进一步确认现有积分来自签到或活动赠送。官方 MiniMax Code 首页公告（http://chat.minimax.io/，2026-10-30 两次检索均返回同一公告）明确：“9 月 15 日前，签到积分和付费积分均可用于生成 MiniMax H3 视频（此后仅付费积分支持）”。因此普通签到赠送积分不支持当前 H3；此前一般性“积分包支持视频”不能推出所有积分都支持 H3。登录前主页当前直接抓取未显示该横幅，公告文字依据为官方站点的检索收录；用户如持有特殊活动的 H3 专用赠额，应另按该活动条款核实。尚未创建视频任务、购买积分或改动账户凭据，首帧及动作脚本保留待可用额度。

采用用户提供的官方 `h3-sprite-sheet`、`write-h3-prompts` 和 `h3-prompt-writing` 中适用于本次的首帧锚定、单动作及源片先验规则，执行仍使用用户指定的 MMX。提示词改为官方 I2VA 字段格式，未改变已同意的动作。首帧预检：PNG/RGB、768×1024、30,286 字节、正常方向、比例 0.75。命令未传 `--ratio`；MMX 1.0.28 自动在请求里加入 `ratio: adaptive`，输出比例实际保持 3:4，不能将此说成请求体完全省略了比例字段。

**制作者复核：动作未通过。** 原人物、橙色外套、深绿裤、两件器物所属手以及固定机位基本保留，比本批四张静态候选更接近目标，说明本次首帧模式值得与人物参考图模式分别评价。但约 2.7–3.2 秒，原要求始终贴地的自身右脚（画面左侧）也抬起，出现额外一步；3 秒起的双脚落地保持没有按时成立。AAC 音轨检测到非静音信号（峰值 -11.9 dB），也不符合提示中的完全静音要求。未将视频称为单步合格、循环素材或首页可用角色，没有打包游戏图集。

**本次管线经验：** 首帧条件比本批人物参考图更能保留既有画面，但只有起点约束，仍可能自行补出下一步；需要精确单步落点时，应先取得同身份的有效终点姿态，再评估首尾帧约束，而不是对本条倒放、镜像、冻结上身或扩大行走帧数。每次记录输入哈希、请求规格、任务 ID、实际媒体规格和独立视觉结论；机械检查负责发现技术异常，不能替代动作审片。本次单条试验到此收口，未自动生成第二条。

## AGY 参考图编辑能力实测（2026-10-30）

用户另行要求测试新装的 agy MCP 是否能调用 Nano Banana 2 等生图模型。本机 agy 1.4.11 与登录状态可识别；不带代理的会话与模型列表等待上游响应，结束该只读探测后，仅为本次调用设置 `HTTP_PROXY` / `HTTPS_PROXY` 为已有代理 `http://10.46.35.24:10080`，连接与模型列表恢复。未修改全局代理、登录凭据或安装版本。

ag​y 顶层报告通过内置 `image-generator` 调用 `generate_image`；该工具有 `Prompt`、`ImageName`、`AspectRatio`、`ImagePaths`，支持参考图编辑。只调用一次，以已准备的 `first-frame.png` 作参考，实际返回 JPEG 896×1200、258,578 字节，已复制并检查真实文件：`pixel-loaded-keyposes-v01/candidates/agy-reference-edit01/candidate.jpg`。该能力探测成功，图片与原画基本保持同一人物、衣装、装备归属及像素外观。

但工具没有图像模型选择参数，返回也没有后端型号。ag​y 的 `--model` 列表是推理模型列表，不能据此将生图后端标成 Nano Banana 2。当前准确结论是“ag​y MCP 可经内置图像代理完成参考图生图”，指定 Nano Banana 2 和其他图像模型尚未验证。

这张候选仍没有满足动作端点：左脚脚跟抬起，腿向画面右后伸，不能认作要求的双脚全底落地、半鞋长向前的小步终点。能力成功与姿态未通过分别记录，未扩大生成或接入首页。请求、输出哈希、工具报告与制作者判断保存在候选目录；没有新增 H3 视频任务。

## 原生像素腿部姿态小样（2026-10-30）

在新分支 `codex/native-phase-anchor` 上继续制作 `pixel-phase-anchor-v03`。没有调用 MMX、H3 或 AGY；直接使用认可的 156×348 分层源，把上身、箱体和记录器作为一个共享组微移，右脚保留源鞋底，另一条腿从源色簇中拆分、最近邻转动并在膝部补三枚像素。原生尺寸已经能读出支撑脚与经过脚的分离，优于前一版坐标轮廓方案。

该小样仍保持候选状态：经过鞋尖向下，膝部折面还不足以承担最终动画锚点。输出、复现脚本和对照图在 `prototypes/visual-direction/pixel-phase-anchor-v03/`；没有接入 `main` 或首页。下一次只处理脚背、鞋底和膝部色簇，再重新做单张原生尺寸复核。

用户指出连续局部修订会把完整动作拆成“脚、膝、鞋尖”的无底线微调。随后改做 `pixel-phase-anchor-v05` 整帧重排：一次性定义骨盆、胸廓、支撑脚、经过脚、双手和器物的关系；经过脚抬离支撑基线，箱体与记录器随上身整体移动。该候选已能读出支撑＋经过，但下段腿仍偏细，保持候选，不进入 `main`、首页或视频阶段。后续只按整帧重画腿部体积，不再回到局部参数循环。

为停止单帧微调，继续制作 `pixel-phase-pair-v01`：同一原生人物源的一对相反承重整帧，分别是右脚承重／左脚经过和左脚承重／右脚经过。两帧的装备归属、上身尺度和支撑关系可并排检查；左承重帧的经过腿仍需整体比例复核，状态保持候选。通过这对姿态前不制作过渡帧、循环或首页接入。

随后补入第三帧 `left-contact.png`，形成“右脚承重 → 左脚低位接触 → 左脚承重”的三姿态研究。三帧仍只作为整帧候选，左承重段的经过腿和鞋底比例需要共同复核；未自动插值、未生成视频、未接入首页。

## 脚跟下落过渡 v05（2026-10-30）

离散时序检查发现 v04 中“左脚前摆 → 低位接触”的跳变来自同时移动两条腿和上身。本轮加入 `left-touchdown`，沿用前摆帧的上身和右脚承重关系，只让左腿以完整轮廓下落，再进入低位接触。目标尺寸下，前摆到跟下落的变化明显变小；跟下落到低位接触仍是接触事件的主要变化，需人工判断这个节奏是否合理。
