这是在不同完整姿态参考下的一次实际能力试验，结果进一步说明：当前接口未提供可依赖的全身姿态／风格精确控制。不能以更多重复提示词代替缺失的编辑能力。

## 二维试片实际如何制作

`scripts/draw-pixel-character.py` 直接从 128 × 196 透明画布开始，使用明确整数坐标、颜色与多边形／线条笔触绘制。8 个绘制图层、146 条笔触操作，实际可见色数 46，人物 alpha 边界 `(33,17)–(90,193)`，可见身高 176px。原身份参考和三维辅稿身高均为 174px；对照页分别保持原生尺寸，不局部拉伸对齐。

图层用于绘制顺序与编辑：远腿和鞋、裤装与近鞋、颈部与远臂、外套体积、近臂与左手、工具箱与右手、记录器与手指、面部和短发。此处的图层组织**不等于**已做好动画拆件或验证了二维绑定。

绘制内容包括：

- 左向鼻尖、眼眉与短胡茬，头颈和贴颈立领连续；
- 齐髋外套、闭合前襟、胸袋与围绕肩肘和腰部的明暗色块；
- 连续裤腿、膝部转折、封闭工作短靴；
- 远侧右手提银箱，近侧左手握绿记录器，手与提手／设备边缘交叠。

这是对一张完整图的显式绘制尝试，不能仅凭“用了像素笔触”就认定它有合格人体与风格。当前自评：统一的二维色块语言比通用三维材质更接近目标，但人物面貌、衣褶的自然度与原画的绘画层次仍有差距，**尚未定稿**。没有扩步态、接线、持书或其他方向，也未替换正式首页。

## 验证及其边界

`docs/research/homepage-pixel-stance-v04-validation.json` 记录文件完整性：ORA 的 mimetype 和图层结构可读，8 层按顺序重合后与原生 PNG 完全一致，内置合成图也一致。这只说明编辑源未丢失图像，**不构成人体或美术认可**；本轮未通过绘图软件 GUI 实测导入。

评审页无 JS、Canvas、WebGL 或动态循环；原尺寸图为 1 倍，放大图在桌面为 3 倍、小屏为 2 倍。淘汰的生成稿放在原生 `<details>` 中，默认折叠，未作为新人物使用。
