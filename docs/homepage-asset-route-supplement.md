# 新增美术工具与动作路线核对 · 2026-10-28

本轮核对用户提供的两个仓库、B 站视频与本机 Tripo CLI。只读取资料、抽查公开视频画面、查询余额和执行 dry-run；没有安装工具、上传人物、提交生成／绑定／动画任务、充值或修改正式页面。仍处于关键美术验证阶段，尚无通过验收的新步态。

## 结论

三个方向都有价值，但职责不同：**参数化建筑用于场景资产制作；第二个仓库优先借鉴人物动作的生产与检查方法；Tripo 为三维预渲染提供模型及骨骼来源候选。** 目前不足以把任何一条路线宣布为本站已走通的方法。

保留已认可的原野像素画风与人物身份。方块人物示例属于 Minecraft／YSM 一类比例和构造，不直接作为本项目的人物模板。第二个仓库虽名为 aesthetic-test，实际主要是 8 个游戏美术技能包，不是通用自动审美评分器。

## 1. 参数化 Topdown 建筑工坊

- 仓库：[Zengkailin/parametric-topdown-pixel-architecture](https://github.com/Zengkailin/parametric-topdown-pixel-architecture)
- 核对版本：`b7809fa65a8c28c665a952b7fea8e66013eb186e`。
- 已读 README、LICENSE、几何／材质／相机／渲染源码，查看建筑示例；未运行工具或作者测试。

真实能力包括建筑参数化、正交／透视取景、方向导出、精灵表、自定义材质图集与配方记录。其 3D 几何由软件光栅化器输出 2D 素材，**不是必须在网页运行的 Three.js 场景**。这对站房、维护设施和重复建筑变体有价值；正式站点可以只加载最终 PNG／WebP。

[renderer.js](https://github.com/Zengkailin/parametric-topdown-pixel-architecture/blob/b7809fa65a8c28c665a952b7fea8e66013eb186e/js/renderer.js) 明确说明无 WebGL、无光照，只乘顶点染色与材质差异；深度和法线用于结构描边。它没有直接解决投影阴影、室内暖光、夜间局部照明与湿地反射。简单整体染色也不能代替本站要求的昼夜环境对照。

已查看的森林旅店示例，纹理频率与屋面占比和原野站房不同；不能套用“像素”二字就认为画风一致。可借鉴建筑结构、相机参数和配方复现，仍要匹配本站俯角、像素尺度、色块和光向。README 称有 46 种类型，本轮未逐一运行验证。

代码附 MIT 许可；LICENSE 又提示原 Godot 插件和图集素材的独立授权。使用时保留代码声明，资产授权另核，不直接将示例图集加入站点。约 7.6MB 的内嵌图集服务于工具离线使用，不应成为首页运行时负担。

## 4. 本机 Tripo CLI

已定位 `E:/DevCache/npm-global/tripo.cmd`，包版本 `0.7.3`。当前进程 PATH 不含该 npm 全局目录，使用绝对路径可运行，不能误报“未安装”。本轮读取安装包 README、`skill/commands/process.md`、动画示例，以及代理与请求构造代码，核对了本地 CLI 帮助。以下是安装版声明及本地预检结果，不是云端生成成功证明。

- 图片／多视图 → 3D，已有模型可导入；骨骼可导出 GLB／FBX。
- `anim check` 返回是否适合绑定；`anim rig` 支持 biped 等体型。
- 安装版默认 rig 模型为 `v3.0-20260909`。
- `anim retarget` 接受绑定任务 ID，安装版命令暴露预设动作；支持 `preset:idle`、`preset:walk`、`preset:turn` 等，至多 5 个，按动画计费。未核实任意外部动作视频／FBX 能否直接通过这一接口重定向。
- `--animate-in-place` 可以剥离根位移；网页移动与支撑脚、步长仍需配合，不能剥离后独立按时钟播腿。
- CLI 支持 `HTTPS_PROXY`／`HTTP_PROXY`。本轮仅在单个子进程设置用户给的 `http://10.46.35.24:10080`，余额查询成功：`balance: 0, frozen: 0`。不修改全局代理，不声称无代理一定不能访问。

执行一次 `make <现有侧面参考> --then rig-check,rig,retarget:preset:walk --dry-run`，输出 `valid:true`，列出四个调用步骤，待上传列表仍含输入文件，交付物为空。**只验证参数和调用链，不上传、不生成、不消耗积分，也没有验证实际 riggable。** 这张侧面持物参考不是已批准的 3D 建模输入，未来不能直接照该 dry-run 自动提交。

Tripo 可减轻建模和自动绑定成本，不能自动保证原画比例、手指／握持、衣装拓扑、未见背面和受光风格。即使有标准走路，工具箱负重、翻书和端口操作仍需约束或动画修改。若采用三维预渲染，应把工具箱／记录仪作为独立刚性物件约束到对应手，先排除网格粘连和装备换手；然后固定相机与像素输出，必要时修轮廓和去除贴图里的烘焙光影。四轮载体不套人形行走。

2. 核对侧面接触、肩胯／头部随动、负重手、停步与转向；支撑脚在世界地面稳定，动作相位随实际路程推进。
