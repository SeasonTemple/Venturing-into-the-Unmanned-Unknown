# H3 Character Studio 调研结论

> 当前执行状态见 [首页人物现状与交接](../homepage-character-status.md)。本文记录调研及本地撤回经过，不代表整套运行时改动已提交；本次资产交接提交不包含既有站点改动。旧序列资源和完整审片记录仍保留在本地工作树。

调研对象：[`winkidney/h3-character-studio`](https://github.com/winkidney/h3-character-studio)，审阅版本 `07a4e4e`（2026-10-14）。

## 结论

这个项目有参考价值，但不适合直接作为当前首页人物的成品管线。它最有价值的部分是把“生成、抽取、逐帧修订、技术检查、人工美术验收”拆开，并且把每个方向的母版、提示词、种子、原始帧、透明帧、色板和修订记录保留下来。它不能替我们解决人物的重心、脚底接触、膝向、手掌方向或像素审美；示例输出本身也不是本项目已经确认的原野人物风格。

## 可以吸收的管线规则

- 四方向必须各有独立母版，不能用镜像冒充另一方向；先锁定人物身份、比例、装备归属和脚底锚点，再生成动作。
- 每次生成只提交一个可追溯作业，冻结参考图、提示词、种子、真实节点规格和输出摘要；重试或改参数建立新作业，不覆盖旧证据。
- 原始帧、抠图软蒙版、透明帧、统一色板和最终图集分层保存；在黑／白背景和原生尺寸、场景尺寸分别查看边缘。
- 法线、材质和遮罩按逐帧语义标注，不能从颜色或包围盒猜人体表面，也不能把数学覆盖率当成美术通过。
- 技术状态与视觉状态分离：加载、帧数、透明度、哈希、循环接缝都通过后，仍必须单独记录 `visual_approval: pending`，由人检查姿态、接触、身份连续性和像素簇。

这些规则正好暴露了本项目当前 load-sequence 的错误：它的运行和结构审计通过了，却错误地把视觉闸门写成 `true`。本轮已将该序列撤回为 `artApproved: false`、`motionApproved: false`。

同时，正式首页的站点路由已经加上素材闸门：默认进入观测站不再加载这批未通过帧；只有带 `motionReview=load-sequence-v01` 的显式技术审查地址才会加载。这样“隔离试用”和“正式交付”不会再由文档约定，而是由运行时实际保证。

## 不应直接照搬的部分

- 项目要求 Linux x86_64、Python 3.12、CUDA 13；H3 权重约 50.92 GB，另有 ToonOut 模型约 0.89 GB，当前 Windows 工作区没有必要为一次试验安装这套重量级环境。
- 生成入口连接本地 ComfyUI，不是 MiniMax 的 `mmx` API，也不是现有首页运行时。它不能直接把当前人物变成可靠的网页行走动画。
- H3 生成仍然具有随机性；四方向独立生成会带来脸、服装、装备和步态漂移。即使导出 256 帧、法线和材质图集，也不能跳过原生尺寸人工审片。
- 仓库中的示例是高细节日式角色，不能把它的示例图当成本项目已确认的视觉目标；能复用的是制作纪律，不是角色画风。

## 对当前项目的决定

暂不安装或接入该仓库的模型。当前先按它的管线纪律重做一张负重静帧母版：原生像素簇、骨盆—胸廓—头肩的受力链、支撑脚与经过脚、双手与设备接触同时成立，并在约 104px 场景尺寸复核。静帧通过后才制作相邻过渡帧；视频生成、法线制作和首页接入都排在这道闸门之后。
