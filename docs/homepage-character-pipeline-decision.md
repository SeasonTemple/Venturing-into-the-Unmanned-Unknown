## 当前判断

先验证人物制作管线，再扩大动作与场景制作。原野像素的美术方向保留；当前程序绘制人物不再作为待精修的最终资产。此前建议用占位人物先推进完整流程，会让关键美术依赖继续悬而未决，现调整优先级。

在脚部复核完成前，下一条优先试验不是调用新服务，而是做两条小样对照：

1. **足部轴校准 FK**：只修目标脚、鞋底和趾滚动，保留来源骨盆与膝肘曲线；
2. **二维关键姿态绘制**：只做脚跟着地、全脚支撑、前掌承重、趾离地四张完整姿态。

两条路线通过同一套接触、轮廓、握持和像素连续性验收后，再决定是否继续扩展。通过后才使用下面的候选生成管线：

**已认可人物原图 → 与原图匹配的完整姿态／遮挡参考 → 同一人物参考加逐帧骨架生成少量完整姿态 → 遮罩限定的整体关系修订 → 在目标尺寸检查 → 离线导出有限帧。**

现有三维母版只承担动作、相机与器物空间参考，不能直接将它的脸型、衣料或材质当作目标。三维姿态也需要先适配原图的比例，不能把通用人体的关节点直接套给原画。

这是候选管线，尚未实测成立。新增证据表明存在比当前 MMX 人物参考生成更明确的控制接口；不能由此推出本项目的画风、负重和手持物已得到保证。

## 制作基准纠正：174px 不是已经证实的原生像素尺寸

`art-pack-media/actor-front.png` 实际为 156 × 348。逐像素比较发现，将其缩为 78 × 174 再以最近邻放大两倍，不能还原原文件；原图不是严格的 2 × 2 同色像素块展示。因此，先前“以最近邻整数还原为原生尺寸”的说法不准确。78 × 174 是缩小参照，旧评审图中的 174px 是当时采用的制作／比较尺度，不证明原画的原生像素网格。

这项诊断不说明此前全部失败均由缩小造成；脸型、衣装、握点和生成控制仍是独立问题。

后续保留原图和哈希。适配最大 256px 的服务时另存派生输入，记录统一缩小与透明留白，不覆盖原图、不分部缩放。比较时同时查看原图、实际送入模型的派生图、输出及最终场景显示尺寸。不可将服务输入已丢失的细节全归为模型的风格变化。

## 三条候选路线的证据与取舍

| 路线 | 本轮直接核对到的能力 | 对本项目仍未解决的部分 | 取舍 |
| --- | --- | --- | --- |
| PixelLab：原图参考＋骨架＋局部重绘 | 官方 OpenAPI 确实提供逐帧关节、人物参考、方向；旧版同时有初始图、遮罩和色板字段，官方制作教程演示冻结部分帧后修改另一些帧 | 人脸／绘画式像素簇、手指、左右器物与负重没有自动保证；新服务账户、API 权限和额度未核对 | 优先做一次小样，先用具备冻结／遮罩能力的旧版骨架窗口；不先做八方向 |
| Krita AI Diffusion：参考层＋姿态控制＋选区编辑 | 官方文档明确区分人物／风格参考与 OpenPose 控制，也支持选区和编辑模型；有本地、自定义服务、云服务入口 | 不能把各模型能力任意组合；没有验证同一模型同时支持所需参考、姿态、编辑和跨帧一致性。还需要实际绘制与精修 | 作为需要更强编辑控制时的备选，暂不下载大模型或安装整套环境 |

普通二维绑定依然需要完整可补绘资产；此前的失败不能概括为 PixelOver／Spine／Godot 全部无效。不过换一个绑定软件不会自动补出另一侧衣服、手、鞋和握点，因此本轮不再重复其功能清单。

## PixelLab 新旧接口必须分开

实际读取 `https://api.pixellab.ai/v2/openapi.json`，不是仅依赖搜索摘要或第三方教程。

### `/animate-with-skeleton`：有遮罩和已有帧输入

- 文档列出 16、32、64、128、256 方形画布；试验优先用 256 方形透明留白，不依赖尺寸 schema 对其他矩形的宽松声明。
- `skeleton_keypoints` **恰好三个帧位**，不能按四帧一次调用来准备输入。
- `reference_image` 指向原人物；`init_images` 和 `init_image_strength` 提供初始画面引导。
- `inpainting_images` 与 `mask_images` 对应现有帧及需改动区域；黑色／白色分别表示保护／重绘，具体返回仍需实测核对。
- `color_image` 是强制色板输入，不代表自动保住衣料的形体或像素簇。
- 官方编辑器文档演示 “Freeze 1 → Generate 2 frames”，以及选用已有好帧作为指导。对应 API 请求仍需用同一窗口正确匹配骨架、已有图和遮罩，不能只传一张参考图就宣称冻结成立。
- 工具页面标注至少 Tier 1；API 页面按调用估价。本轮未验证账户在 API 与编辑器中的具体权限，不把二者计费或订阅条件混为一谈。

### `/animate-with-skeleton-v3`：逐帧骨架，当前没有旧版编辑字段

- Beta；一张 `first_frame`，其对应的 `first_frame_keypoints`，再加 3–15 组目标姿态。
- 每帧 18 个命名关节，x／y 为画布归一化坐标；`depth` 可选。最高 256 × 256，异步返回任务 ID。
- 原参考帧不在结果中返回；它不是“始终保留原图第一帧”的文字动画接口。
- 官方特别说明，源骨架必须匹配源图；模型会先重绘参考帧，匹配错误可能损害透明度和颜色。
- 当前请求 schema **没有**旧版的 `mask_images`、`init_images`、`color_image`，不能把旧版冻结／局部编辑能力算作 v3 的现成功能。
- 18 关节没有手指、工具箱和记录器的专属约束。存在身体姿态基本正确、器物与握持仍错误的风险。

### 其他相关能力不能代替骨架小样

`generate-8-rotations-v3` 可从人物参考生成方向图，但没有可证明左右装备不交换的专用字段，不先批量制作方向。`animate-with-text-v3` 主要由动作文字驱动，也不能替代本次关节与遮挡控制的验证。

`inpaint-image-pro-flash` 官方声明保护遮罩外 RGBA，属于另一接口。它可以作为后续精修候选，但不是骨架 v3 的内置冻结能力；需要独立权限和结果核对。

## 第一次小样怎样决定去留

### 输入与范围

1. 保留已认可人物原图；对来源和适配后的图分别固定文件、尺寸和哈希。PIXEL 04、standing02、master02 渲染都不替代身份参考。
2. 先保持原图的同一机位和朝向，不同时要求新侧面、转身、背面和走路。先验证两张新的完整负重关键姿态：承重／接触与经过。它们是方法检验，不能直接称为完整步态。
3. 源骨架逐个对应原图头颈肩、肘腕、髋膝踝；明确解剖学右手银箱、左手绿记录器和前后遮挡。器物另有握点／轮廓参考，但不假称 API 已有器物约束。
4. 第一窗口三个帧位，其中一个已有参照、两个新姿态。只在这两张完整人物成立后，再补另一腿的两个关键姿态；首批最多四张新姿态候选。不要一开始扩成几十帧。

### 放行标准

- 目标显示尺寸能认出同一人物；头颈肩、外套剪裁、裤腿和鞋连续。
- 两手装备身份与侧别不变；手接触把手或设备，承重肩、肘和身体重心相互解释。
- 两帧保持同一相机、光向和像素尺度，衣服具有体积，不变成光滑三维或新的卡通比例。
- 源图的参考帧／被保护区域是否保留，另做像素诊断；它不能替代以上视觉判断。

### 停止标准

两张新姿态就出现明显换脸、换衣装、器物换手或整体画风漂移时，不继续追加帧或用独立缩头／补裤腿掩盖。先区分骨架输入错误和模型表达能力；不能靠无限增加提示词修复缺失的控制能力。若该接口在正确输入下仍不能保住人物，就转向更强选区／轮廓控制的编辑试验，或专门的完整逐帧绘制与精修。

小样通过后才扩大到同方向四关键姿态、有限循环、真实另一朝向与转身；最后接入路径位移。脚在世界地面的稳定和步态随路程推进，属于下一层行为验收。

## 本轮已经确定与尚未确定

已确定：当前缺失的是受控人物资产生产；单有骨架、可运行图集或姿态提示词不够。已发现并核对有明确参考／骨架／遮罩字段的候选接口，也纠正了源图尺寸假设。

尚未确定：PixelLab 是否能保住本站的绘画式像素风格、非对称装备和自然负重；Krita 编辑模型在本机的实际成本及兼容组合；Sprite Sheet Diffusion 的本机推理与当前权重效果。没有任何一条可标为“本站已走通”。

接下来的交付应是上述方法小样的实际结果和去留判断。若服务访问条件不足，就明确缺少的账户／权限／额度或本地推理条件；不把接口调研称为已完成动画，也不以新做场景来代替人物验证。
