# native-phase-anchor-v01：坐标轮廓方案未通过

这一轮没有调用图像或视频生成服务。它从认可的 `actor-front.png` 分层源出发，用 `author-actor-contour-poses.py` 生成一张 260×400 的可编辑 OpenRaster 静帧；上身、两只手、银箱和绿色记录器共用连续表面与握点。3D 行走代理只提供“右脚承重、左脚近地经过”的相位意图。

## 目视结论

上身、头颈、箱体和记录器保持了源图关系，右脚能够读成接地。腿部轮廓方案没有成立：左腿从髋到膝到踝压缩成很窄的连续条，经过脚与支撑脚在目标尺寸几乎合并，膝向和脚底都不可读。它不满足完整人体、脚点和经过关系的关键姿态要求。

这不是像素缩放或导出问题，而是给二维布料轮廓指定的中心线与膝踝目标不足以表达这张原画的腿部体积。继续小幅移动同一组坐标会在“合并”和“断缝”之间来回，不能作为可靠修复。

## 管线决定

保留 `rendered/phase-anchor.ora` 作为可回改诊断源，拒绝 `phase-anchor.png` 作为动作锚点。`main` 不接入该静帧，不能继续扩成动画或交给 H3。

下一次姿态制作需要在原生像素画面上直接补绘完整的髋、膝、踝和鞋底色簇，再把已验证的上身与装备层接回；轮廓中心线只能帮助定位，不能替代腿部体积绘制。通过一张完整静帧后，才恢复短动作试验。
